# ADR-0012: 本文の検索を、一覧の 3 ページに dialog として置く

## Status

承認

## Context

ADR-0001 は、検索のモーダルの UI を、コンテンツが 50 本を超えるまで作らないと決めた。  
一覧の表と分類の絞り込みのほうが、目的の 1 本へ早く着くという理由である。  
ADR-0001: [Starlight を採らず、Astro 単体 + Expressive Code + Pagefind で組む](0001-starlight-as-docs-renderer.md)

PRD は、一覧のタブと本文の検索を、一覧の 3 ページにだけ出すと定めた。  
探す気がある人は一覧まで来るので、検索を全ページの上端に置かない。  
PRD: [fukuemon.dev PRD](../PRD.md)

一覧の表は、題と分類で絞る。  
本文に書いた語からは探せない。

## Decision

本文の検索の UI を、一覧の 3 ページに `<dialog>` として置く。  
索引は Pagefind が build のときに作り、検索の UI はボタンを押したときに索引を読み込む。

理由は 2 つある。

- 本文の語から探す手段は、一覧の表と絞り込みでは代わりにならない。コンテンツの本数によらず要る。
- 一覧の 3 ページにだけ置くので、本文のページの読み込みに検索の JavaScript を足さない。

この決定は、ADR-0001 の Decision 3 のうち、モーダルの UI を 50 本を超えるまで作らないとした判断を置き換える。  
索引を最初から作ることと、自前のページに `data-pagefind-body` を付けることは変えない。

## Considered Options

| 選択肢                                        | 強み                                                     | 弱み                                                               |
| --------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------ |
| **採用:** 一覧の 3 ページに `<dialog>` で置く | 本文の語から探せる。本文のページに JavaScript を足さない | 本数が少ないうちは、使われる場面が少ない                           |
| 50 本を超えるまで作らない（ADR-0001）         | 作って保つものが減る                                     | 本文の語から探す手段がない                                         |
| 全ページの上端に置く                          | どのページからも探せる                                   | 本文のページにも検索の JavaScript を配る。PRD の一覧の役割と重なる |

## Consequences

### Positive

- 読者は、一覧のページで、本文に書いた語から記事とハンズオンを探せる。

### Negative

- 検索の UI を保つ必要がある。Pagefind の更新で、UI が使う API が変わるとこの UI を直す。
