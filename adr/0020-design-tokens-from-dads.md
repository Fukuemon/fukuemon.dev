# ADR-0020: トークンを、DADS の値をコピーしたプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、ライトとダークをセマンティックトークンで切り替える

## Status

承認

## Context

fukuemon.dev のデザインシステムのトークンの持ち方を決める必要がある。

- 記事の画面とコードを動かす画面を、同じトークンで組む。
- 訪問者は、ライトとダークのどちらのテーマでも、本文、コード、HTTP の流れの表示を読める。
- スタイリングの基盤は Tailwind CSS にする。
  - ADR-0010: [Tailwind CSS の採用](0010-tailwind-as-styling-base.md)
- 運営者は buddy も保守している。buddy のトークンは、DADS の `@digital-go-jp/design-tokens` 2.1.0 からコピーした値を、3 つの層で持つ。

## Decision

トークンを 3 つの層に分け、`packages/ui/src/tokens/` に置く。

- プリミティブトークンは、DADS の `@digital-go-jp/design-tokens` の値をコピーして持つ。依存のパッケージから読まない。
  - コピーするのは、セマンティックトークンとテーマ変数が参照する値だけにする。
  - ファイルの冒頭に、コピーした元のパッケージとバージョン、出典の URL、MIT License の表示を残す。
  - 名前は `--fd-primitive-` で始める。DADS の名前のままにすると、DADS を依存に戻したときに、どちらの値かを見分けられない。
- セマンティックトークンは、役割の名前を `--fd-color-` で始め、プリミティブトークンを参照する。
- テーマ変数は、Tailwind CSS の `@theme inline` に置き、Tailwind のデフォルトの色、文字の大きさ、角丸、影、ブレークポイントを消す。セマンティックトークンを通らない書き方を、画面のコードで書けなくするためである。
  - スタイリングは Tailwind CSS v4 のまま書く。
  - テーマ変数にないクラスと、任意の値のクラス（`bg-[#fff]` など）を、lint のエラーにする。テーマ変数にないクラスは CSS を出さないだけでビルドが通り、任意の値のクラスはテーマ変数を通らずに CSS を出すためである。
- ライトとダークは、セマンティックトークンの参照先を `@media (prefers-color-scheme: dark)` で替えて作る。プリミティブトークンとテーマ変数のファイルは、テーマごとに分けない。
  - 画面とコンポーネントのコードに、テーマの条件を書かない。
  - ダークの値も、DADS のプリミティブトークンの階調から選ぶ。

## Considered Options

| 選択肢                                                         | 強み                                                             | 弱み                                                    |
| -------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------- |
| **採用:** DADS の値をコピーし、3 つの層で持つ                  | buddy と同じ形で、同じスキルとチェックを使える。使う値だけを持つ | DADS の修正は、手でコピーするまで入らない               |
| `@digital-go-jp/design-tokens` を依存のパッケージから読む      | DADS の修正をバージョンを上げて取り込める                        | 使わない値も全て読む。buddy と持ち方が分かれる          |
| 今の `packages/design-system/styles/tokens.css` の値を引き継ぐ | 今の見た目を保てる                                               | DADS の色、文字、余白の考え方に沿わない                 |
| テーマごとにプリミティブトークンのファイルを分ける             | テーマごとの値を 1 つのファイルで読める                          | 同じ階調を 2 回書く。コントラストのチェックの元が増える |

## Consequences

### Positive

- 画面のコードは、テーマを意識せずにテーマ変数のユーティリティだけを書ける。
- buddy と同じ層の名前と、同じチェックのスクリプトを使える。

### Negative

- DADS の修正を取り込むときは、差分を読んで手でコピーする。
- ダークの組み合わせは DADS の指針に頼れず、コントラストのチェックで確認する。
- テーマ変数にないクラスと任意の値を見つける lint を持つ。テーマ変数を足したときは、lint が新しいクラスを受け付けることを確認する。
