# ADR-0014: ハンズオンのページは、手順の切り替えを React の外に置き、island どうしを CustomEvent でつなぐ

## Status

承認

## Context

ハンズオンのページは、1 画面に 1 手順を出し、サイドバーの手順の一覧と前後のボタンで切り替える。  
全手順を 1 つの文書に入れ、表示する手順を属性で切り替える。

`interactive.level` が `embedded` のハンズオンは、本文に実行パネルを置き、サイドバーに「いまのテーブル」を出す。  
`local` のハンズオンは実行環境を持たず、手順の切り替えだけを使う。  
ADR-0006: [手を動かす場所を 4 つに分け、cross-origin isolation を `/playground/*` に限定する](0006-interactive-content-levels.md)

実行パネル、「いまのテーブル」、playground の「試す」は、それぞれ別の React root の island になる。  
別の root どうしは、props でも React の context でもつながらない。  
実行パネルが実行したことを「いまのテーブル」へ、「試す」で選んだ例を playground の入力欄へ、実行パネルが記録した完了を手順の一覧へ伝える必要がある。

サイドバーの幅は 306px である。

## Decision

### 1. 手順の切り替えに React を使わない

手順の一覧、画面の切り替え、サイドバーの開閉は、React を使わないスクリプトが属性の付け替えで行う。  
属性の付け替えで足り、island にすると `local` のハンズオンにも React を配ることになるためである。  
lab の Design Doc の計測では、`local` のページが配る JavaScript は gzip で 1.5 KiB、`embedded` のページは React と実行環境を含めて 61.6 KiB である。

### 2. island をまたぐ通知は `window` の CustomEvent にし、状態管理のライブラリを入れない

別の root の island が共通に触れられるのは `window` だけなので、`window` に CustomEvent を発火して伝える。  
React の側の購読は `bus.ts` にまとめ、事象の名前と `contentId` を確かめる処理を、使う側ごとに書かない。

状態管理のライブラリは入れない。  
流しているのは値ではなく「実行した」「例を選んだ」「完了した」という合図で、`useSyncExternalStore` を経由しても購読の本数は減らない。  
完了の合図は React を使わない手順の切り替えのスクリプトも受けるので、React に依存する仕組みには載せられない。

### 3. 「いまのテーブル」の中身を `<dialog>` に出す

サイドバーにはテーブル名と概算の行数だけを並べ、列の定義と先頭の行は `<dialog>` に出す。  
306px の列に表の列を並べると、日時が途中で切れ、値を読むという目的を果たせない。  
`<dialog>` は top layer に出るので、サイドバーの `overflow` に切られない。

## Considered Options

| 選択肢                                                                             | 強み                                                                                  | 弱み                                                                                         |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **採用:** 手順の切り替えは素のスクリプト、island は CustomEvent、中身は `<dialog>` | `local` のページに React を配らない。新しい依存がない。表をサイドバーの幅に縛られない | 事象の名前と中身の型を、送り手と受け手のモジュールで揃えて保つ                               |
| 手順の切り替えも React の island にする                                            | 実行パネルと同じ仕組みで状態を共有できる                                              | 実行環境を持たない `local` のハンズオンにも React を配る                                     |
| 状態管理のライブラリで island の間の状態を共有する                                 | 値を共有する書き方が揃う                                                              | 依存が増えるのに、流すのは合図だけで購読は減らない。React を使わないスクリプトから使いにくい |
| 「いまのテーブル」の中身をサイドバーに出す                                         | 開く操作が要らない                                                                    | 306px では値が途中で切れて読めない                                                           |

## Consequences

### Positive

- `local` のハンズオンのページは、React と実行環境を配らない。
- island を足しても、通知の仕組みに依存を足さずに済む。

### Negative

- CustomEvent の中身の型は、送り手と受け手の間で、型が一致するかを TypeScript が確かめない。発火と購読を `bus.ts` と `progress.ts` に寄せて揃える。
- 「いまのテーブル」の中身を見るには、`<dialog>` を開く操作が要る。
