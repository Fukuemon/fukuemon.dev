# ADR-0015: ハンズオンの手順の画面へのまとめを、remark ではなく rehype のプラグインに置く

## Status

承認

## Context

ハンズオンの本文は、`h2` を手順の境界とし、手順ごとに 1 つの `<section>` にまとめて 1 画面ずつ出す。  
手順を数えるのは `remark-lab` だけで、まとめる処理は同じ `h2` をたどるだけにする。

ハンズオンは、実行パネルを置くものを `.mdx` で、置かないものを `.md` で書く。  
remark の段階（mdast）で `<section>` を挿すと、`.mdx` には JSX のノードを、`.md` には生の HTML のノードを挿す必要がある。  
rehype の段階（hast）では、`.mdx` と `.md` のどちらも同じ要素のノードになる。

## Decision

手順を `<section>` にまとめる処理（`rehype-lab-steps`）を、rehype のプラグインに置く。  
hast まで来れば拡張子の違いが消え、1 通りの処理で済むためである。

## Considered Options

| 選択肢                                  | 強み                                     | 弱み                                                                        |
| --------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------- |
| **採用:** rehype のプラグインでまとめる | `.mdx` と `.md` を 1 通りの処理で扱える  | 手順を数える `remark-lab` と、まとめる `rehype-lab-steps` の 2 つに分かれる |
| remark のプラグインでまとめる           | 手順を数える処理と同じプラグインに置ける | `.mdx` は JSX、`.md` は生の HTML と、2 通りに書き分ける                     |

## Consequences

### Positive

- 拡張子によって手順のまとめ方が変わらない。

### Negative

- 手順の境界を、`remark-lab` と `rehype-lab-steps` の 2 か所が同じ `h2` から読む。
  - どちらも構文木の `h2` を出現の順に読むので、フェンスの中の `##` で番号がずれることはない。
