# ADR-0063: AI のエージェントからの操作を、SQL だけを動かすツールと Go を動かすツールにも公開し、PGlite と Yaegi を操作が呼ばれたときにも読み込む

## Status

提案

## Context

AI のエージェントからの操作を、SQL だけを動かすツール（`/sql/`）と、Go を動かすツール（`/go/`）にも広げる。  
足す操作、ページが確認を出す操作、PGlite と Yaegi を読み込む時期を決める必要がある。

- 公開する操作は 15 個で、実行環境の操作は、Node の実行環境のファイルの 4 つとコマンドの 1 つである。SQL を実行する操作と、Go を実行する操作は無い。
  - ADR-0044: [AI のエージェントからの操作は、WebMCP の API で登録し、MCP-B の polyfill と relay でも呼べるようにする](0044-ai-operations-with-webmcp.md)
- ページが確認を出す操作は、4 つである。コマンドを実行する操作は、確認なしで実行する。コマンドが WebContainers の中で動き、プレイグラウンドに保存した図とスライドに届かないためである。AI のエージェントが書いたコードは、利用者が自分の操作で動かしたコードとして扱う。
  - ADR-0045: [AI のエージェントからの操作は、ツールごとに 7 日のあいだ保存するスイッチで許可し、消す操作と全体を置き換える操作はページが確認を出す](0045-ai-operations-permission-and-confirmation.md)
- Go のコードは、Yaegi のインタプリタの WASM で動かす。Yaegi の WASM は、訪問者が実行のボタンを押してから読み込む。
  - ADR-0037: [Go のコードを、Yaegi のインタプリタの WASM で動かす](0037-go-with-yaegi.md)
- SQL だけを動かすツールは、PGlite を Web Worker で動かす。DB の中身は保存せず、Web Worker を作り直すと、初期の状態に戻る。保存するのは、入力欄の SQL だけである。
  - ADR-0053: [DB の記事は PGlite を使い、Node のコードからは Unix ドメインソケットで `pg` から接続し、SQL は DB のプロセスの標準入出力で送る](0053-pglite-database-in-playground.md)
- Go を動かすツールは、訪問者のファイルを IndexedDB に保存する。
  - ADR-0050: [訪問者のファイルを、埋め込みの ID ごとに、IndexedDB に保存する](0050-save-visitor-files-in-indexeddb.md)
- プレイグラウンドでは、訪問者が動かしたコードが、同じ origin に保存した図とスライドにアクセスできることを受け入れる。条件は、他人が用意したコードを、訪問者の操作なしに動かさないことである。
  - ADR-0031: [サブドメインに分ける規則を決め、1 つのアプリを 1 つの Worker とホスト名に割り当てる](0031-subdomains-and-workers.md)
- Go のコードは、WebContainers の中ではなく、`play.fukuemon.dev` の Worker の中で動く。Worker の中からは、IndexedDB を読める。

## Decision

ADR-0044 の Decision 4、ADR-0045 の Decision 4、ADR-0037 の Decision の読み込みの時期に、次のとおり足す。  
3 つの ADR のほかの決定は、変えない。

### 1. 足す操作

ADR-0044 の 15 個に、次の 8 個を足し、23 個にする。  
注釈の語は、ADR-0044 の Decision 4 と同じである。

| ツール | 操作                                     | 注釈                           |
| ------ | ---------------------------------------- | ------------------------------ |
| SQL    | 入力欄の SQL を返す                      | 読み取りだけ、信頼できない内容 |
| SQL    | 渡した SQL を実行し、結果を返す          | 重大な操作、信頼できない内容   |
| Go     | ファイルの一覧を返す                     | 読み取りだけ                   |
| Go     | ファイルの中身を返す                     | 読み取りだけ、信頼できない内容 |
| Go     | ファイルを書く                           | 無い                           |
| Go     | ファイルを消す                           | 重大な操作                     |
| Go     | ファイルを実行し、終了コードと出力を返す | 重大な操作、信頼できない内容   |
| Go     | テストを実行し、終了コードと出力を返す   | 重大な操作、信頼できない内容   |

- SQL の操作は、入力欄の SQL を書き換えない。利用者が書いて保存した SQL が、エージェントの操作で消えないようにするためである。
- AI のエージェントが実行した SQL の結果は、操作の記録の欄にだけ出す。SQL の画面の結果の表は、変えない。利用者が見ている結果が、利用者の操作なしに替わらないようにするためである。
- テーブルの一覧と列を返す操作は、足さない。エージェントは、SQL を実行する操作で `information_schema` を読む。
- Go のファイルの 4 つの操作は、Node の実行環境の同じ操作と、名前の付け方と入出力をそろえる。エージェントが、同じ使い方で両方を操作できるようにするためである。
- Go を動かすツールのファイルは、ディレクトリを持つ。ディレクトリを含むパスは、Node の実行環境の操作と同じに扱う。
- Go を実行する操作とテストを実行する操作は、保存してあるファイルを実行する。入力でコードを受け取らない。画面の実行のボタンとテストのボタンと、同じものを動かすためである。
- Node の実行環境の DB には、SQL の操作を足さない。エージェントは、ファイルを書く操作とコマンドを実行する操作で、`pg` を使うコードを書いて実行できる。

### 2. ページが確認を出す操作

Go のファイルを消す操作は、ページが確認を出す。  
ADR-0045 の 4 つと合わせて、確認を出す操作は 5 つになる。  
理由は、ADR-0045 の Decision 4 と同じで、利用者が書いて保存したファイルが、確認なしに消えないようにするためである。

次の操作は、確認なしで実行する。

- SQL を実行する操作。`DROP` と `DELETE` を含む SQL も、確認なしで実行する。DB の中身は保存されず、初期の状態に戻せるためである。
- Go のファイルを書く操作。Node の実行環境のファイルを書く操作と同じである。
- Go を実行する操作と、テストを実行する操作。Yaegi で動かすコードが、ページの `localStorage` と IndexedDB を読み書きできないようにしたうえで、確認を出さない。
  - `GoRunner` が Yaegi に渡す symbol を、`stdlib.Symbols` だけにする。`syscall`、`unsafe`、`unrestricted` の symbol を渡さない。
  - Yaegi で動かすコードが `syscall/js` を呼べないことを、テストで確認する。

### 3. PGlite と Yaegi を読み込む時期

PGlite と Yaegi の WASM は、訪問者が実行のボタンを押したときのほかに、SQL を実行する操作、Go を実行する操作、テストを実行する操作が呼ばれたときにも読み込む。  
読み込んでから、操作を実行する。

操作が呼ばれるのは、利用者がスイッチをオンにし、自分のエージェントをつないだ後である。  
ADR-0045 の Decision 6 と同じく、利用者の操作として扱う。

## Verification

#34 の試作の Yaegi 0.16.3 の WASM（`stdlib.Symbols` だけを渡したもの）を、Node の上で動かした（Apple M2）。

| Yaegi で動かすコードが import したもの | 結果                                                 |
| -------------------------------------- | ---------------------------------------------------- |
| `syscall/js`                           | import がエラーになった                              |
| `syscall`                              | import がエラーになった                              |
| `unsafe`                               | import がエラーになった                              |
| `net/http`                             | import できた。呼び出しは、Node の上でエラーを返した |

- ブラウザの中では、確認していない。
- Yaegi で動かすコードが、ブラウザの中で `net/http` から外部へリクエストを送れるかは、未確認である。
- PGlite の拡張と関数（`COPY`、`pg_read_file` など）が、Web Worker の外に届くかは、未確認である。
- 複数の package に分けたファイルの import を、Yaegi の WASM で解決できるかは、未確認である。

## Considered Options

| ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **採用:** SQL に 2 つ、Go に 6 つの操作を足し、Go のファイルを消す操作だけに確認を出し、PGlite と Yaegi を操作が呼ばれたときにも読み込む | エージェントは、利用者の SQL を読み、直した SQL を実行できる。Go では、Node の実行環境と同じ使い方で、ファイルを書いて実行できる | 操作が 8 個増える。エージェントが直した SQL は、入力欄に入らない。Yaegi に渡す symbol を増やすと、確認を出さない理由が崩れる |

| Go を実行する操作とテストを実行する操作のたびに、確認を出す                                                                              | Yaegi に渡す symbol に依らずに、利用者が実行を見てから通せる                                                                     | 「このページでは今後尋ねない」を選ぶまで、エージェントが 1 回実行するたびに、利用者がボタンを押す                            |

| Node の実行環境の DB にも、SQL を実行する操作を足す                                                                                      | エージェントが、コードを書かずに SQL を実行できる                                                                                | 操作が 1 つ増える。DB を使うプロジェクトのときだけ登録する処理が要る                                                         |

## Consequences

### Positive

- 利用者は、自分の AI のエージェントに頼んで、SQL を実行して結果を受け取り、Go のファイルを書いて実行し、テストの結果を受け取れる。
- 利用者が書いて保存した SQL は、エージェントの操作で変わらない。
- 利用者が書いて保存した Go のファイルは、利用者が確認を通すか、「このページでは今後尋ねない」を選ばない限り、ファイルを消す操作で消えない。
- 利用者は、エージェントをつないだ後に、実行のボタンを押さなくても、エージェントに SQL と Go を実行させられる。

### Negative

- AI のエージェントは、確認なしで、SQL を実行でき、Go のファイルを書き換えられ、Go のコードを実行できる。
- エージェントが実行した SQL は、DB の中身を変える。利用者が画面で見ている結果の表と、DB の中身が、合わなくなることがある。
- スイッチがオンの間は、利用者が実行のボタンを押していなくても、エージェントの操作で、PGlite と Yaegi の WASM を読み込む。
- `GoRunner` が Yaegi に渡す symbol を、`stdlib.Symbols` のほかに増やせない。増やすときは、Go を実行する操作の確認を決め直す。
- `GoRunner` に、複数の package の import を解決する処理が要る。
- Yaegi で動かすコードは、`net/http` を import できる。ブラウザの中で外部へリクエストを送れるかを、実装のタスクで確認する。
