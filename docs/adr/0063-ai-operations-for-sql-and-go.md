# ADR-0063: AI のエージェントからの操作を、SQL だけを動かすツールと Go を動かすツールにも公開し、PGlite と Yaegi を操作が呼ばれたときにも読み込む

## Status

承認（Decision 2 に ADR-0064 を足す）

## Context

AI のエージェントからの操作を、SQL だけを動かすツール（`/sql/`）と、Go を動かすツール（`/go/`）にも広げる。  
足す操作、ページが確認を出す操作、PGlite と Yaegi を読み込む時期を決める必要がある。

- ADR-0044 が公開する操作は、15 個である。そのうち実行環境の操作は、Node の実行環境のファイルの 4 つと、コマンドの 1 つである。SQL を実行する操作と、Go を実行する操作は無い。
  - ADR-0044: [AI のエージェントからの操作は、WebMCP の API で登録し、MCP-B の polyfill と relay でも呼べるようにする](0044-ai-operations-with-webmcp.md)
- ページが確認を出す操作は、4 つである。コマンドを実行する操作は、確認なしで実行する。コマンドが WebContainers の中で動き、プレイグラウンドに保存した図とスライドに届かないためである。
- AI のエージェントが書いたコードは、利用者が自分の操作で動かしたコードとして扱う。
  - ADR-0045: [AI のエージェントからの操作は、ツールごとに 7 日のあいだ保存するスイッチで許可し、消す操作と全体を置き換える操作はページが確認を出す](0045-ai-operations-permission-and-confirmation.md)
- Go のコードは、Yaegi のインタプリタの WASM で動かす。Yaegi の WASM は、訪問者が実行のボタンを押してから読み込む。
  - ADR-0037: [Go のコードを、Yaegi のインタプリタの WASM で動かす](0037-go-with-yaegi.md)
- SQL だけを動かすツールは、PGlite を Web Worker で動かす。SQL だけを動かすツールは、DB の中身を保存しない。Web Worker を作り直すと、DB は初期の状態に戻る。保存するのは、入力欄の SQL だけである。
  - ADR-0053: [DB の記事は PGlite を使い、Node のコードからは Unix ドメインソケットで `pg` から接続し、SQL は DB のプロセスの標準入出力で送る](0053-pglite-database-in-playground.md)
- SQL だけを動かすツールの PGlite も、訪問者が実行のボタンを押してから読み込む。
  - 出典: [プレイグラウンドの Design Doc](../../apps/playground/DesignDoc.md)
- Go を動かすツールは、訪問者のファイルを IndexedDB に保存する。
  - ADR-0077: [訪問者のファイルを、埋め込みの ID ごとに IndexedDB に保存し、Node の実行環境ではシークレットのファイル、ビルドの出力、`.git`、リンクを除き、上限を付ける](0077-save-visitor-files.md)
- プレイグラウンドでは、訪問者が動かしたコードが、同じ origin に保存した図とスライドにアクセスできることを受け入れる。条件は、他人が用意したコードを、訪問者の操作なしに動かさないことである。
  - ADR-0031: [サブドメインに分ける規則を決め、1 つのアプリを 1 つの Worker とホスト名に割り当てる](0031-subdomains-and-workers.md)
- Go のコードは、WebContainers の中で動かさず、`play.fukuemon.dev` のページで動かす。ページの Web Worker の中で動くコードは、`localStorage` を読めず、IndexedDB を読める。

## Decision

この ADR は、ADR-0044 の Decision 4 に操作を足し、ADR-0045 の Decision 4 に確認を出す操作を足す。  
ADR-0037 の Decision のうち、Yaegi を読み込む時期を変える。  
プレイグラウンドの Design Doc が決めている、PGlite を読み込む時期も変える。  
3 つの ADR のほかの決定は、変えない。

### 1. 足す操作

ADR-0044 の 15 個に、次の 8 個を足し、23 個にする。  
注釈の語は、ADR-0044 の Decision 4 と同じである。

| ツール | 操作                                     | 注釈                           |
| ------ | ---------------------------------------- | ------------------------------ |
| SQL    | 入力欄の SQL を返す                      | 読み取りだけ、信頼できない内容 |
| SQL    | 渡した SQL を実行し、結果を返す          | 重大な操作、信頼できない内容   |
| Go     | ファイルの一覧を返す                     | 読み取りだけ                   |
| Go     | ファイルの中身を返す                     | 読み取りだけ、信頼できない内容 |
| Go     | ファイルを書く                           | 無い                           |
| Go     | ファイルを消す                           | 重大な操作                     |
| Go     | ファイルを実行し、終了コードと出力を返す | 重大な操作、信頼できない内容   |
| Go     | テストを実行し、終了コードと出力を返す   | 重大な操作、信頼できない内容   |

- SQL だけを動かすツールの 2 つの操作は、入力欄の SQL を書き換えない。利用者が書いて保存した SQL が、エージェントの操作で消えないようにするためである。
- AI のエージェントが実行した SQL の結果は、操作の記録の欄にだけ出す。SQL の画面の結果の表は、変えない。利用者が見ている結果が、利用者の操作なしに変わらないようにするためである。
- テーブルとカラムの一覧を返す操作は、足さない。エージェントは、SQL を実行する操作で `information_schema` を読む。
- Go のファイルの 4 つの操作は、Node の実行環境の同じ操作と、名前の付け方と入出力をそろえる。エージェントが、同じ使い方で両方を操作できるようにするためである。
- Go を動かすツールは、ファイルをディレクトリに分けて持つ。ディレクトリを含むパスは、Node の実行環境の操作と同じに扱う。
- Go を実行する操作とテストを実行する操作は、Go を動かすツールが持つ今のファイルを実行する。入力でコードを受け取らない。画面の実行のボタンとテストのボタンと、同じファイルを実行するためである。
- Node の実行環境の DB には、SQL を実行する操作を足さない。エージェントは、ファイルを書く操作とコマンドを実行する操作で、`pg` を使うコードを書いて実行できる。

### 2. ページが確認を出す操作

Go のファイルを消す操作は、ページが確認を出す。  
ADR-0045 の 4 つと合わせて、確認を出す操作は 5 つになる。  
理由は、ADR-0045 の Decision 4 と同じで、利用者が書いて保存したファイルが、確認なしに消えないようにするためである。

次の操作は、確認なしで実行する。

- SQL を実行する操作。`DROP` と `DELETE` を含む SQL も、確認なしで実行する。DB の中身は保存されず、Web Worker を作り直すと初期の状態に戻るためである。
- Go のファイルを書く操作。Node の実行環境のファイルを書く操作も、確認を出さない。
- Go を実行する操作と、テストを実行する操作。Yaegi で動かすコードが、ページの `localStorage` と IndexedDB を読み書きできないようにしたうえで、確認を出さない。
  - `GoRunner` は、Yaegi を Web Worker の中で動かす。止めるときは、Web Worker を終了させる。
  - `GoRunner` が Yaegi に渡す symbol を、`stdlib.Symbols` だけにする。`syscall`、`unsafe`、`unrestricted` の symbol を渡さない。
  - Yaegi で動かすコードが `syscall/js` を呼べないことを、テストで確認する。

### 3. PGlite と Yaegi を読み込む時期

PGlite と Yaegi の WASM は、利用者が実行のボタンを押したときのほかに、SQL を実行する操作、Go を実行する操作、テストを実行する操作が呼ばれたときにも読み込む。  
読み込んでから、操作を実行する。

操作が呼ばれるのは、利用者がスイッチをオンにし、自分のエージェントをつないだ後である。  
ADR-0045 の Decision 6 と同じく、エージェントの操作で読み込むことも、利用者の操作として扱う。

## 承認の条件

次の 2 つを、Go を動かすツールの実装のタスク（#100）で、ブラウザの中で確認する。

- Yaegi に渡す symbol を `stdlib.Symbols` だけにした WASM で、Yaegi で動かすコードの `syscall/js`、`syscall`、`unsafe` の import が失敗すること。Decision 2 が、Go を実行する操作に確認を出さないのは、この条件を前提にする。満たせないときは、Decision 2 を変え、Go を実行する操作とテストを実行する操作に、ページが確認を出す。
- ディレクトリで複数の package に分けたファイルの import を、Yaegi の WASM で解決できること。解決できないときは、Go を動かすツールは、ファイルをディレクトリに分けて持てるが、`main` の 1 つの package だけを実行する。別の package を import したコードには、エラーを出す。

## Verification

#34 の試作の Yaegi 0.16.3 の WASM（`stdlib.Symbols` だけを渡したもの）を、Node の上で動かした（Apple M2）。

| Yaegi で動かすコードが import したもの | 結果                                                 |
| -------------------------------------- | ---------------------------------------------------- |
| `syscall/js`                           | import がエラーになった                              |
| `syscall`                              | import がエラーになった                              |
| `unsafe`                               | import がエラーになった                              |
| `net/http`                             | import できた。呼び出しは、Node の上でエラーを返した |

承認の条件の 2 つは、Go を動かすツールの実装のタスクで、ブラウザの中で確認した。  
確認のために、`stdlib.Symbols` だけを渡した Yaegi 0.16.3 と Go 1.26.4 の WASM を作った。  
その WASM を、Playwright 1.64.1 の Chromium 156 と WebKit 27.2 の Web Worker の中で動かした。  
ファイルは `src/<モジュールの名前>/` に置き、`GoPath` を `.` にした。

| Yaegi で動かすコード                                                                             | Chromium と WebKit の結果                                                   |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `syscall/js`、`syscall`、`unsafe`、`os/exec` を import する                                      | どれも `import "…" error: unable to find source related to: "…"` で失敗した |
| `main.go` が、別のディレクトリの `play/greet` を import する                                     | 標準出力が出た                                                              |
| `main` の package を 2 つのファイルに分け、`play/internal/a` が `play/internal/b` を import する | 標準出力が出た                                                              |
| `net/http` で、同じ origin のパスを取得する                                                      | 応答を読めた                                                                |
| `net/http` で、別の origin のパスを取得する                                                      | 応答は読めなかった。別の origin のサーバーにリクエストが届いた              |

- import が失敗するのは、`stdlib.Symbols` に symbol が無く、Yaegi がソースを読むファイルシステムに、訪問者のファイルしか無いためである。
- `net/http` のリクエストの扱いは、ADR-0064 が決める。
  - ADR-0064: [Yaegi で動かす Go のコードの HTTP のリクエストは、Web Worker と同じ origin へのものだけを通す](0064-go-net-http-same-origin-only.md)
- `COPY` と `pg_read_file` のような、ファイルを読み書きする SQL が、Web Worker の外のファイルを読み書きできるかは、未確認である。

## Considered Options

| 選択肢                                                                                                                                                                   | 強み                                                                                                                             | 弱み                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **採用:** SQL だけを動かすツールに 2 つ、Go を動かすツールに 6 つの操作を足し、Go のファイルを消す操作だけに確認を出し、PGlite と Yaegi を操作が呼ばれたときにも読み込む | エージェントは、利用者の SQL を読み、直した SQL を実行できる。Go では、Node の実行環境と同じ使い方で、ファイルを書いて実行できる | 操作が 8 個増える。エージェントが直した SQL は、入力欄に入らない。Yaegi に渡す symbol を増やすと、確認を出さない理由が成り立たなくなる |
| SQL だけを動かすツールに、入力欄の SQL を置き換える操作も足す                                                                                                            | エージェントが、直した SQL を入力欄に入れられる                                                                                  | 利用者が書いて保存した SQL を置き換える。確認を出す操作が増える                                                                        |
| SQL だけを動かすツールは、SQL を実行する操作だけにする                                                                                                                   | 操作が少ない                                                                                                                     | エージェントが、利用者の書いた SQL を読めない                                                                                          |
| SQL を実行する操作で、`SELECT` のほかの文を含むときに確認を出す                                                                                                          | 利用者が、DB を変える SQL を見てから通せる                                                                                       | 文の種類を見分ける処理が要る。CTE の中の `DELETE` と、関数の呼び出しでの書き込みは、見分けにくい                                       |
| エージェントが実行した SQL の結果を、SQL の画面の結果の表にも出す                                                                                                        | 利用者が、エージェントの実行の結果を、表で読める                                                                                 | 入力欄の SQL と、表の結果が、合わなくなる                                                                                              |
| Go のファイルを消す操作に、確認を出さない                                                                                                                                | 確認を出す操作が増えない                                                                                                         | 利用者が書き換えたファイルが、確認なしに消える。初期の状態に戻しても、書き換えた分は戻らない                                           |
| Go のファイルを、1 回で全て返す操作にまとめ、消す操作を持たない                                                                                                          | 操作が少ない                                                                                                                     | Node の実行環境と、形が違う。ファイルを消せない                                                                                        |
| Go を実行する操作とテストを実行する操作のたびに、確認を出す                                                                                                              | Yaegi に渡す symbol に依らずに、利用者が実行を見てから通せる                                                                     | 「このページでは今後尋ねない」を選ぶまで、エージェントが 1 回実行するたびに、利用者がボタンを押す                                      |
| PGlite と Yaegi を読み込んでいないときは、操作が失敗を返す                                                                                                               | ADR-0037 の読み込みの時期を変えない                                                                                              | 利用者が、先に実行のボタンを押すことになる                                                                                             |
| Go を動かすツールのファイルを、ディレクトリに分けない形にする                                                                                                            | 複数の package の import の解決が要らない                                                                                        | Node の実行環境の操作と、パスの扱いが違う。package を分けたコードを書けない                                                            |
| Node の実行環境の DB にも、SQL を実行する操作を足す                                                                                                                      | エージェントが、コードを書かずに SQL を実行できる                                                                                | 操作が 1 つ増える。DB を使うプロジェクトのときだけ登録する処理が要る                                                                   |

## Consequences

### Positive

- 利用者は、自分の AI のエージェントに頼んで、SQL を実行して結果を受け取り、Go のファイルを書いて実行し、テストの結果を受け取れる。
- 利用者が書いて保存した SQL は、エージェントの操作で変わらない。
- ファイルを消す操作が、利用者が書いて保存した Go のファイルを消すのは、利用者が確認の画面で確定のボタンを押したときと、「このページでは今後尋ねない」を選んだ後だけである。
- 利用者は、エージェントをつないだ後に、実行のボタンを押さなくても、エージェントに SQL と Go を実行させられる。

### Negative

- AI のエージェントは、確認なしで SQL を実行できる。Go のファイルの書き換えと、Go のコードの実行も、確認なしでできる。
- エージェントが実行した SQL は、DB の中身を変える。利用者が画面で見ている結果の表と、DB の中身が、合わなくなることがある。
- スイッチがオンの間は、利用者が実行のボタンを押していなくても、エージェントの操作で、PGlite と Yaegi の WASM を読み込む。
- `GoRunner` は、Yaegi に `stdlib.Symbols` のほかの symbol を渡さない。渡すときは、Go を実行する操作に確認を出すかを決め直す。
- `GoRunner` に、複数の package の import を解決する処理が要る。
- Yaegi で動かすコードは、`net/http` を import できる。ほかの origin へのリクエストの扱いは、ADR-0064 が決める。
  - ADR-0064: [Yaegi で動かす Go のコードの HTTP のリクエストは、Web Worker と同じ origin へのものだけを通す](0064-go-net-http-same-origin-only.md)
