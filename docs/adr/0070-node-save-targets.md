# ADR-0070: 保存する対象から、シークレットのファイル、ビルドの出力、`.git`、リンクを除き、数と大きさに上限を付ける

## Status

提案

## Context

訪問者の作業ディレクトリのうち、どのファイルを IndexedDB に保存するかを決める必要がある。
ADR-0050 は、保存する対象を、作業ディレクトリの全体のうち `node_modules` を除いたものにしている。

- 訪問者が作ったファイルは、訪問者のブラウザに保存する。プレイグラウンドの中では、ツールの間で origin を分けない。
  - ADR-0031: [サブドメインに分ける規則を決め、1 つのアプリを 1 つの Worker とホスト名に割り当てる](0031-subdomains-and-workers.md)
- 訪問者のファイルは、`play.fukuemon.dev` の IndexedDB に、埋め込みの ID ごとに保存する。同じ origin のほかのツールのページも、その IndexedDB を読める。
  - ADR-0050: [訪問者のファイルを、埋め込みの ID ごとに、IndexedDB に保存する](0050-save-visitor-files-in-indexeddb.md)
- 訪問者のシェルは制限が無く、訪問者は作業ディレクトリに、どの名前のファイルでも、シンボリックリンクでも作れる。
  - ADR-0051: [Node の実行環境は、ページを開いたときに起動し、シェルを制限なしで使わせ、訪問者が変えたコードは操作の後に動かす](0051-node-runtime-boot-and-commands.md)
- 訪問者が `.env` や `.npmrc` にトークンを書くと、平文で IndexedDB に残る。
- 起動のコマンドがビルドの出力（`dist/`、`.next/`、`.cache/`）を書くか、訪問者が `git init` すると、保存のたびに、その全てを読んでレコードに入れる。
- 次の項目は、Apple M2 の `vp dev` の `/node/` を、Playwright 1.64.1 の Chromium（headless）で開いて測った。WebKit と Firefox では測っていない。
  - シンボリックリンクとして、`.` を指すものと、作業ディレクトリの外のファイルを指すものを作った。
  - WebContainers の `fs.readdir` の `withFileTypes` の項目は、2 つとも `isFile()` も `isDirectory()` も false だった。`isSymbolicLink` は無い。
  - リンクをファイルとして読むと、作業ディレクトリの外のファイル（`/tmp/fukuemon-playground/ports.json`）の中身が保存された。
  - 1 つのディレクトリに置いたファイルを読む時間は、950 個（合計 9.5 MB）で 0.35 秒、5000 個（合計 5 MB）で 5.7 秒、10000 個で 24 秒だった。
  - 10 個（合計 10 MB）は、読むのに 16 ms、IndexedDB に書くのに 12 ms だった。
  - 保存のために作業ディレクトリを読む処理には、5 秒の上限がある。

## Decision

- 保存する対象は、訪問者の作業ディレクトリの全体のうち、次のものを除いたものにする。訪問者がコマンドで作ったファイルも保存する。
  - どの階層でも、`node_modules`、`.git`、`dist`、`.next`、`.nuxt`、`.cache`、`.turbo` のディレクトリの下のもの。`build` と `out` は、ソースのディレクトリにも使う名前なので除かない。
  - どの階層でも、`.env`、`.env.` で始まる名前、`.npmrc`、`.netrc` のファイル。シークレットを置くことが多いファイルである。
  - ファイルでもディレクトリでもないもの（シンボリックリンク）。作業ディレクトリの外のファイルの中身を保存しないためである。
  - 作業ディレクトリのファイルの変更を監視して保存する。監視で通知を受け取れないときは、一定の時間ごとに、作業ディレクトリを読み、前回と中身が違うときに保存する。
  - 一定の時間ごとにする理由は、訪問者がシェルで打ったコマンドの終了を、ツールのページが受け取れないためである。
- 1 つのファイルが 1 MB を超えるものと、テキストとして読めないものは、保存しない。
- 除いたディレクトリの外のファイルが 1000 個か、合計で 10 MB を超えたら、保存しない。前に保存したレコードは残し、保存していないことを画面に出す。
  - 超えた時点で、作業ディレクトリを読むのをやめる。超えたプロジェクトでも、保存のたびに全部を読まないようにするためである。
  - 1000 個は、測った時間が 5 秒の上限の 10 分の 1 以下に収まる数である。10 MB は、読む時間と書く時間がそれぞれ 20 ms 以下だった大きさである。

## Considered Options

保存する対象の選択肢は次のとおり。

| 選択肢                                                                                                         | 強み                                                                                                 | 弱み                                                                                           |
| -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **採用:** 作業ディレクトリの全体から、シークレットのファイル、ビルドの出力、`.git`、リンクを除き、上限を付ける | よくある置き場のシークレットと、作業ディレクトリの外の中身を残さない。大きな出力で保存が重くならない | ほかの名前のファイルに書いたシークレットは残る。上限を超えると、それより後の変更が保存されない |
| 作業ディレクトリの全体（`node_modules` を除く）                                                                | 訪問者がコマンドで作ったファイルも残る                                                               | シークレットとリンクの先の中身が残る。大きな出力で、保存のたびに数 MB を読み書きする           |
| エディタとファイルのツリーで変えたファイルだけ                                                                 | 処理が少ない                                                                                         | コマンドで作ったファイルと、`npm install` で変わった `package.json` が残らない                 |

上限を超えたときの選択肢は次のとおり。

| 選択肢                                                     | 強み                                 | 弱み                                                                |
| ---------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------- |
| **採用:** 保存せず、前に保存したレコードを残す             | 訪問者のファイルを消さない           | 再訪のときに、超える前のファイルで開く                              |
| 前に保存したレコードを消す                                 | 再訪のときに、古いファイルで開かない | 訪問者のファイルが消える                                            |
| 上限を持たず、IndexedDB が容量の超過で失敗したら警告を出す | 上限の値を決めなくてよい             | 保存のたびに全部を読み、読み込みの 5 秒の上限を超えると保存されない |

## Consequences

### Positive

- 訪問者が `.env`、`.npmrc`、`.netrc` に書いたトークンが、IndexedDB に残らない。
- 作業ディレクトリの外のファイルの中身が、リンクを通して保存されない。
- ビルドの出力と `.git` があっても、保存のたびに読む量が増えない。

### Negative

- `.env` の中のシークレットでない値と、`.env.example` も、再訪のときに無い。
- ほかの名前のファイルに書いたシークレットは、保存される。
- 訪問者が作ったリンク、ビルドの出力、`.git` は、再訪のときに無い。
- 上限を超えている間の変更は、保存されない。
- 1 MB を超えるファイルと、テキストとして読めないファイルは、再訪のときに無い。
- `node_modules` は保存しないので、再訪のたびに `npm install` を実行する。
