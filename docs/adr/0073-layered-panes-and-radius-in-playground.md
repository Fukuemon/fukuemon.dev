# ADR-0073: コードを動かす画面を、地の上に角の丸い紙の面を重ねる見た目にし、面の角を 6〜14px で丸める

## Status

提案

## Context

コードを動かす画面の、ペインの区切りと角の丸めを決め直す必要がある。

- トークンを、プリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、テーマの組をコントラストのチェックで確認すると決めている。
  - ADR-0024: [トークンを、fukuemon.dev の値のプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、生成りの地と旧サイトの差し色で、角丸と影を使わない版面にする](0024-tokens-of-fukuemon-dev.md)
- 罫で区切る版面を保ち、操作できる要素と重なる面の角を 2px で丸め、テーマ変数に角丸の名前を 1 つだけ置く（`rounded-control`）と決めている。Tabs のタブ、Notice、Table、コードブロックなどの角は丸めない。重なる面は、`surface-raised` の面、1px の枠、ずらした影を組にして示す。
  - ADR-0028: [操作できる要素と重なる面の角を 2px で丸め、重なる面にずらした影を付け、罫を引く動きを筆の線にする](0028-radius-shadow-and-brush-motion.md)
- コードを動かす画面は、文字と押せる領域を詰めた画面で、記事の本文と読み方が違う。詰めるときも、色、罫、墨と生成りの面、角丸、筆の線の動きは変えないと決めている。
  - ADR-0062: [コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくする](0062-dense-text-and-targets-in-playground.md)
- フォーカスの表示は墨の 2px の輪で、詰めたペインでは要素の内側に引くと決めている。
  - ADR-0061: [フォーカスの表示を、DADS の黄と黒の 2 重の表示から、墨の 2px の 1 重の輪にする](0061-sumi-focus-ring.md)
  - ADR-0066: [コードを動かす画面の詰めたペインで、フォーカスの輪を要素の内側に引く](0066-inset-focus-ring-in-dense-panes.md)
- 指で押す端末では、押せる領域を 44px にする。
  - ADR-0071: [指で押す端末では、コードを動かす画面の押せる領域を 44px にし、iOS と iPadOS の入力時の拡大を viewport の指定で止める](0071-touch-targets-and-ios-zoom-in-playground.md)
- 狭い配置（ファイルのドロワー、下のタブ、左の縦のタブ、記事の枠の上のタブ）と PC の配置を分ける。
  - ADR-0072: [コードを動かす画面を、幅が 48rem 未満か高さが 500px 未満のときに狭い配置にし、高さが 500px 未満ではペインを左の縦のタブで切り替える](0072-short-landscape-layout-in-playground.md)
- 今のプレイグラウンドの画面は、ペインごとに四方の 1px の枠を引き、その中の見出しの帯とタブの帯に罫を引き、ペインの間に仕切りの罫を引く。PC の画面では、仕切りの押せる幅 44px とペインの余白で、ペインの間が約 52px 空く。
- 利用者は、今の画面を角ばって見えると感じた。罫と余白で区切る案（W1）と、地の上に紙の面を重ねる案（W2）の画像を比べ、W2 を選んだ。PC の画面では、ペインの間を詰め、境界をはっきり出しすぎない形を求めた。利用者が承認した W2 の画像は、ペインの面を 10px、ペインの中のボタンを 6px、下のタブの帯とファイルのドロワーを 14px で丸めて描いた。
- VS Code は、ペインを 1px の罫で仕切り、ペインの間を空けない。
- WCAG 2.2 の 2.5.8（AA）は、押せる領域を 24×24 CSS px 以上にするか、24px の円が隣の押せるものに重ならない間隔を求める。
- WCAG 2.2 の 1.4.11 は、操作に要る図とコンポーネントの境界に 3:1 を求める。ペインの区切りは飾りの境界で対象外と読んでいる（解釈）。
- 地と面のコントラストの比を、プリミティブトークンの値から計算した値は、次の表のとおりである。

| 組                                         | ライト                         | ダーク                            |
| ------------------------------------------ | ------------------------------ | --------------------------------- |
| 地と面（`surface-ground`、`surface-pane`） | 1.23:1（`sumi-100`、`sumi-0`） | 1.10:1（`sumi-950`、`sumi-800`）  |
| 地とエディタの背景（`code-surface`）       | 1.10:1（`sumi-75`）            | 1.07:1（`sumi-1000`、地より暗い） |
| 面と hover の面（`surface-subtle`）        | 1.08:1（`sumi-50`）            | 1.00:1（どちらも `sumi-800`）     |
| フォーカスの輪と面                         | 17.25:1                        | 14.86:1                           |

## Decision

コードを動かす画面（プレイグラウンドの Node、SQL、Go のツールのページと、記事に埋め込んだ実行環境）だけ、ペインを地の上に重ねた紙の面にする。

- 面と地
  - セマンティックトークンに、地の `surface-ground` と、ペインの紙の面の `surface-pane` を足す。ライトは地を `sumi-100`、面を `sumi-0` にする。ダークは地を `sumi-950`、面を `sumi-800` にする。エディタと端末の背景（`code-surface`）は変えない。`surface-ground`、`surface-pane`、`rounded-pane`、`rounded-sheet` は、コードを動かす画面の外で使わない。
  - ペインの四方の枠と、ペインの間の仕切りの罫を引かない。面と地の濃さの差で区切る。
  - ハイコントラストのとき（`forced-colors: active`）だけ、ペインの面に 1px の枠を引く。面の塗りが消え、ペインの区切りが見えなくなるためである。
  - ペインの中の罫は、タブの帯の下の罫だけにする。見出しの帯の下、行番号の縦、エディタの下の案内の帯、プレビューの URL の帯の下の罫を引かない。
  - 面の上の hover の面は、面と見分けられる色にする。ダークの `surface-subtle` は面と同じ `sumi-800` なので、実装のときに値を詰める。
- 角
  - ペインの面を 10px、ペインの中の操作できる要素を 6px、下のタブの帯とファイルのドロワーを 14px で丸める。紙の面の重なりを、角の丸めで見分けるためである。
  - テーマ変数に、`rounded-pane`（10px）と `rounded-sheet`（14px）を足す。コードを動かす画面の中では、`rounded-control` を 6px にする。
  - ADR-0028 が丸めないと決めた要素（Tabs のタブ、下罫だけの検索の欄、メニューの項目、Notice、StatusBadge、Table、コードブロック）は、今のとおり丸めない。
  - フォーカスの輪は、要素の角の丸めに沿わせる。
- 重なる面
  - 下のタブの帯は、ペインと同じ `surface-pane` の面にし、枠と影を付けない。ペインの下に並ぶ面で、ADR-0028 の重なる面に当たらないためである。
  - ファイルのドロワーは、ペインに重なる面として、`surface-raised` の面と、右の縁の 1px の枠（`border-field`）で示し、影を付けない。利用者が承認した W2 の画像のとおりである。
- 間隔
  - マウスで押す端末の PC の配置では、ペインの間を 8px にする。面の間に地が見えないと、紙を重ねたように見えないためである。
  - 分割の幅を変える `SplitPane` の仕切りは、押せる幅を 8px にし、ペインの間の余白に置く。
    - 線はふだん出さず、マウスを載せたときに 2px の線を出す。
    - フォーカスしたときは、仕切りにも ADR-0066 の内側の輪（`focus-ring-inset`）を引く。8px の幅の外に 2px 離して輪を引くと、両側のペインの面に重なるためである。
  - 仕切りの押せる幅 8px は、WCAG 2.2 の 2.5.8 の 24×24 CSS px に届かない。`TARGET-SIZE` の例外として認める。
    - 24px の円が、ペインの中の押せるもの（木の行、エディタのスクロールバー）に重なる。
    - マウスで押す配置だけで使い、キーボードの矢印のキーで同じ操作ができる。
    - キーボードの操作が、2.5.8 が認める例外（同じ機能を持つ別の押せるもの）に当たるかは、未確認である。
  - 主な入力が指の端末（`pointer: coarse`）で PC の配置になるとき（横に向けたタブレット）は、仕切りの押せる幅とペインの間を 44px にする。ADR-0071 の押せる領域の大きさにそろえるためである。
- 記事の埋め込み
  - 記事の枠の中で、ペインを 1 つずつ出す配置では、地を出さず、ペインの面を枠いっぱいに置き、角を丸めない。記事の枠と面の縁が、二重の線に見えないようにするためである。枠の上のタブは、ペインの面の上に置き、タブの帯の下の罫だけを引く。
  - 記事の枠の中でペインを並べる配置の、地と角の出し方は、記事に埋め込む iframe の大きさが決まるまで決めない。記事の段の幅（640px）では、ペインを並べる配置にならない。

ADR-0028 の Decision の「罫で区切る版面を保ったまま」と「角丸」と、重なる面を影と組にする決定のうち、コードを動かす画面の中の分を、この ADR が置き換える。  
ADR-0062 の Decision の「色、罫、墨と生成りの面、角丸、筆の線の動きは変えない」のうち、罫、面、角丸の分を、この ADR が置き換える。  
ADR-0062 の Decision の押せる領域を 24×24 CSS px 以上にする決定のうち、マウスで押す端末の仕切りの分を、この ADR が置き換える。  
ADR-0066 の内側の輪を使う所を限る決定と、ADR-0061 の輪を要素から 2px 離して引く決定のうち、仕切りの分を、この ADR が置き換える。  
コードを動かす画面の外の角丸、影、罫を引く動き、筆の線の決定は、ADR-0028 のまま変えない。

## 承認の条件

- ADR-0071 と ADR-0072 を先に承認していること。
- 実装した画面を、ライトとダーク、PC と 375px で撮る。面の縁、hover の面、エディタの背景と `surface-ground` の境が見えることを、利用者が画像で確認する。撮る組には、ダークのドロワー、記事の埋め込み、指で押す端末の PC の配置（ペインの間 44px）を含める。
- 仕切りの hover の 2px の線と、8px の幅の中の内側の輪を撮って確認する。
- コントラストのチェックに、`surface-ground` と `surface-pane` の上の文字、`border-field`、フォーカスの輪の組を足す。文字は 4.5:1 以上、枠と輪は 3:1 以上であること。
- フォーカスの輪が、6px と 10px の角に沿って引かれることを、Chrome、Firefox、WebKit で撮って確認する。
- ハイコントラストのとき、ペインの区切りの 1px の枠が出ることを確認する。

## Considered Options

| 選択肢                                                                | 強み                                                                           | 弱み                                                                                             |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| **採用:** 地の上に角の丸い紙の面を重ね、ペインの間を 8px にする（W2） | 直角の線の数が最も減る。生成りの紙を重ねる形が、和紙と墨のサイトの考え方に合う | 角丸の名前が 2 つ増え、`rounded-control` の値が画面で変わる。仕切りの押せる幅が 2.5.8 に届かない |
| ペインの四方の枠を外し、帯の罫と余白だけで区切る（W1）                | ADR-0028 の角を変えない                                                        | 帯の罫は残り、利用者が挙げた角ばった見た目が残る                                                 |
| VS Code のように、ペインの間を空けず 1px の罫で仕切る                 | 画面を最も広く使える。仕切りの押せる領域を罫の上に重ねられる                   | 罫で区切る今の見た目に近く、角ばった見た目が残る                                                 |
| 今のまま（W0）                                                        | 変更が無い                                                                     | ペインの間が約 52px 空き、枠と罫が重なる                                                         |

## Consequences

### Positive

- PC の画面で、ペインの間が約 52px から 8px になり、エディタとプレビューが広くなる。
- ペインの区切りの罫が減り、ペインの中の内容が目に入りやすくなる見込みである。

### Negative

- コードを動かす画面と、サイトのほかの画面で、操作できる要素の角の丸めが違う。
- 地と面のトークンを 2 つ、角丸のテーマ変数を 2 つ持つ。
- 記事の埋め込みと、ツールのページで、面の角と地の出し方が違う。
- 仕切りの押せる幅が、マウスで押す端末と指で押す端末で違う。
- 仕切りは 2.5.8 の大きさに届かず、ADR-0062 の「AA への適合は変わらない」は仕切りには当たらない。2.5.8 が認める例外に当たるかは、未確認である。
