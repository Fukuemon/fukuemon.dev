# ADR-0073: コードを動かす画面を、地の上に角の丸い紙の面を重ねる見た目にし、面の角を 6〜14px で丸める

## Status

提案

## Context

コードを動かす画面の、ペインの区切りと角の丸めを決め直す必要がある。

- 罫で区切る版面を保ち、操作できる要素と重なる面の角を 2px で丸め、テーマ変数に角丸の名前を 1 つだけ置く（`rounded-control`）と決めている。Tabs のタブ、Notice、Table、コードブロックの角は丸めない。
  - ADR-0028: [操作できる要素と重なる面の角を 2px で丸め、重なる面にずらした影を付け、罫を引く動きを筆の線にする](0028-radius-shadow-and-brush-motion.md)
- コードを動かす画面は、文字と押せる領域を詰めた画面で、記事の本文と読み方が違う。
  - ADR-0062: [コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくする](0062-dense-text-and-targets-in-playground.md)
- 今の画面は、ペインごとに四方の 1px の枠を引き、その中の見出しの帯とタブの帯に罫を引き、ペインの間に仕切りの罫を引く。PC の画面では、仕切りの押せる幅 44px とペインの余白で、ペインの間が約 52px 空く。
- 利用者は、今の画面を角ばって見えると感じた。罫と余白で区切る案（W1）と、地の上に紙の面を重ねる案（W2）の画像を比べ、W2 を選んだ。PC の画面では、ペインの間を詰め、境界をはっきり出しすぎない形を求めた。
- VS Code は、ペインを 1px の罫で仕切り、ペインの間を空けない。
- WCAG 2.2 の 2.5.8（AA）は、押せる領域を 24×24 CSS px 以上にするか、24px の円が隣の押せるものに重ならない間隔を求める。

## Decision

コードを動かす画面（プレイグラウンドのツールのページと、記事に埋めた実行環境）だけ、ペインを地の上に重ねた紙の面にする。

- 面と地
  - セマンティックトークンに、地の `surface-ground` と、ペインの紙の面の `surface-pane` を足す。ライトは地を `sumi-100`、面を `sumi-0` にする。ダークは地を `sumi-950`、面を `sumi-800` にする。エディタと端末の地（`code-surface`）は変えない。
  - ペインの四方の枠と、ペインの間の仕切りの罫を引かない。面と地の濃さの差で区切る。
  - ペインの中の罫は、タブの帯の下の罫だけにする。見出しの帯の下、行番号の縦、エディタの下の案内の帯、プレビューの URL の帯の下の罫を引かない。
- 角
  - ペインの面を 10px、ペインの中の操作できる要素を 6px、下のタブの帯とファイルのドロワーを 14px で丸める。紙の面の重なりを、角の丸めで見分けるためである。
  - テーマ変数に、`rounded-pane`（10px）と `rounded-sheet`（14px）を足す。コードを動かす画面の中では、`rounded-control` を 6px にする。
  - Tabs のタブ、Notice、Table の角は、今のとおり丸めない。
- 間隔
  - PC の配置では、ペインの間を 8px にする。紙の面の重ねは、面の間に地が見えないと成り立たないためである。
  - 分割の幅を変える仕切りは、押せる幅を 8px にし、ペインの間の余白に置く。線はふだん出さず、マウスを載せたときとフォーカスしたときに 2px の線を出す。
- 記事の埋め込み
  - 記事の枠の中では、地を出さず、ペインの面を枠いっぱいに置き、角を丸めない。記事の枠と面の縁が、二重の線に見えないようにするためである。

コードを動かす画面の外の角丸、影、罫を引く動き、筆の線の決定は、ADR-0028 のまま変えない。

ADR-0028 の Decision の「角丸」のうち、コードを動かす画面の中の分を、この ADR が置き換える。

## 承認の条件

- 仕切りの押せる幅 8px は、WCAG 2.2 の 2.5.8（AA）の 24×24 CSS px に届かず、24px の円がペインの中の押せるもの（木の行、エディタのスクロールバー）に重なる。マウスで押す配置だけで使い、キーボードの矢印のキーで同じ操作ができることを、例外として認めるかを決める。
  - 認めないときは、押せる幅を 24px にし、ペインの縁に 8px ずつ重ねる。重ねた所では、ペインのスクロールバーを押せなくなる。
- 地と面のコントラストの比を測り、ライトとダークの両方で面の縁が見えることを確認する。

## Considered Options

| 選択肢                                                                | 強み                                                                           | 弱み                                                                                             |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| **採用:** 地の上に角の丸い紙の面を重ね、ペインの間を 8px にする（W2） | 直角の線の数が最も減る。生成りの紙を重ねる形が、和紙と墨のサイトの考え方に合う | 角丸の名前が 2 つ増え、`rounded-control` の値が画面で変わる。仕切りの押せる幅が 2.5.8 に届かない |
| ペインの四方の枠を外し、帯の罫と余白だけで区切る（W1）                | ADR-0028 の角を変えない                                                        | 帯の罫は残り、利用者が挙げた角ばった見た目が残る                                                 |
| VS Code のように、ペインの間を空けず 1px の罫で仕切る                 | 画面を最も広く使える。仕切りの押せる領域を罫の上に重ねられる                   | 罫で区切る今の見た目に近く、角ばった見た目が残る                                                 |
| 今のまま（W0）                                                        | 変更が無い                                                                     | ペインの間が約 52px 空き、枠と罫が重なる                                                         |

## Consequences

### Positive

- PC の画面で、ペインの間が約 52px から 8px になり、エディタとプレビューが広くなる。
- ペインの区切りの罫が減り、ペインの中の内容が目に入りやすくなる。

### Negative

- コードを動かす画面と、サイトのほかの画面で、操作できる要素の角の丸めが違う。
- 地と面のトークンを 2 つ、角丸のテーマ変数を 2 つ持つ。
- 記事の埋め込みと、ツールのページで、面の角と地の出し方が違う。
