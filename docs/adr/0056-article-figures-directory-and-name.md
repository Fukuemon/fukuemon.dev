# ADR-0056: 記事の図を `content/figures/` に置いて画像の記法で指し、`/figures/` で配り、キャンバスには図の名前を渡す

## Status

承認

## Context

運営者がキャンバスから書き出した SVG を置くディレクトリ、記事の Markdown から図を指す書き方、キャンバスが図を読む URL、キャンバスに渡す識別子の形を決める必要がある。

- 記事の図は、元データ入りの SVG の 1 枚をリポジトリに置き、ビルドのときに記事の HTML にインラインで入れる。図を置くディレクトリは 1 つにし、そのディレクトリの第三者のアイコンと書体を、MIT License の対象から外す。キャンバスは、fukuemon.dev の図のパスだけを読み込み、fukuemon.dev は、図のパスに `play.fukuemon.dev` を許す `Access-Control-Allow-Origin` を返す。
  - ADR-0040: [記事に埋め込むキャンバスの図は、元データ入りの SVG をリポジトリに置き、ビルドのときにインラインにする](0040-canvas-figures-in-articles.md)
- キャンバスは、draw.io のツールと Excalidraw のツールの 2 つで、別のパスに置く。
  - ADR-0039: [キャンバスは、構成図を draw.io の Embed Mode で、手描きの図を Excalidraw で、別のパスのツールとして提供する](0039-canvas-drawio-and-excalidraw.md)
- キャンバスのツールは、名前を付けた複数の図を IndexedDB に保存する。訪問者が記事の図をキャンバスで開いたときは、開いた図を新しい図として保存し、保存してあった図は変えない。
  - ADR-0043: [キャンバスとスライドのエディタは、ツールごとに、名前を付けた複数の図とスライドを IndexedDB に保存する](0043-multiple-named-documents-per-tool.md)
- 記事の原稿は `apps/web/src/content/articles/` に置き、ディレクトリの入れ子は 1 階層までにする。ADR-0030 の Decision 2 の URL の表に、図の URL は無い。
  - ADR-0030: [種別を記事の 1 つにし、構成を記事の形式で、シリーズをディレクトリで表す](0030-articles-format-and-series.md)
- 公開するスライドの Markdown は、`apps/web/src/content/slides/` に置く。
  - ADR-0042: [公開するスライドは、ビルドのときに静的な HTML にして `/slides/<slug>` に置き、記事には iframe で埋め込む](0042-published-slides-as-static-pages.md)
- 実行環境のプロジェクトは、記事のディレクトリの下に置く。記事の iframe の URL には、埋め込みの ID だけを書き、ツールのページが JSON の URL を組み立てる。記事のディレクトリの形は、決まっていない。
  - ADR-0049: [記事の埋め込みの初期ファイルと設定を、`apps/web` のビルドが JSON にし、ツールのページが埋め込みの ID で読む](0049-playground-projects-from-articles.md)
- draw.io が書き出す元データ入りの SVG は、ルートの `content` の属性に図の XML を持つ。Excalidraw が書き出す SVG は、`payload-type:application/vnd.excalidraw+json` のコメントと、scene を持つ。

## Decision

### 1. 図を置くディレクトリ

運営者は、キャンバスから書き出した SVG を、`apps/web/src/content/figures/` に置く。

- ファイルの名前は、`<名前>.drawio.svg` か `<名前>.excalidraw.svg` にする。拡張子で、描いたツールを表す。
- `<名前>` は、小文字の英数字とハイフンだけにする（`^[a-z0-9][a-z0-9-]*$`）。ディレクトリの入れ子は作らない。
- ビルドは、SVG の中の元データが拡張子のツールと合うかを確認し、合わないときは失敗する。

`content/` の直下の 1 つのディレクトリにする理由は、MIT License の対象から外す記述が 1 つのパスで済むことと、1 つの図を複数の記事で使えることである。

### 2. 記事の Markdown から図を指す書き方

運営者は、Markdown の画像の記法で、図のファイルを相対パスで指す。

```md
![VPC の構成](../figures/vpc.drawio.svg "東京リージョンの VPC")
```

- ビルドは、`content/figures/` のファイルを指す画像を、インラインの SVG に置き換える。そのほかの画像は変えない。
- 代替テキストは必須にする。空のときと、指したファイルが無いときは、ビルドが失敗する。
- 画像の記法のタイトル（引用符の中の文）は、図のキャプションにする。
- 全ての図の下に、「キャンバスで開く」のリンクを出す。

画像の記法にする理由は、`.md` のまま書けること、エディタのプレビューと GitHub で図が見えること、代替テキストとキャプションを書く場所が記法にあることである。

### 3. 図の URL

`apps/web` のビルドは、置いた SVG を、変えずに `https://fukuemon.dev/figures/<名前>.<ツール>.svg` に出力する。  
fukuemon.dev は、`/figures/*` に、`play.fukuemon.dev` を許す `Access-Control-Allow-Origin` を返す。

変えずに出力する理由は、キャンバスのツールが、運営者の書き出した元データを、そのまま読めるためである。

サイトの URL に、次の 1 つを足す。ADR-0030 の Decision 2 のほかの URL は変えない。

| URL                            | 中身                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ |
| `/figures/<名前>.<ツール>.svg` | 記事の図の、元データ入りの SVG。`play.fukuemon.dev` のキャンバスのツールが読む |

### 4. キャンバスに渡す識別子

「キャンバスで開く」のリンクは、図の名前だけを渡す。

```text
https://play.fukuemon.dev/drawio/?figure=vpc
https://play.fukuemon.dev/excalidraw/?figure=vpc
```

- キャンバスのツールが、名前から図の URL（`https://fukuemon.dev/figures/<名前>.<自分のツール>.svg`）を組み立てて、`fetch` する。
- ADR-0040 の Decision 3 の「識別子は、fukuemon.dev の図のパスである」は、図のパスのうち、図ごとに変わる部分（名前）を渡す、という意味で読む。パスの先頭と拡張子は、キャンバスのツールが足す。
- キャンバスのツールは、名前が Decision 1 の規則に合わないときは、`fetch` しない。
- キャンバスのツールは、リダイレクトを辿らずに `fetch` する。

名前だけを渡す理由は、URL の値で、`/figures/` のほかのパスと、ほかの origin を指せなくなるためである。  
ツールは URL のパスで決まるので、図を、描いたツールと別のツールに渡すリンクは作れない。

### 5. 開いた図を保存する時点

キャンバスのツールは、記事の図を開いただけでは、IndexedDB に保存しない。  
訪問者が最初に編集したときに、新しい図として保存する。

- ADR-0043 の Decision の「開いた図を新しい図として保存する」は、最初に編集したときに保存する、という意味で読む。
- 保存してあった図は変えない。同じ記事の図から作った図が保存してあっても、リンクは、記事の図を開く。
- 保存する図は、出所として、記事の図の名前を持つ。

最初の編集で保存する理由は、同じリンクを開くたびに、一覧に図が増えないようにするためである。

### 6. 図の名前の規則と URL の形を置く package

図の名前の規則と、ファイルの名前と URL のパスの形は、新しい package（`packages/figures`、`@fukuemon/figures`）に置く。

- package は、次の 6 つを持つ。
  - 図を描いたツールの型（`drawio`、`excalidraw`）
  - 名前が Decision 1 の規則に合うかを返す関数
  - 名前とツールから、ファイルの名前（`<名前>.<ツール>.svg`）と、URL のパス（`/figures/<名前>.<ツール>.svg`）を組み立てる関数
  - ファイルの名前を、名前とツールに分ける関数
  - 名前とツールから、「キャンバスで開く」のリンクのパスとクエリ（`/<ツール>/?figure=<名前>`）を組み立てる関数
  - クエリから名前を読む関数。クエリのキー（`figure`）は、値としても公開する
- package は、SVG を読む処理、`fetch`、2 つのアプリの origin の値を持たない。
- `apps/web` のビルドは、この package で、ファイルの名前を検証し、出力するパスと、「キャンバスで開く」のリンクを組み立てる。`apps/playground` は、同じ package で、クエリから `figure` の値を読んで検証し、`fetch` する URL のパスを組み立てる。
- package は、workspace のほかの package にも、React にも依存しない。

package にする理由は、図を出力する側（`apps/web`）と、読む側（`apps/playground`）の 2 つが、同じ規則と同じパスの形を使うためである。

## Considered Options

図を置くディレクトリの選択肢は次のとおり。

| 選択肢                                               | 強み                                                                                                            | 弱み                                                                                                                  |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **採用:** `apps/web/src/content/figures/` に置く     | スライドの Markdown と同じ並びになる。MIT License の対象から外す記述が 1 つのパスで済む。図を複数の記事で使える | 図と記事が、別のディレクトリになる。図の名前を、ツールごとに、サイトの全体で重ならないようにする                      |
| `apps/web/public/figures/` に置く                    | ビルドが、図を出力する処理を持たずに済む                                                                        | 運営者が書く原稿が、`content/` と `public/` に分かれる                                                                |
| 記事のディレクトリの下（`articles/<記事>/figures/`） | 図が、記事と同じ場所にまとまる。実行環境のプロジェクトと同じ並びになる                                          | ADR-0040 の「ディレクトリを 1 つ」と合わない。記事のディレクトリの形（ADR-0049 の承認の条件）が決まるまで決められない |

Markdown の書き方の選択肢は次のとおり。

| 選択肢                                                      | 強み                                                                                     | 弱み                                                                                        |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **採用:** 画像の記法で、図のファイルを相対パスで指す        | `.md` のまま書ける。プレビューと GitHub で図が見える。代替テキストとキャプションを書ける | シリーズの中の記事は、`../../figures/` と書く。ビルドに、図を指す画像を置き換える処理が要る |
| コードフェンス（`figure`）に、図の名前を書く                | Mermaid の図と同じ形になる                                                               | 代替テキストとキャプションを書く場所を、別に決める。プレビューで図が見えない                |
| ディレクティブ（`::figure{name="…" alt="…"}`）で書く        | 属性を足しやすい                                                                         | ディレクティブのプラグインが要る。プレビューで図が見えない                                  |
| MDX のコンポーネント（`<Figure name="…" alt="…" />`）で書く | 属性を型で検証できる                                                                     | `.mdx` の記事でしか使えない                                                                 |

キャンバスに渡す識別子の選択肢は次のとおり。

| 選択肢                                              | 強み                                                                                                                                | 弱み                                                                                                                             |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **採用:** 図の名前だけを渡す（`?figure=vpc`）       | 埋め込みの ID（ADR-0049）と同じ形になる。ほかのパスと、ほかの origin を指せない。拡張子と、ツールのページが合わないリンクを作れない | キャンバスのツールのコードが、fukuemon.dev の図のパスの形に依存する。パスの形を、2 つのアプリが使う package に置く（Decision 6） |
| 図のパスを渡す（`?figure=/figures/vpc.drawio.svg`） | キャンバスのツールが、パスの組み立てを持たずに済む                                                                                  | キャンバスのツールが、パスの先頭、`..`、拡張子とツールの一致を検証する。検証の抜けが、ほかのパスの読み込みになる                 |
| 図の URL を渡す                                     | fukuemon.dev のほかに置いた図も開ける                                                                                               | ADR-0040 が退けた形である。他人が用意した図を、URL を開かせるだけで読み込める                                                    |

開いた図を保存する時点の選択肢は次のとおり。

| 選択肢                                                 | 強み                                                   | 弱み                                                         |
| ------------------------------------------------------ | ------------------------------------------------------ | ------------------------------------------------------------ |
| **採用:** 最初に編集したときに、新しい図として保存する | リンクを開くたびに、一覧に図が増えない                 | 編集しないで閉じると、一覧に残らない                         |
| 開いたときに、新しい図として保存する                   | 開いた図が、必ず一覧に残る                             | 同じリンクを開くたびに、同じ図が増える                       |
| 同じ図から作った図が保存してあれば、それを開く         | 記事を開き直すと続きが開く、実行環境の動きと同じになる | 記事の図が変わっても、古い図が開く。記事の図に戻す操作が要る |

図の名前の規則と URL の形を置く場所の選択肢は次のとおり。

| 選択肢                                                    | 強み                                                                                                                            | 弱み                                                                                       |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **採用:** 依存を持たない新しい package に置く             | 規則とパスの形が 1 か所になる。プロジェクトの JSON の形を `@fukuemon/playground-project` に置いた ADR-0049 と、同じ分け方になる | package が 1 つ増える                                                                      |
| `apps/web` と `apps/playground` の 2 か所に、同じ形を書く | package を増やさずに済む                                                                                                        | 片方だけを直すと、ビルドが通ったまま、「キャンバスで開く」のリンクの先で、図を読めなくなる |

## Consequences

### Positive

- 運営者は、SVG の 1 枚を `content/figures/` に置き、画像の記法の 1 行を書くだけで、図を記事に埋め込める。
- 運営者は、ファイルの名前で、図を描いたツールを見分けられる。
- 他人が、自分の用意した図を読み込ませる URL を作れない。

### Negative

- サイトの URL と、`Access-Control-Allow-Origin` を返すパスが、1 つずつ増える。
- 図の名前を変えると、その図を指す記事の Markdown と、訪問者が保存した「キャンバスで開く」のリンクが、古い名前を指す。
- workspace の package が、1 つ増える。
- 図を描いたツールの型（package）と、保存する図のツールの種類（`apps/playground`）が、同じ文字列を別々に持つ。ツールのページが、同じ文字列を両方に渡す。
- SVG の中の元データが、どのツールのものかを見分ける処理は、`apps/web` のビルドと、`apps/playground` のツールのページの 2 か所が持つ。2 か所が別々に持つ理由は、ビルドは見分けるだけで、ツールのページは元データを取り出すまで行うためである。
- ビルドに、画像の記法を置き換える処理と、拡張子と元データの一致を確認する処理が増える。
- 1 つの記事に複数の図をインラインで入れたときに、SVG の中の `id` が重なるかは、確認していない。
