# ADR-0066: コードを動かす画面の詰めたペインで、フォーカスの輪を要素の内側に引き、13px の文字のトークンを 2 つ足す

## Status

提案

## Context

コードを動かす画面のペインを隙間なく並べ、行を 24px に詰めたときの、フォーカスの表示と文字のトークンを決める必要がある。

- フォーカスの表示は、要素から 2px 離して引く墨の 2px の輪で、`focus-ring` の 1 つのユーティリティで書くと決めている。例外は検索の欄だけである。
  - ADR-0061: [フォーカスの表示を、DADS の黄と黒の 2 重の表示から、墨の 2px の 1 重の輪にする](0061-sumi-focus-ring.md)
- コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくすると決めている。テーマ変数には、`text-compact`（12px）と `text-label-compact`（太字の 13px）の 2 つを置くとしている。
  - ADR-0062: [コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくする](0062-dense-text-and-targets-in-playground.md)
- コードを動かす画面は、ペインの間の隙間と外側の余白をなくし、木の行を 24px、HTTP の流れの行を約 44px に詰めた。
- 外へ広がる輪は、次の所で欠けるか、隣に掛かる。
  - スクロールの枠の中で、枠の幅いっぱいの木の行と HTTP の流れの行の輪は、左右が枠で切れる。
  - 24px の木の行が隙間なく並ぶので、輪が上下の行に 4px 掛かる。
  - ペインいっぱいのスクロールの枠（コンソールの行の領域、エディタのエンジン）の輪は、隣のペインと題の帯に出るか、ペインの端で切れる。
  - エディタのタブの並びは横に送る枠なので、タブの輪の上下が切れる。
- VS Code と Chrome DevTools は、一覧の行のフォーカスを、行の内側に引く枠で示す。
- 詰めたペインの文字には、ADR-0062 の 2 つのほかに、13px の細字（ファイルの木の行、入力欄の値、表のセル）と、13px の等幅（エディタ、端末、HTTP のメソッドと URL）が要る。
  - ADR-0062 は、13px にしてよい文字を「コードと操作のラベル」としている。木の行、入力欄の値、表のセルは、この範囲に入らない。
  - 13px の等幅の文字を、VS Code と StackBlitz の行の間隔（12px の文字で 18px）に近い約 20px の行に置くには、DADS の行高（130%、150%、160%、170%）に無い値が要る。

## Decision

### 1. 詰めたペインの中の行と、ペインいっぱいの枠では、フォーカスの輪を要素の内側に引く

- テーマ変数のファイルに、`focus-ring-inset` のユーティリティを足す。色と太さは `focus-ring` と同じ墨の 2px で、輪を要素の内側に 2px 入れて引く（`outline-offset: -2px`）。
- 使う所は、コードを動かす画面のコンポーネントの次の要素に限る。
  - `TreeView` の `density="compact"` の項目
  - `Tabs` の `density="compact"` のタブと、マウスで押す閉じるボタン
  - `HttpExchangeList` の行
  - ペインいっぱいに置く、フォーカスできるスクロールの枠。今は `ConsoleEntryList` の行の領域と、エディタと端末のエンジンを置く枠である
- ほかの要素は、`focus-ring` のままにする。
- 理由は次のとおり。
  - 輪が要素の中に収まるので、隣の行と領域の端で欠けず、行の密度を変えずに済む。
  - VS Code と DevTools の一覧の行と同じ示し方で、使う人が見慣れている。
- `FOCUS-ONE` の例外に、この 1 つを足す。

ADR-0061 の Decision のうち、「要素から 2px 離して引く」と「表示は `focus-ring` のユーティリティ 1 つで書く」を、上の要素についてだけ、この Decision が置き換える。
ADR-0061 の Consequences の「輪が外へ広がる幅は 4px」も、上の要素には当たらない。

### 2. 詰めたペインの文字のトークンを 4 つにし、13px の等幅の行高に DADS に無い値を使う

- テーマ変数に、`text-compact`（12px）と `text-label-compact`（太字の 13px）に加えて、次の 2 つを置く。
  - `text-body-compact`: 13px の細字。行高は 130%。
  - `text-code-compact`: 13px の等幅。行高は 154%（約 20px）。
- 154% は DADS の行高に無いので、プリミティブトークンに足す。DADS の 150% では、行は 19.5px になる。
- 13px にしてよい文字を、コードと操作のラベルに加え、木の行、入力欄の値、表のセルに広げる。
- 4 つのトークンは、コードを動かす画面のコンポーネントの外で使わない。使う場面は、デザインシステムの Design Doc の文字の表に書く。

ADR-0062 の Decision のうち、テーマ変数に置く compact のトークンを 2 つとした決定と、13px にしてよい文字をコードと操作のラベルとした範囲を、この Decision が置き換える。

## Verification

カタログの「画面/コードを動かす画面」を、Chromium の 1600x900 で開いて確認した。

- 木の行と HTTP の流れの行にキーボードでフォーカスを置くと、輪は行の中に収まり、上下の行とペインの端に掛からなかった。ライトとダークの両方で見た。
- compact のタブ、コンソールの行の領域、エディタのエンジンを置く枠は、コンポーネントのテストで、フォーカスしたときの輪が要素の内側（`outline-offset: -2px`）に引かれることを確認した。画面での見た目は撮っていない。
- 内側の輪が WCAG 2.2 の達成基準 2.4.13（AAA）を満たすかは、未確認である。
- 選んだ木の行（`primary-surface`）の上でも、墨の輪は見えた。輪と面の組は、ADR-0061 でコントラストのチェックに入れてある。
- 13px の等幅の行の高さは 20.02px だった。
- Safari と Firefox での確認はしていない。

## Considered Options

| 選択肢                                                              | 強み                                                                               | 弱み                                                                                |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **採用:** 詰めたペインの行と枠だけ、内側に輪を引く                  | 輪が欠けず、隣にも掛からない。行の密度を変えない。VS Code と DevTools と同じ示し方 | フォーカスの表示が 2 つになる。内側の輪は、行の中の文字や印に近づく                 |
| スクロールの枠と行の間に 4px の余白を足し、外へ広がる輪のままにする | フォーカスの表示が 1 つのまま                                                      | 木の行の間が広がり、DevTools と VS Code に近い密度にならない                        |
| 今のまま、欠けた輪を受け入れる                                      | 変更が無い                                                                         | 左右が欠けた輪は上下の 2 本の線になり、輪の形で見つけにくい。上下の行の文字に掛かる |

13px のトークンについては、次の案を比べた。

| 選択肢                                                                | 強み                                                                                      | 弱み                                                               |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| **採用:** 13px の細字と等幅のトークンを足し、等幅の行高に 154% を使う | ファイルの木の行と名前が太字にならない。エディタの行が VS Code と StackBlitz の間隔に近い | トークンが 4 つになる。DADS に無い行高が 1 つ増える                |
| `text-label-compact` に細字の指定を重ねる                             | トークンが増えない                                                                        | 使う側ごとに太さを書き、トークンで文字のスタイルを決める形が崩れる |
| 等幅の行高を DADS の 150% にする                                      | DADS の値だけで済む                                                                       | 行が 19.5px になり、20px の行と合わない                            |

## Consequences

### Positive

- 詰めたペインで、どの行と枠にフォーカスがあるかを、欠けない輪で示せる。
- 詰めたペインの文字を、トークンだけで書ける。

### Negative

- フォーカスの表示のユーティリティが 2 つになる。`focus-ring-inset` をコードを動かす画面の外で使っていないかは、レビューで見る。
- 内側の輪は、行の背景の面の上に出る。行の面とのコントラストは、ADR-0061 のチェックの組に頼る。
- DADS に無い行高が 1 つ増える。
