# ADR-0080: 墨の絵と署名の SVG を、トップの HTML に入れず、最初の訪問のときだけ読み込む

## Status

提案

## Context

トップの墨の絵と署名の SVG を、どこから配信するかを決める必要がある。

- ADR-0026 は、墨の絵を SVG の線にして HTML に置き、CSS の遷移で筆の順に描くと決めている。署名も SVG の `path` として置く。
  - ADR-0026: [トップの最初の訪問で水墨の門を描き、門をくぐった立体の庭にプロフィールを置く](0026-sumi-gate-and-garden-on-top.md)
- 墨の絵と署名を出すのは、最初の訪問のイントロの間だけである。2 回目以降の訪問と、庭を出さない訪問では、`display: none` のまま、画面に出ない。
- 墨の絵の SVG は gzip で約 36 KB、署名の SVG は gzip で約 8 KB を占める。
- 2 回目以降の訪問のトップは、LCP が 2.5 秒以内で、Performance が 90 以上という要求の対象である。
- ADR-0026 の承認の条件は、要求を満たさなければ、ふつうの HTML を先に出し、「庭に入る」のボタンで庭を出す形に替えると決めている。
- ADR-0026 は、最初の訪問のトップを LCP の要求の対象から除くと決めている。
- トップの合否は、ADR-0078 の条件で測る。
  - ADR-0078: [トップの Lighthouse の合否を、Metal の GPU と simulate のスロットリングで 5 回測った中央値で判定する](0078-top-lighthouse-gpu-and-throttling.md)
- 同じビルドから `<InkGate />` だけを外して、有りと無しを比べた。
  - 外れたのは、墨の絵と署名の SVG と、イントロの CSS である。
  - 条件は ADR-0078 と同じで、`pnpm run measure:top` を、有りと無しで 5 回ずつ、2 組測った。
  - HTML は、gzip で有りが 55,017 バイト、無しが 6,941 バイトだった。
  - 2 回目以降の訪問の Performance は、有りが 89 と 90、無しが 92 と 93 だった。LCP は、有りが 3150 ms と 3139 ms、無しが 2829 ms と 2827.5 ms だった。
  - 庭を出さない訪問（`--visit reduced-motion`）の Performance は、有りが 98、無しが 100 だった。LCP は、有りが 1801 ms、無しが 1501 ms だった。
  - 参考の `--throttling devtools` では、2 回目以降の Performance はどちらも 81 で、差が出なかった。simulate の差が、実際の読み込みでも出るかは確認していない。
  - ほかの変更を入れたトップの値は測っていない。

## Decision

墨の絵と署名の SVG を、トップの HTML に入れない。最初の訪問のときだけ、別のファイルとして読み込む。

- ファイル
  - ビルドのときに `ink/` が、リポジトリの中の入力だけから作る。
  - `/_astro/` から、内容のハッシュを入れたファイル名で配信する。
  - 形式と MIME は、実装のときに Design Doc に書く。
- 読み込み
  - 最初の訪問のとき、head のスクリプトが、場面のバンドルと並べて、このファイルを `fetch` する。`.ink-gate` の要素に挿入し、線を描く遷移は、挿入した時点から動く。
  - `stage/` には、同じ origin の `/_astro/` の URL だけを渡す。場面のバンドルの URL と同じエスケープで inline script に埋める。`location` と `localStorage` の値から URL を作らない。
  - 静的な `preload` は置かない。2 回目以降の訪問にも読み込ませてしまうためである。
  - 2 回目以降の訪問と、庭を出さない訪問では、読み込まない。HTML にも入れない。
  - Content-Security-Policy は `frame-ancestors` だけで、同じ origin の `fetch` を止めない。後で `script-src` や `connect-src` を絞るときは、この読み込みを許す。
- 結果の伝え方
  - head のスクリプトは、応答が想定どおりの SVG だと確認して挿入できたときに、`html` の class `ink-ready` を付ける。
  - 通信の失敗、`!res.ok`、想定と違う `Content-Type` か中身のときは、class `ink-failed` を付ける。無い URL に 404 の HTML が返ったときも、`ink-failed` を付ける。
  - class を読んで動くのは、場面のバンドルである。
- 失敗とタイムアウト
  - 場面のバンドルが `ink-failed` を読んで、ふつうのページに戻す。場面が動き出した後のクリーンアップは、場面のバンドルが持つためである。
  - 最初の訪問では、`scene-ready` と `ink-ready` の両方が 6 秒で揃わなければ、ふつうのページに戻す。ADR-0026 の、場面の準備を 6 秒で打ち切る決定を、この形に変える。2 回目以降の訪問は、`scene-ready` だけを 6 秒待つ。`scene-ready` の意味は変えない。
  - 6 秒のタイムアウトでは、`fetch` を abort する。その後に届いた応答は、挿入せず、class も付けない。
- 色を差す時刻
  - ADR-0026 の、墨の線と署名の遷移が終わるのを待ってから色を差す決定は、変えない。
  - 場面のバンドルは、`ink-ready` が付いてから、遷移を集めて待つ。
  - 色を差す時刻は、`ink-ready` を付けた時刻に `intro-timing.ts` の `INK_END`（署名を書き始めるまでの 600 ms を含む）を足した時刻より前にしない。
- ふつうのページ
  - ADR-0026 の、ふつうのページの帯に止まった水墨の絵を置く決定は、置き換える。ふつうのページには、墨の絵を置かない。`apps/web/src` に、その実装は無い。
- 変えないこと
  - ADR-0026 の、墨の絵の描き方（SVG の線、筆の順、立体の配置と同じ位置、署名の `path`）は、変えない。

理由は、LCP が要求を満たしていない 2 回目以降の訪問に、使わない墨の絵と署名の SVG（gzip で約 44 KB）を配信しないためである。
`<InkGate />` を外したビルドは、HTML が gzip で約 48 KB 小さく、simulate の測定で LCP が約 0.32 秒短く、Performance が約 3 点高かった。

## 承認の条件

実装の中で、次を確認する。

- 最初の訪問のイントロが、ADR-0026 と同じ筆の順で終わり、署名と墨の絵が、色を差すまでに描き終わる。
- 無い URL に 404 の HTML が返ったとき、`ink-failed` が付き、ふつうのページに戻る。
- 墨の絵と署名のファイルの応答を 6 秒を超えて遅らせたとき、ふつうのページに戻る。
- 墨の絵と署名のファイルが、場面の準備より後に届いても、線を描き終わってから色を差す。
- 2 回目以降の訪問と、庭を出さない訪問の HTML に、イントロの墨の絵と署名（`.ink-gate` の中）の SVG が無い。ヘッダーのロゴの署名は、全てのページの HTML に残る。
- `stage/` と `ink/` の間の import の向きの規則を、Design Doc と Oxlint に足す。
- 挿入する処理を含めて、`pnpm run measure:top-intro` の `ink` と `assemble` の最長タスクとコマ落ちが、HTML に置いたときの値より悪くならない。HTML に置いたときの値は、`--cpu 4` で、場面のバンドルを遅らせないとき `ink` が 12〜16 ms、`assemble` が 313〜339 ms、1500 ms 遅らせたとき `ink` が 302〜322 ms である。
- 外した後の 2 回目以降の訪問のトップを、ADR-0078 の条件で測り直し、値を記録する。要求を満たさないときの扱いは、ADR-0026 の承認の条件による。

承認の後に直す文書は、次のとおり。

- ADR-0026 の、墨の絵と署名を HTML に置く記述と、ふつうのページの帯に止まった水墨の絵を置く記述。
- `docs/adr/index.md` の「番号の対応」に、ADR-0026 から ADR-0080 へ移した 2 つの判断を足す。
- `packages/ui/src/art/DesignDoc.md` と `apps/web/src/features/top-garden/DesignDoc.md` の、墨の絵を HTML に置く記述。

| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **採用:** 墨の絵と署名の SVG を HTML に入れず、最初の訪問のときだけ別のファイルで読み込む | 2 回目以降の HTML が、gzip で約 48 KB 小さくなる見込みである。simulate の測定で、LCP が約 0.32 秒短く、Performance が約 3 点高かった。庭を出さない訪問にも、配信しない | 最初の訪問で、墨の線を描き始めるのが、ファイルが届くまで遅れる。読み込みが 1 つ増え、失敗する処理が 1 つ増える                 |
| 今のまま、HTML に入れる                                                                   | 最初の訪問で、HTML と一緒に届き、線を描き始めるのが遅れない。実装が要らない                                                                                            | 2 回目以降の Performance の中央値が 89 と 90 で、1 組は要求の 90 に届かない。LCP が約 0.32 秒延びる                            |
| ふつうの HTML を先に出し、「庭に入る」のボタンで庭を出す形に替える                        | ADR-0026 の承認の条件に沿う。LCP の要求を満たしやすい                                                                                                                  | イントロと、庭がすぐ出る動きが無くなる。ADR-0026 の演出の決定を置き換える                                                      |

## Consequences

### Positive

- 2 回目以降の訪問と、庭を出さない訪問の HTML が小さくなる。
- 測定では、2 回目以降の Performance が 92 と 93 で、要求の 90 以上を満たした。

### Negative

- 最初の訪問で、墨の線を描き始める時刻が、ファイルが届くまで遅れる。
- 墨の絵と署名のファイルの読み込みの失敗を、扱う必要がある。
- 測定では、庭を出す訪問の LCP が 2.83 秒で、要求の 2.5 秒以内を満たさない。この変更だけでは届かない見込みである。測り直した値が届かないときの扱いは、ADR-0026 の承認の条件による。この ADR では決めない。
