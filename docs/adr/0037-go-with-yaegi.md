# ADR-0037: Go のコードを、Yaegi のインタプリタの WASM で動かす

## Status

承認（Decision の「Yaegi の WASM は、訪問者が実行のボタンを押してから読み込む」を ADR-0063 に置換）

## Context

訪問者が書き換えた Go のコードを動かし、標準出力と `go test` 相当の結果を見せる方式を決める必要がある。  
Go の HTTP サーバーを立てることは、対象にしない。

- 訪問者のコードは訪問者のブラウザの中だけで動かし、サイトのサーバーに送らない。
  - ADR-0008: [読者の identity を前提とする機能を作らず、バックエンドを持たない](0008-no-reader-identity.md)
- 実行環境の選び方は、有効な決定が無い。
  - ADR-0030: [種別を記事の 1 つにし、構成を記事の形式で、シリーズをディレクトリで表す](0030-articles-format-and-series.md)
- 訪問者が書いたコードを動かすツールは、プレイグラウンドのサブドメインに置く。cross-origin isolation のヘッダは、Node の実行環境のパスにだけ返す。
  - ADR-0034: [cross-origin isolation のヘッダを、プレイグラウンドの Node の実行環境のパスと、それを埋め込む記事の URL にだけ返す](0034-playground-origin-and-embedding.md)
- TinyGo の公式の playground は、サーバーでコンパイルする。TinyGo のコンパイラは、LLVM に依存する。
  - 出典: [tinygo-org/playground](https://github.com/tinygo-org/playground)
  - 出典: [TinyGo: Build from source](https://tinygo.org/docs/guides/build/)
- Yaegi の README は、Go 1.21 と 1.22 に対応すると書いている。
  - 出典: [traefik/yaegi](https://github.com/traefik/yaegi)

## Decision

Go のコードは、Yaegi のインタプリタを WASM にして、ブラウザの中で動かす。

- ダウンロードのサイズが、Go のコンパイラを WASM にする形の約 4 分の 1 で済むためである。
- Yaegi の WASM は、cross-origin isolation を求めない。Go だけを動かす記事には、isolation のヘッダが掛からない。
- `go test` 相当の結果は、テストの関数を `testing.Main` に渡して出す。`testing.Main` は `os.Exit` で終わるので、実行のたびに WASM のインスタンスを作り直す。
- Yaegi の WASM は、訪問者が実行のボタンを押してから読み込む。

記事の Go のコードは、Yaegi が動かせる範囲で書く。  
`iter` パッケージと、型の推論に失敗するジェネリックな関数は使わない。

## Verification

Yaegi 0.16.3 と Go 1.26.4 を、Node の上で動かして比べた（Apple M2）。  
ブラウザの中での起動の時間は、どちらの方式も確認していない。

| 項目                 | Yaegi の WASM                                                                             | Go のコンパイラとリンカの WASM                                                      |
| -------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| ダウンロードのサイズ | 40.0 MB。gzip で 8.41 MB、brotli で 5.78 MB                                               | コンパイラ、リンカ、標準ライブラリの 187 個のパッケージの合計が、brotli で 20.99 MB |
| 起動                 | 読み込みと初期化に 0.14 秒                                                                | hello world のコンパイルに 0.51 秒、リンクに 0.31 秒                                |
| 言語                 | `iter` を import できない。関数を引数に取るジェネリックな関数の一部で、型の推論に失敗する | Go 1.26.4 のコンパイラそのもの                                                      |
| 実行速度             | `fib(27)` に 1.1 秒                                                                       | 未確認                                                                              |
| `go test` 相当       | `=== RUN`、`--- PASS`、`--- FAIL`、サブテストの出力が出た                                 | テストの main を生成する処理が要る。未確認                                          |
| ブラウザでの実行     | 未確認                                                                                    | 仮想のファイルシステムが要る。未確認                                                |

- Yaegi で、`fmt`、`encoding/json`、`sync`、`context`、`crypto/sha256`、`net/http/httptest` は動いた。
- Yaegi のコンパイルのエラーは、行と列つきで返る。テストの失敗の行の場所は、テストのファイルの行にならない。
- WASM のインスタンスを作り直す時間は、0.06 秒だった。

## Considered Options

| 選択肢                                | 強み                                                                    | 弱み                                                                                                                         |
| ------------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **採用:** Yaegi のインタプリタの WASM | 読み込みが brotli で 5.78 MB。`go test` 相当の出力が、Node の上で動いた | Go 1.22 までの言語で、ジェネリックの一部と `iter` が使えない。インタプリタなので、計算の多いコードが遅い                     |
| Go のコンパイラとリンカを WASM にする | 言語と標準ライブラリが、手元の Go と同じになる                          | brotli で約 21 MB を読み込む。ブラウザの仮想のファイルシステムと、テストの main の生成を作る。ブラウザで動くかは未確認である |
| TinyGo                                | 出力する WASM が小さい                                                  | 訪問者が書き換えたコードを、サーバーでコンパイルすることになる。訪問者のコードをサーバーに送らない条件と両立しない           |

## Consequences

### Positive

- Go だけを動かす記事は、WebContainers のライセンスとブラウザの対応に依らずに公開できる。
- 訪問者は、コードを書き換えて、標準出力とテストの結果をすぐに見られる。

### Negative

- 訪問者が、Yaegi が対応しない書き方（`iter`、一部のジェネリック）をすると、手元の Go では通るコードがエラーになる。
- テストの失敗の行が、テストのファイルの行を指さない。
- 性能を測る題材（ベンチマーク）は、インタプリタの実行速度になるので、扱えない。
