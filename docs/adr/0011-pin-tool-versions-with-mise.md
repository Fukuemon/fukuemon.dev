# ADR-0011: ツールのバージョンを mise で固定する

## Status

承認

## Context

agent-harness のスキルとフックは apm で配置し、Git で追跡しない。  
CI の docs のチェックも、apm が配置したスクリプトを呼ぶ。  
apm のバージョンが CI と手元で違うと、配置されるスキルとフックが食い違う。

ADR-0007 は mise を採らないと決め、ADR-0003 は Node.js のバージョンの固定を `vp env` に任せると決めた。  
Vite+ はまだ入れていないので、Node.js のバージョンを固定する手段は決まっていない。  
ADR-0003: [monorepo と Vite+ の採否](0003-monorepo-and-vite-plus.md)  
ADR-0007: [品質のチェックの採否](0007-quality-gates.md)

## Decision

`mise.toml` で apm（`pipx:apm-cli`）と Node.js のバージョンを固定する。  
CI と手元は、同じ `mise.toml` からツールを入れる。

理由は 2 つある。

- agent-harness の apm を、CI と手元で同じバージョンで入れる必要がある。
- ほかのリポジトリと、ツールを入れる手順をそろえる。

この決定は、ADR-0007 のうち mise を採らないとした判断と、ADR-0003 のうち Node.js のバージョンを `vp env` で固定するとした判断を置き換える。  
ADR-0003 と ADR-0007 のほかの判断は変えない。

## Considered Options

| 選択肢                                                         | 強み                                                                                                                    | 弱み                                                     |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| **採用:** `mise.toml` で apm と Node.js のバージョンを固定する | apm と Node.js のバージョンを 1 つのファイルで固定でき、CI と手元が同じバージョンになる。ほかのリポジトリと手順がそろう | Vite+ を入れたときに、`vp env` と役割が重なる            |
| Node.js のバージョンを `vp env` で固定する（ADR-0003）         | Vite+ にバージョンの管理を集約できる                                                                                    | Vite+ はまだ入れておらず、apm のバージョンを固定できない |
| Node.js の下限を `package.json` の `engines` だけで示す        | 新しいツールが要らない                                                                                                  | バージョンを固定せず、apm のバージョンも固定できない     |

## Consequences

### Positive

- CI と手元で、同じバージョンの apm がスキルとフックを配置する。

### Negative

- Vite+ を入れるときは、Node.js のバージョンを `mise.toml` と `vp env` のどちらで持つかを、改めて決める必要がある。
