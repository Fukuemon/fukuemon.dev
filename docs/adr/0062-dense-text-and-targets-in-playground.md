# ADR-0062: コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくする

## Status

承認（テーマ変数に置く compact のトークンを 2 つとした決定と、13px にしてよい文字の範囲を ADR-0067 に置換）

## Context

コードを動かす画面の文字と押せる領域を、原則より小さくするかを決める必要がある。  
コードを動かす画面は、エディタ、ファイルの木、端末、プレビュー、HTTP の流れ、コンソールを、1 つの画面に並べる。  
利用者は、今の画面がコードエディタや DevTools と比べて大きく見え、使い勝手が違うと感じた。

- デザインシステムの原則は、14px より小さい文字を使わず（`TEXT-MIN-SIZE`）、押せる領域を 44×44 CSS px 以上にする（`TARGET-SIZE`）と決めている。
  - ADR-0024: [トークンを、fukuemon.dev の値のプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、生成りの地と旧サイトの差し色で、角丸と影を使わない版面にする](0024-tokens-of-fukuemon-dev.md)
- 角丸、影、筆の線の動きは、操作できる要素と重なる面だけに付ける。
  - ADR-0028: [操作できる要素と重なる面の角を 2px で丸め、重なる面にずらした影を付け、罫を引く動きを筆の線にする](0028-radius-shadow-and-brush-motion.md)
- 同じ記録を出して測った値は、次のとおり。2026-11-13 に、Chromium 156.0.8078.4 の DevTools と、vscode.dev（VS Code のビルドのコミット 6904719。バージョンの番号は確認できなかった）で測った。
  - Chrome の DevTools のコンソールは、文字 11px、1 行 18px、値の木の項目 16px である。
  - VS Code（vscode.dev）は、エクスプローラーの行 22px（文字 13px）、ペインの見出し 28px（文字 11px）で、ペインを 1px の罫で仕切る。
  - 今のコードを動かす画面は、コード 16px（行高 27.2px）、ファイルの木の行 44.8px、タブの帯 44px、ペインの見出し 44px で、ペインの間を 16px 空ける。コンソールの 1 行は 37.8px である。
- WCAG 2.2 は、押せる領域の大きさを AA（2.5.8）で 24×24 CSS px 以上、AAA（2.5.5）で 44×44 CSS px 以上としている。`TARGET-SIZE` は、既に `Link` を例外にし、AA の 24×24 CSS px 以上としている。

## Decision

コードを動かす画面に置くコンポーネントだけ、2 つの原則を緩める。

- 文字は、コードと操作のラベルを 13px、コンソールの値と補足（時刻、出力元、HTTP の流れの通信する者）を 12px まで小さくしてよい。
  - テーマ変数に、`text-compact`（12px）と `text-label-compact`（太字の 13px）を置く。この 2 つは、コードを動かす画面のコンポーネントの外で使わない。
- 押せる領域は、WCAG 2.2 の AA（2.5.8）の 24×24 CSS px 以上にする。木の行と開閉の要約（`Disclosure`）は 24px、ボタン、入力欄、タブは 28〜32px にする。
- 色、罫、墨と生成りの面、角丸、筆の線の動きは変えない（ADR-0024、ADR-0028）。
- コンソール（`ConsoleEntryList`）と、その値の木（`TreeView` の `density="compact"`）から適用する。

理由は次のとおり。

- コードを動かす画面は、多くの行を一度に見比べる画面で、記事の本文と読み方が違う。DevTools とコードエディタに近い密度にすると、記録を見渡しやすくなる。
- 押せる領域は AA（2.5.8）の基準を満たすので、WCAG 2.2 の AA への適合は変わらない。

## Verification

試作の CSS をカタログの story に当てて測った値である。

- コンソールは、同じ記録で行の領域の高さが 849px から約 570px になる。
- コードを動かす画面のほかのコンポーネントも詰めると、画面の高さは 1692px から約 1120px になる。

## Considered Options

| 選択肢                                                                                          | 強み                                                             | 弱み                                                                           |
| ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **採用:** コードを動かす画面だけ、文字を 12px と 13px、押せる領域を 24×24 CSS px まで小さくする | DevTools と VS Code に近い密度になる。木の行とタブの高さも詰まる | 原則の例外が 2 つ増える。押せる領域の基準が、この画面だけ AAA から AA に下がる |
| 原則を守り、文字を 14px にして隙間を 1px の罫にする                                             | 原則を変えずに済む                                               | 木の行、タブ、見出しが 44px のまま残り、画面は大きく見えるままになる           |
| 今のまま                                                                                        | 変更が無い                                                       | 利用者が挙げた違和感が残る                                                     |

## Consequences

### Positive

- コンソールとコードを動かす画面で、一度に見渡せる行が増える。

### Negative

- 12px と 13px の文字は、サイトの中で一番小さい文字になる。コードを動かす画面の外に広げないよう、レビューで見る。
- `TARGET-SIZE` のテストは、コードを動かす画面のコンポーネントでは 24px 以上を確認する形に変わる。
