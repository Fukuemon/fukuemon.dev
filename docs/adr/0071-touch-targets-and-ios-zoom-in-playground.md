# ADR-0071: 指で押す端末では、コードを動かす画面の押せる領域を 44px にし、iOS の入力時の拡大を viewport の指定で止める

## Status

提案

## Context

コードを動かす画面を、スマートフォンと記事の埋め込みで操作しやすくするために、指で押す端末の押せる領域と、エディタの文字の大きさを決める必要がある。

- コードを動かす画面に置くコンポーネントだけ、押せる領域を 24×24 CSS px まで小さくしてよいと決めている。指で押す端末と、マウスで押す端末を分けていない。
  - ADR-0062: [コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくする](0062-dense-text-and-targets-in-playground.md)
- 13px にしてよい文字にコードを含め、等幅の 13px のトークンを `text-code-compact` にすると決めている。
  - ADR-0067: [コードを動かす画面の詰めたペインの文字のトークンを 4 つにし、13px の等幅の行高に DADS に無い値を使う](0067-compact-text-tokens-in-dense-panes.md)
- 今のエディタは、`text-code`（16px）で描いている。端末のプロセスのタブとプレビューのポートのタブは、`density="compact"` が無く、44px の高さの 16px の太字になっている。
- 375px の幅で今の画面を使うと、24px の木の行と 28px のボタンは、指で押し分けにくい。
- iOS の Safari は、16px 未満の文字の入力欄にフォーカスすると、ページを拡大する。
- viewport の指定に `maximum-scale=1` を足すと、iOS 10 からの Safari は、フォーカスしたときの自動の拡大だけを止め、2 本の指で拡大する操作は止めない。Android の Chrome は、2 本の指の拡大も止める。
  - 出典: [Preventing iOS Textbox Auto Zooming and ViewPort Sizing（Rick Strahl's Weblog）](https://weblog.west-wind.com/posts/2023/Apr/17/Preventing-iOS-Textbox-Auto-Zooming-and-ViewPort-Sizing)
- iframe の中の viewport の指定は、外のページの拡大を変えない見込みである（未確認）。

## Decision

指で押す端末だけ押せる領域を 44px に戻し、文字は 13px と 12px のままにする。iOS の拡大は、iOS のときだけ viewport の指定で止める。

- 主な入力が指の端末（`pointer: coarse`）では、コードを動かす画面のボタン、タブ、木の行、入力欄の押せる領域を 44×44 CSS px 以上にする。WCAG 2.2 の AAA（2.5.5）の大きさである。
- マウスで押す端末では、ADR-0062 のとおり 24×24 CSS px 以上のままにする。
- 文字の大きさは、どの端末でも変えない。エディタは `text-code-compact`（13px）にする。押せる領域だけを広げると、行の密度を保ったまま、押し分けやすくなるためである。
- iOS の Safari のときだけ、ページの読み込みの初めに、viewport の指定へ `maximum-scale=1` を足す。Android では足さない。2 本の指の拡大を止めると、拡大して読む利用者が読めなくなるためである。
- 実行環境を埋めた記事のページにも、同じ指定を iOS のときだけ足す。

ADR-0062 の Decision のうち、押せる領域を 24×24 CSS px 以上にする決定を、指で押す端末の分だけ、この ADR が置き換える。

## 承認の条件

- 実機の iPhone の Safari で、エディタ（CodeMirror）と入力欄にフォーカスしても、ページが拡大しないこと。
- 同じ端末で、2 本の指で拡大できること。
- 止まらなければ、指で押す端末だけ、エディタを 16px にする形に、この ADR を書き直す。

## Considered Options

| 選択肢                                                                                                     | 強み                                                 | 弱み                                                                                         |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **採用:** 指で押す端末だけ押せる領域を 44px にし、文字は 13px のまま、iOS の拡大を viewport の指定で止める | 行の密度を保ったまま押し分けやすい。拡大の操作は残る | iOS を見分けるスクリプトを、ページの初めに置く。実機で確認するまで、拡大が止まるか分からない |
| 指で押す端末だけ、エディタを 16px にする                                                                   | 指定を足さずに iOS の拡大が起きない                  | エディタだけ周りの文字より大きくなり、1 行に入る文字が減る                                   |
| viewport の指定を、どの端末にも足す                                                                        | スクリプトが要らない                                 | Android で 2 本の指の拡大が止まる                                                            |
| 押せる領域を 24px のままにする                                                                             | 変更が無い                                           | 375px の幅で、木の行とボタンを押し分けにくい                                                 |

## Consequences

### Positive

- スマートフォンと記事の埋め込みで、木の行、タブ、ボタンを押し分けやすくなる。
- PC の画面の密度は変わらない。

### Negative

- 押せる領域の大きさが、端末の種類で 2 つになる。`TARGET-SIZE` のテストは、両方の大きさを確認する。
- iOS を見分けるスクリプトを、ツールのページと記事のページに置く。
