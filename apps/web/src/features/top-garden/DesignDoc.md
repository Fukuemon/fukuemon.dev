# トップの水墨の門と立体の庭

## Overview

トップ（`/`）の最初の訪問では、署名と水墨の門を筆の順に描き、色を差して立体の庭に移し、カメラが門をくぐる。  
2 回目以降の訪問は、門の内側の庭を、イントロなしで出す。  
庭を出さないときは、画面全体に霞が流れる薄墨の絵を敷く。  
プロフィールの 3 つのセクションは、庭の木の枝に掛けた和紙に置く。

この文書は、コードの構成と、見た目の数値を持つ。  
サイトの全体像は [fukuemon.dev Design Doc](../../../../../docs/design/DesignDoc.md) にある。

- ADR-0026: [トップの最初の訪問で水墨の門を描き、門をくぐった立体の庭にプロフィールを置く](../../../../../docs/adr/0026-sumi-gate-and-garden-on-top.md)
- ADR-0027: [トップの庭の絵を、訪問者の端末の日付と時刻で、季節と時間帯ごとに変える](../../../../../docs/adr/0027-garden-by-season-and-time.md)
- ADR-0082: [トップと記事とプレイグラウンドの一覧の画面全体に、霞が流れる薄墨の絵を CSS の mask で敷く](../../../../../docs/adr/0082-ink-background-as-css-mask.md)

## Design

### コードの構成

`apps/web/src/features/top-garden/` は、墨の絵の SVG を作るコード、立体の庭を three で描くコード、その両方が読む庭の配置、トップのプロフィールの本文を持つ。
墨の絵の SVG を作るモジュールは、`layout.ts` と、`ink/` の `brush.ts`、`ink-art.ts`、`ink-svg.ts`、`ink-trees.ts`、`ink-background.ts` の 6 つである。
どれも React と DOM に依らない TypeScript で書く。
ビルドのときに Node で動く。
`ink/ink-gate-fragment.ts` は、ヘッダーのロゴと同じ `sign.svg` を [`components/sign/`](../../components/sign/README.md) から読む。
`stage/stage.ts` と `scene/garden-entry.ts` は、設定が変わったときのイベントの名前と型、URL の引数の名前を `components/site-settings/settings.ts` から読む。
`stage/season.ts` は、季節と時間帯の値の型を同じファイルから読む。
`stage/stage.ts` の `stageScript` は、`stage/season.ts` と `stage/visit.ts` の関数と `applyStage` を、文字列にしてトップの `head` の inline script に埋め込む。
埋め込んだ関数は、ブラウザで、表示の前に動く。
`readOverride` は、開発のビルドの inline script にだけ埋め込む。

コードは、墨の絵、`head` のスクリプト、立体の場面という関心ごとで、3 つのディレクトリに分ける。
それぞれ、動く場所と制約が違う。
墨の絵と場面の両方が読む `layout.ts`、`rng.ts`、`intro-timing.ts` は、このディレクトリの直下に置く。
`Profile.astro` は、3 つのどれにも当たらないので、直下に置く。
ディレクトリの間の import は、`scene/` から `stage/` へは型だけ、`stage/` から `scene/` へは場面のバンドルの URL（`?worker&url`）だけにする。
`ink/` と `scene/` は、互いを import しない。
`stage/` から `ink/` へは、墨の絵と署名のファイルの URL（`?worker&url`）だけを import する。`ink/` から `stage/` へは、何も import しない。
この 5 つの向きは、`oxlint.config.ts` の `no-restricted-imports` が止める。
`pnpm run lint` が、向きに反する import で失敗する。
`stage/` から `scene/` へは、`?worker&url` 以外の接尾辞と、接尾辞の無い import を止める。
`scene/` から `stage/` へは、`import type` だけを通す。
`import { type X }` の形は、Oxlint が通すので、`import type` を使う。
`../stage/../scene` のように、途中で戻るパスと、直下のファイルを通った間接の import は、止めない。

### 同じシードから同じ絵ができる

同じシードからは、同じ線のデータと、同じ SVG の文字列ができる。
乱数を使う順は、`ink/brush.ts` の呼び出しの順で決まる。
線を足すか、消すか、並べ替えると、それより後の線がすべて変わる。

墨の絵の 281 本の線の後ろに、`ink/ink-trees.ts` が、塀の向こうと門の奥の木の線を足す。
木の線は、281 本の線より後に乱数を使うので、281 本の線を変えない。
出力は、線が 399 本、`path` が 543 本である。
`path` の `d` は、座標を 0.1 の単位に丸め、2 点目以降を相対座標のコマンド（`l`）で書く。
相対座標で書くと、最初の訪問で読み込むファイルの転送量が減るためである。
SVG のサイズの上限は gzip で 28 KiB で、署名を足した墨の絵と署名のファイル全体の上限は gzip で 36 KiB である。背景の mask の SVG の上限は gzip で 30 KiB である。どれもユニットテストが確認する。

### イントロの各段の時間

最初の訪問は、開いてから約 10.1 秒で終わる。  
署名を出さないときは、署名の段がなくなり、墨の絵から後ろの段が 0.6 秒早まる。

| 時刻         | 動き                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| 0.2〜1.7 秒  | 左下に、筆記体の「Fukuemon」の署名を、左から書く                                                     |
| 0.6〜5.6 秒  | 紙の上に、山並み、塀、門、飛び石、石、近景の松、塀の向こうと門の奥の木の順で、墨の線を筆の順に描く   |
| 5.6〜7.1 秒  | 墨の線の下に立体の庭の絵を出し、墨だけの絵から淡い色へ移す                                           |
| 6.9〜9.7 秒  | 墨の線と署名を消し、カメラが門をくぐる。近景の松の枝は、頭上へ抜ける                                 |
| 9.3〜10.1 秒 | 門の内側の、松の枝に掛けた和紙の前で止まり、プロフィールの文を出す。ヘッダーと、庭の中のボタンを出す |

- 色を差し始めるのは、墨の絵を描き終える時刻と、場面の準備が終わる時刻の、遅いほうである。
  - 墨の絵を描き終える時刻は、開いてからの時刻で決めず、墨の線と署名の CSS の遷移が終わった時刻にする。遷移は、墨の絵と署名を挿入した時点（`ink-ready`）から動くので、ファイルが遅く届くと、その分だけ後ろにずれるためである。
  - 遷移を取れなかったときに早く色が差さないよう、`ink-ready` から 5.6 秒より前には色を差さない。
  - 松の円の不透明度の遷移は、墨の線より後に終わるので待たない。色が差した後も、松の円は現れ続ける。
- 墨の門、塀、飛び石、石、木の線は、立体の配置を最初のカメラで投影した位置に描く。色が差すときに、線と立体がずれないためである。
  - 木の線は、立体の木と同じ幹と枝の形から作る。
    奥の木から手前の木へ、1 本ごとに幹、枝、葉の順で描く。
    塀、門の梁、屋根に隠れる部分は描かない。
    隠れる部分で切った後に 24px より短く残る区間は、点のように見えるので描かない。
- 墨の線は、SVG の `path` の `stroke-dashoffset` を CSS の遷移で動かして描く。
- 左下の署名は、イントロの間だけ出す。
- 文を出す時刻とカメラが止まる時刻は、色を差し始めた時刻からタイマーで決める。描くのが遅い端末でも、決めた長さで終わるためである。
- 文を出してからイントロを終えるまで（色を差し始めてから 3.7〜4.5 秒）に、庭の中のボタンか矢印キーで別の和紙へ移ると、カメラは 4.5 秒まで門をくぐる動きのまま進み、その後に移った先の和紙へ動く。
- 「スキップ」のボタン、Esc、Tab では、カメラを動かさずに、門の内側の最後の状態にする。
  - 「スキップ」は、押したボタンが消えるので、プロフィールの見出しへフォーカスを移す。
  - Tab は、ブラウザのデフォルトの動作を止めず、最後の状態でそのまま次の要素へフォーカスを移す。Esc は、フォーカスを動かさない。
  - 場面の準備ができるまでは、最後の状態を描けないので、「スキップ」のボタンを出さず、Esc と Tab を受けない。

### 墨の絵と署名の置き方

墨の絵は、設計の画面（1600 × 900）の座標で描いた SVG で、絵を置く枠の中央に置く。
絵の幅は、枠の縦横比で変える。
`cqw` と `cqh` は、枠の幅と高さの 1% である。

| 枠の縦横比                | 絵の幅                            |
| ------------------------- | --------------------------------- |
| 16:9 より横長             | 枠の幅（`100cqw`）                |
| 16:9 から正方形の手前まで | 枠の高さの 16/9 倍（`177.78cqh`） |
| 正方形か、正方形より縦長  | 枠の幅の 1.25 倍（`125cqw`）      |

- 墨の線: 色は `--fd-color-text` である。遠景の山並みはにじませ、中景と近景の線はかすれさせる。
- 松の円: 色は `--fd-color-primary` で、不透明度は 0.2 である。
- 署名: 色は `--fd-color-text` である。枠の左から `5cqw`、下から `4cqh` に置き、幅は `clamp(11rem, 24cqw, 24rem)` にし、反時計回りに 5 度回す。

墨の絵と署名の色と長さは、`InkGate.astro` の `<style>` に、セマンティックトークンと値を直に書く。
デザインシステムの規則（色はテーマ変数のユーティリティで書く）の例外である。
SVG を、ビルドのときに作った文字列として挿入するので、SVG の中の `path` にユーティリティを付けられないためである。

イントロの遷移とアニメーションの時間とイージングも、`InkGate.astro` と `GardenStage.astro` の `<style>` に値を直に書く。
デザインシステムの規則（動きはテーマ変数のユーティリティで書く）の例外である。
値はこの文書の「イントロの各段の時間」の時刻に合わせたイントロだけのもので、ほかの画面では使わないためである。

### 庭を出さないときの背景

庭を出さないときのトップと、記事の一覧とプレイグラウンドの一覧には、`components/ink-background/InkBackground.astro` が、画面全体に固定した背景を本文の後ろに敷く。
3 つのページは、`SiteLayout` の prop `inkBackground` で背景を置く。
2 つの一覧のページには `stage-on` が付かないので、ハイコントラストのときを除いて背景を出す。
ADR-0082 で決めた。

- ADR-0082: [トップと記事とプレイグラウンドの一覧の画面全体に、霞が流れる薄墨の絵を CSS の mask で敷く](../../../../../docs/adr/0082-ink-background-as-css-mask.md)

- 絵: `components/ink-background/ink-background.svg` を、CSS の `mask-image` で背景の要素に掛け、`--fd-color-text` で塗る。枠を覆うように中央に置く（`cover`）。背景の高さは `100lvh` に固定し、スマートフォンのアドレスバーが伸び縮みしても、絵を描き直さない。
- 濃さ: 16%（`opacity: 0.16`）にする。3 つのページの文字の色（本文、補足、リンク）が、ライトとダークで 4.5:1 以上を保つ。最も低いのは、ライトのリンクの色の 4.71:1 である。文字の色のトークンを変えたときは、コントラストを測り直す。
- ヘッダー: 背景を出すページ（`html[data-ink-background]`）では、`SiteLayout` の CSS が、ヘッダー（`[data-site-header]`）に紙の色の背景を敷き、絵をヘッダーの下の罫より下にだけ見せる。絵をロゴと罫に重ねないためで、ヘッダーが折り返して高くなっても隠れる。
- 霞: 紙の色（`--fd-color-surface`）の放射状グラデーション（`radial-gradient`）を 3 つ重ね、左右に 20vw ずつ往復させる。1 つ目と 3 つ目は 48 秒、2 つ目は 64 秒で逆向きに動く。
- ページの背景の色: 背景を出すページ（`html[data-ink-background]`）で庭を出さないときは、`SiteLayout` の CSS が、ページの背景の色を `body` から `html` に移し、`body` を透明にする。墨の絵を本文の後ろに出すためである。
- 一覧の本文: 2 つの一覧のページは、本文を `InkVeil.astro` で包み、本文の後ろに紙の色を、ライトで 60%、ダークで 42% 敷く。上端の 2rem と下端の 5rem では、紙の色を透明から徐々に濃くする。絵の横の線が、罫と文字の後ろに濃く重ならないためである。

背景は、次のときに出し方を変える。

| 条件                                                                                                                             | 背景                       |
| -------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 庭を出す（`html.stage-on`）                                                                                                      | 出さない。SVG も取得しない |
| `html` の `data-motion` が `on`                                                                                                  | 霞が流れる                 |
| `data-motion` が `off`（表示の設定でアニメーションをオフにしたとき、表示の設定を保存せずに OS で動きを減らす設定にしているとき） | 止まった絵                 |
| JavaScript が動かない（`data-motion` が付かない）                                                                                | 止まった絵                 |
| `mask-image` に対応しない                                                                                                        | 絵を塗らない。霞だけが残る |
| ハイコントラスト（`forced-colors: active`）                                                                                      | 出さない                   |

背景の濃さと、霞の大きさと時間は、`InkBackground.astro` の `<style>` に値を直に書く。
一覧の本文の後ろの紙の色の濃さは、`InkVeil.astro` の `<style>` に値を直に書く。
デザインシステムの規則の `COLOR-TOKEN` と `MOTION-TOKEN` の例外にする。
値はこの背景だけのもので、ほかの画面では使わないためである。
霞は止まらずに繰り返し、位置が動くので、繰り返す動きを処理中の印だけにする規則、5 秒を超える動きを止める規則、位置を動かさない規則の例外にもする。
霞は `html[data-motion="on"]` のセレクタの中でだけ動かす。JavaScript が動かないときに霞を止めるためで、画面のコードに設定ごとの条件を書かない `MOTION-REDUCE` の規則の例外にする。
表示の設定のアニメーションのスイッチをオフにすると、霞はほかの動きと一緒に止まる。

### 季節と時間帯の決め方

`head` のスクリプトが、ページを開いた時点の端末の日付と時刻で、季節と時間帯を決める。

| 季節           | 月       |
| -------------- | -------- |
| 春（`spring`） | 3〜5 月  |
| 夏（`summer`） | 6〜8 月  |
| 秋（`autumn`） | 9〜11 月 |
| 冬（`winter`） | 12〜2 月 |

| 時間帯          | 時刻      |
| --------------- | --------- |
| 朝（`morning`） | 5〜10 時  |
| 昼（`day`）     | 10〜16 時 |
| 夕（`evening`） | 16〜19 時 |
| 夜（`night`）   | 19〜5 時  |

- 境目の時刻は、後ろの時間帯に入る。10 時は昼、19 時は夜になる。
- 場面の色は、時間帯で決める。紙と墨の色（イントロの墨の絵、端の余白、色が差す前の「スキップ」のボタン）は、テーマで決める。
- 開いたまま OS のテーマが変わったら、紙と墨の色をトークンから読み直し、庭を描き直す。場面の色は変えない。
- 夜の場面の端の余白だけは、テーマの紙の色を使わず、夜の `mist` の色にする。

### 和紙の文

文は DOM のまま、three の CSS3DRenderer で 3D に置く。  
庭の場面の 1 m は、文の 260px に当たる。  
文の要素を 1/260 に縮めると、iOS の Safari が、文を立体の和紙の面からずらして描く。  
そのため、文を置く場面は px の単位で組み、文の要素の倍率を 1 にする。  
文を描画するカメラには、庭のカメラの位置を 260 倍した値を設定し、向きと投影行列は庭のカメラと同じにする。  
CSS3DRenderer が文を置く要素（`.garden-cards`）は、`overflow: clip` にしてスクロールさせない。  
和紙の文の summary がフォーカスを受けたときやクリックされたときに、ブラウザがこの要素をスクロールし、文だけが立体の和紙からずれるためである。

| 項目           | 画面の幅が 768px 以上のとき | 768px より狭いとき |
| -------------- | --------------------------- | ------------------ |
| 文の幅         | 25rem                       | 17.5rem            |
| 字の大きさ     | 1rem                        | 1rem               |
| 行間           | 1.9                         | 1.8                |
| 見出しの大きさ | 1.5rem                      | 1.5rem             |

- 見出しは、下に 0.625rem の余白をとって、字の色を 35% にした罫を引き、罫の下を 1rem あける。
- 段落の間は、1rem あける。経歴の詳細の段落の間は、0.5rem あける。
- 経歴の行は、上下に 0.625rem の余白をとり、字の色を 25% にした罫で区切る。
- 経歴の年は、字の大きさを本文と同じ 1rem にし、字の色を 70% にして本文と分ける。
  和紙は画面に縮んで映るので、14px の字は 14px より小さく映るためである。
  字の大きさの下限は、[packages/ui の DESIGN.md](../../../../../packages/ui/DESIGN.md) の `TEXT-MIN-SIZE` にある。
- カメラは、和紙の文の高さが画面の高さの 65% に収まる距離か、和紙の幅が画面の幅に収まる距離のうち、遠いほうから和紙を見る。
  - 375×667、375×812、390×844、1280×720、1366×650、1366×768、1440×900 では、どの和紙も、経歴の行を開いても、字が 14px 以上で映る。
  - 320×568 と 360×800 では、和紙の幅で距離が決まり、字は 12.0px と 13.6px で映る。375×548 では、高い和紙の字が 11.6px で映る。
  - 65% にするのは、これより上げると、375×548 で和紙の文の下端が庭の中のボタンに重なるためである。
- プロフィールの肩書きと活動は、行ごとに 0.25rem あけて並べ、行の中の折り返しと行の区切りを見分けられるようにする。庭では、字の色を本文と同じにする。
  - 活動は、団体の名前だけを書き、団体の公式のページへのリンクにする。団体の中の役職（organizer、TA など）は書かない。
- 経歴の行の題は、庭では本文と同じ書体の太字（700）にする。庭では年と題が同じ大きさで映り、年の数字のほうが目立つためである。
- 語の途中で折り返さないようにする `word-break: auto-phrase` は、summary、肩書きと活動の行、短い段落だけに当てる。経歴の詳細の段落は、行の終わりが不揃いになるので当てない。
- 押せる領域は、和紙に縮んで映っても、幅 320px の画面で 44px 以上で映る大きさにする。
  - プロフィールの GitHub と X のリンクは、押せる領域を 60px 四方にし、-0.5rem の margin を付けて、並びの中で占める大きさを 44px 四方にする。リンクの間は 1rem あけ、押せる領域を重ねない。
  - 活動のリンクは、押せる領域の高さを 60px にし、上下に -0.5rem の margin を付けて、並びの中で占める高さを 44px にする。庭ではリンクどうしの間を 1rem あけ、押せる領域を重ねない。
  - 経歴の行の summary は、上下に 0.25rem の padding と -0.25rem の margin を付け、和紙の高さを変えずに押せる領域を広げる。
- プロフィールの GitHub と X のリンクは、アイコンだけで示し、読み上げの名前を「GitHub」と「X」にする。
  - アイコンの色は、ふつうのページでも庭でも字の色にし、外部のリンクの色（藍）にしない。アイコンだけのリンクは、ヘッダーのナビのリンクと同じく、色でリンクを示さない。
  - 記事の本文の外部のリンクと同じく、`target` を付けず、同じタブで開く。新しいタブで開く `packages/ui` の `Link` の外部の変種は使わない。
  - アイコンの左端を文の左端に揃えるよう、並びに -0.625rem の margin を付ける。押せる領域とフォーカスの輪は、文の左端より外に出る。
  - アイコンだけのリンクは 2 つだけなので、`packages/ui` のコンポーネントにせず、画面のコードで組む。
- プロフィールの活動のリンクは、下線でリンクと示し、hover で記事の本文のリンクと同じく下線の下に罫を引く。
  - 字の色は、ふつうのページでは外部のリンクの色（藍）にし、庭では和紙の字の色にする。和紙の中にテーマの色を入れないためである。
  - GitHub と X のリンクと同じく、`target` を付けず、同じタブで開き、`packages/ui` の `Link` を使わない。
  - ふつうのページでは、押せる領域の高さを 44px にする。

  文の幅は、768px をまたいだときだけ変わるためである。
- 経歴の行は、年と題だけを見せ、詳細は `<details>` で閉じておく。
  - 経歴の行の `<details>` に同じ `name` を付け、開ける詳細を 1 つだけにする。

    和紙が閉じたときより高くなると、カメラが和紙を画面に収めようと引き、字が 14px より小さく映るためである。
  - ふつうのページでは、詳細を開いても、ほかの行を出したままにする。
  - 詳細を開閉したときは、その和紙だけをセクションの大きさから測り直して掛け直す。
    カメラは、掛け直した和紙の高さで寄り直す。

### 庭の中のボタンの並び

庭の中のボタンは、画面の下に固定する。  
画面の端から、幅が 768px 以上のときは 1.25rem、768px より狭いときは 0.5rem 離す。

- 3 つの文へ移るボタンは、隣どうしの境の線を 1 本にしてつなぐ。
  - ボタンは、霞の色の面に、時間帯の枠の色（`garden-edge-day`、`garden-edge-night`）の枠を付ける。
  - 3 つのボタンで 1 つのボタングループにするので、最初のボタンの左の 2 つの角と、最後のボタンの右の 2 つの角だけを丸め（`band`）、ボタンの間に角を出さない。
  - ボタンの枠の内側に、ステッチ（枠線の内側の破線）を引く。今いる場所のボタンの破線は、字の色の濃度 70% にする。枠線、ステッチ、今いる場所の反転は、`band` が描く。
  - 今いる場所のボタンは、背景と字の色を反転する。
- 3 つの文へ移るボタンは、下の中央に並べる。
- アニメーションと庭の表示の切り替えは、サイトのヘッダーの歯車から開く設定の面に置く。
- ボタンの字は、操作の字の `text-label`（16px）である。
- 3 つの文へ移るボタンの左右の余白は、幅が 768px 以上のときは 1rem、768px より狭いときは 0.5rem にし、幅と高さを 44px 以上にする。狭いときの 0.5rem は、ステッチと字の間を空けるためである。
- 3 つの文へ移るボタンは、幅 320px の画面でも 1 行に並ぶ。
  - 字は 16px のままにする（`TEXT-MIN-SIZE`）。
- 3 つの文へ移るボタンの枠は 4 辺に付け、隣のボタンと 1px 重ねる。
  - 今いる場所のボタンの枠は、隣の枠より手前に出す。
- イントロの間は、場面の準備ができてから文を出すまで、「スキップ」のボタンだけを右下に出す。
  - ボタンは、面に枠を付け、角を `rounded-control` で丸め、枠の内側にステッチを引く。
  - 面と枠と字は、色が差す前はテーマの紙と墨の色にし、色が差した後は、庭の中のボタンと同じく時間帯の色にする。
  - 色は、`transition-colors` で 150ms かけて替える。
  - 画面の端からの距離は、庭の中のボタンと同じにする。

### ヘッダーと霞

庭を出している間、サイトのヘッダーは、背景を透明にし、下の罫を消して、画面の上端に重ねる。  
字が場面の色に重なって読みにくくならないよう、画面の上端と下端に霞を敷き、ヘッダーのロゴとリンク、庭の中の字のボタンを霞の上に置く。  
ヘッダーは、`stage-on` が付いた時点で文書の流れの外に置き、庭を描くまでは庭の面の下に隠す。  
庭を描いた時点で外すと、本文が上へずれ、CLS に数えられるためである。  
庭を描けずに `stage-on` を外したときは、ヘッダーが文書の流れに戻り、本文がヘッダーの高さだけ下がる。

霞の高さと、霞の色で塗りつぶす範囲は次のとおり。

| 霞   | 高さ                                                   | 霞の色で塗りつぶす範囲 |
| ---- | ------------------------------------------------------ | ---------------------- |
| 上端 | 6.5rem                                                 | 上から 65%             |
| 下端 | 768px 以上のときは 6.5rem、768px より狭いときは 8.5rem | 下から 65%             |

- 残りの範囲は、霞の色から透明へ、縦の線形のグラデーションで薄くする。
- 面を持たない字と印（ヘッダーのロゴとリンクと歯車）は、霞の色で塗りつぶす範囲に収める。
  3 つの文へ移るボタンは、霞の色の面を持つので、範囲から出てもよい。
- 768px より狭いときは、庭を出している間だけ、ヘッダーのロゴの高さを 1.5rem にする。
  幅 320px でも、ロゴと 2 つのリンクと歯車を 1 段に収めるためである。
  左右の余白と、ロゴとリンクの間とリンクどうしの間は、庭に依らず、[全体の Design Doc の「表示の設定」](../../../../../docs/design/DesignDoc.md#表示の設定) の値を使う。
- 霞、字、ボタンの枠、フォーカスの輪の色は、和紙と同じく時間帯で決め、テーマに依らない。
  - ヘッダーの歯車にポインタを重ねたときの面も、霞の色にする。テーマの面の色が霞の上に出て、印が見えなくなるのを防ぐためである。
  - 歯車で開く設定の面は、ヘッダーの外に置き、テーマの色で出す。
    どれもセマンティックトークンで、組はコントラストのチェック（`pnpm run check:contrast`）が確認する。

| 時間帯     | 霞の色              | 字とフォーカスの輪の色 | ボタンの枠の色      |
| ---------- | ------------------- | ---------------------- | ------------------- |
| 朝、昼、夕 | `garden-mist-day`   | `garden-ink-day`       | `garden-edge-day`   |
| 夜         | `garden-mist-night` | `garden-ink-night`     | `garden-edge-night` |

- 庭を出している間は、ヘッダー、庭の中のボタン、霞の範囲で、`surface`、`text`、`border-field`、`focus` をこの表の色に差し替える。
  イントロで色が差した後は、「スキップ」のボタンの範囲でも差し替える。
  ヘッダーとボタンのコードは、テーマの色の名前のまま書く。
- 最初の訪問のイントロの間（文を出すまで）は、ヘッダーと、和紙の文のリンクと経歴の詳細の summary を `visibility: hidden` にし、Tab のキーの順から外す。墨の絵の下に隠れた要素に、フォーカスが移らないためである。和紙の文の h1 は、読み上げから隠さない。

## Interface

### ページが持つ状態

`head` のスクリプトは、次の値を書く。

| 置き場                          | 値                                     |
| ------------------------------- | -------------------------------------- |
| `html` の `data-season`         | `spring`、`summer`、`autumn`、`winter` |
| `html` の `data-time`           | `morning`、`day`、`evening`、`night`   |
| `html` の class `stage-on`      | 庭を出す                               |
| `html` の class `intro`         | イントロを出す                         |
| `localStorage` の `fd-top-seen` | 端末でトップを開いたことがある         |

- `data-season` と `data-time` は、表示の設定で選んだ値（`html` の `data-season-setting` と `data-time-setting`）から決める。
  - 開発のビルドの URL の引数 `season` と `time`、選んだ値、端末の日付と時刻の順に優先する。
    選んだ値が `auto` のときは、端末の日付と時刻を使う。
- 庭の表示の設定（`html` の `data-garden`）が `off` のときは、`stage-on` を付けず、場面のバンドルを読み込まない。
  - 設定の属性は、全てのページの `head` の inline script が、このスクリプトより先に書く。値の決め方は、[全体の Design Doc の「表示の設定」](../../../../../docs/design/DesignDoc.md#表示の設定) にある。
- アニメーションの設定（`html` の `data-motion`）が `off` のときは、最初の訪問でも `intro` を付けず、庭だけを出す。
- URL に引数 `intro` があるときは、2 回目以降の訪問でも `intro` を付ける。設定の面の「イントロをもう一度見る」が、この URL でトップを開く。
  - 引数は、読んだ後に `history.replaceState` で URL から消す。読み込み直したときに、イントロをまた流さないためである。
- `localStorage` を読めないか書けない端末では、最初の訪問かを判定できないので、`intro` を付けず、庭だけを出す。
- `fd-top-seen` は、庭を出すかにかかわらず、ページを開いた時点で書く。
- 場面のバンドルの読み込みに失敗したら、`stage-on` と `intro` を外し、ふつうのページにする。書いた `fd-top-seen` は消さない。
- イントロを出すとき（上の条件で `intro` を付けたとき）は、場面のバンドルと並べて、墨の絵と署名のファイル（`ink/ink-gate-entry.ts` のバンドル）を読み込む。イントロを出さない訪問では、読み込まない。HTML にも、墨の絵と署名の SVG を入れない。
  - ファイルは、`.ink-gate` に墨の絵と署名を挿入して `ink-ready` を書く。`intro` が外れた後に届いたときは、何もしない。
  - 読み込みに失敗したときは、`intro` が残っていれば `ink-failed` を書く。`intro` が外れた後は、書かない。場面のバンドルが `ink-failed` を読み、庭を止めて、ふつうのページに戻す。
- WebGL を使えない端末でも、読み込みに失敗したときと同じく、`stage-on` と `intro` を外し、ふつうのページにする。
- ページを開いてから 6 秒たった時点で、場面のバンドルが `scene-ready` を書いていなければ、`stage-on` と `intro` を外し、ふつうのページにする。通信が応答を返さずに止まると、読み込みの失敗が届かないためである。この判定は、2 回目以降の訪問でも行う。
  - イントロを出すときは、`scene-ready` を書いていても、`intro` が残っていて `ink-ready` を書いていなければ、`ink-failed` を書く。場面を動かした後のクリーンアップは、場面のバンドルが持つためである。
  - 6 秒の時点で場面を組み立てている途中なら、組み立て終えてから判定する。組み立ては同期の処理でメインスレッドを占め、その間はタイマーの関数が動かないためである。

場面のバンドルは、庭を描き始めた後に、次の値を書く。

| 書く先                                              | 値                                         |
| --------------------------------------------------- | ------------------------------------------ |
| `html` の class `scene-ready`                       | 場面を組み立て、最初の 1 枚を描いた        |
| `html` の class `enter`                             | イントロで、色を差して門をくぐる間         |
| `html` の class `garden-ready`                      | 庭を描き、和紙と庭の中のボタンを出せる     |
| `html` の class `no-anim`                           | イントロをスキップした直後で、遷移を止める |
| `html` の CSS 変数 `--scene-paper`、`--scene-text`  | 和紙の背景と字の色（時間帯の場面の色）     |
| `html` の CSS 変数 `--scene-pad-x`、`--scene-pad-y` | 和紙の、文の外の左右と上下の余白           |
| セクションの class `is-current`                     | 今いる場所の文                             |

- イントロを出すときは、`garden-ready` を、文を出す時刻（9.3 秒）に書き、カメラが止まる時刻（10.1 秒）に `intro` と `enter` を外す。
  墨の絵と署名のファイル（`ink/ink-gate-entry.ts`）と `head` のスクリプトは、次の値を書く。

| 書く先                       | 値                                                                                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `html` の class `ink-ready`  | 墨の絵と署名を挿入した（墨の絵と署名のファイルが書く）。`performance.mark` の `ink-ready` も書く                                                         |
| `html` の class `ink-failed` | `intro` があるうちに、読み込みに失敗した、または 6 秒の後に届いていない（`head` のスクリプトが書く）。`intro` が外れた後に届いたファイルは、何も書かない |

- 場面を組み立てた時刻、色を差し始めた時刻、イントロを終えた時刻を、`performance.mark` の `garden-scene-ready`、`garden-enter`、`garden-intro-done` で記録する。E2E が、イントロの段の時刻を確認するために読む。
- 設定の面で庭の表示をオフにしたときと、描く途中の例外か WebGL のコンテキストの喪失で描けなくなったときは、この値をすべて外し、セクションを元の場所に戻し、`stage-on` と `intro` を外す。
  - 庭の表示をオフにしたときは、フォーカスを設定の面に残す。
- アニメーションの設定が `off` の間は、カメラを動かさずに行き先へ切り替え、ポインタに合わせて揺らさない。設定の面で切り替えたときは、開いている庭にすぐ当てる。
- 庭を出していないトップで庭の表示をオンにしたときは、ページを読み込み直して庭を出す。庭を出すかは、描く前の `head` のスクリプトが決めるためである。
- 場面のバンドルを読み込む間に庭の表示をオフにしたときは、場面は庭を立ち上げず、ふつうのページに戻す。場面は、起動のときに `data-garden` を読む。

### 場面のバンドル

場面のバンドルは、three と場面のモジュールを 1 つにまとめた JavaScript のファイルである。
トップの `head` の inline script が、庭を出すときだけ、module の script で読み込む。

- バンドルの大きさの上限は、gzip で 160 KB（160,000 バイト）である。
  - ビルドの後に `pnpm run check:garden-bundle` が確認する。
- バンドルは、ビルドのときに Vite が IIFE の 1 ファイルにまとめ、ファイル名にハッシュを付けて `/_astro/` に置く。
  - 開発サーバーはバンドルを ES モジュールのまま配るので、どちらでも動く module の script で読み込む。
- 場面の色は、デザインシステムのトークンの対象の外である（[デザインシステムの Design Doc の Scope](../../../../../packages/ui/DesignDoc.md#scope)）。
