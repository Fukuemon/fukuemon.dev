# デザインシステム（packages/ui）

## Overview

`packages/ui`（`@fukuemon/ui`）は、fukuemon.dev の画面が使うトークンとコンポーネントを持つ。  
記事の画面と、コードを動かす画面（エディタ、ファイルのツリー、端末、プレビュー、HTTP の流れ）を、同じトークンとコンポーネントで組む。  
値は fukuemon.dev が決め、アクセシビリティ、タイポグラフィ、配色、レイアウトの指標と参考に、デジタル庁デザインシステム（DADS）を使う。  
トークンの層とコンポーネントの分け方は、buddy の `packages/ui` と同じ形にする。

- 出典: [デジタル庁デザインシステム](https://design.digital.go.jp/dads/)
- ADR-0024: [トークンを、fukuemon.dev の値のプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、生成りの地と旧サイトの差し色で、角丸と影を使わない版面にする](../../docs/adr/0024-tokens-of-fukuemon-dev.md)
- ADR-0021: [packages/ui に Base と Case の React のコンポーネントを置き、packages/ui の Storybook をカタログにする](../../docs/adr/0021-ui-components-and-catalog.md)
- ADR-0028: [操作できる要素と重なる面の角を 2px で丸め、重なる面にずらした影を付け、罫を引く動きを筆の線にする](../../docs/adr/0028-radius-shadow-and-brush-motion.md)

## Scope

持つものは次のとおり。

- プリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層
- ライトとダークのテーマ
- 文字、余白、角丸、影、ブレークポイント、動きの段
- コードの色（記事のコードブロック、エディタ、端末）と、HTTP の流れの色
- ドメインを持たない Base と Case のコンポーネント
- Storybook のカタログ
- デザインシステムの文書（`DESIGN.md` と `design/` の 3 つの文書）

持たないものは次のとおり。

- Domain のコンポーネント。サイトの帯と記事の一覧の行は `apps/web` の `features/<機能>/` に、プレイグラウンドの画面の配置は `apps/playground/src/` の関心ごとのディレクトリに置く。
- エディタと端末のエンジン（CodeMirror、xterm.js など）の選択と結び付け。プレイグラウンドの要求の prototype で決める。`packages/ui` は枠とテーマだけを持つ。
- 記事の Markdown の描画と、Mermaid の図の SVG への変換。サイトの基盤の要求で扱う。
- 縦組み。

## Design

### トークンの層

トークンを 3 つの層に分ける。  
画面とコンポーネントは、テーマ変数のユーティリティだけを書く。

| 層                     | ファイル                                                  | 持つもの                                                                                                       |
| ---------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| プリミティブトークン   | `src/tokens/primitive.css`                                | fukuemon.dev の値。色の階調、書体、文字の大きさ、行高                                                          |
| セマンティックトークン | `src/tokens/semantic.css`、`src/tokens/semantic-dark.css` | 役割の名前。プリミティブトークンを参照し、テーマごとに参照先を替える                                           |
| テーマ変数             | `src/tokens/theme.css`                                    | Tailwind CSS のユーティリティの名前。Tailwind のデフォルトの色、文字の大きさ、角丸、影、ブレークポイントを消す |

- 接頭辞は、プリミティブトークンを `--fd-primitive-`、セマンティックトークンを `--fd-color-` にする。
- テーマ変数にないクラスと、任意の値のクラス（`bg-[#fff]` など）は、lint（oxlint の JS プラグインの eslint-plugin-better-tailwindcss）がエラーにする。Tailwind のデフォルトを消しただけでは、テーマ変数にないクラスは CSS を出さないだけでビルドが通るためである。
- プリミティブトークンは、セマンティックトークンとテーマ変数が参照する値だけを持つ。地と罫と差し色は旧サイトの値で、フォーカスの色、書体の太さ、文字の大きさ、行高は DADS 2.1.0 の値である。
- セマンティックトークンの種類は、面、文字、枠、操作、フォーカス、状態、区別、コード、挿絵の 9 つにする。
  - 状態は、エラー、注意、成功、情報の 4 つにする。文字の色と、同じ系統の薄い面を組にする。
  - コードの種類は、下の「コードの色」にある。
  - 挿絵の種類は、色ではなく、挿絵の層（遠景、中景、近景、月）の不透明度を持つ（`--fd-art-*`）。挿絵は文字と面の色だけで塗り、濃さをこの値で決める。ライトは近景ほど濃く、ダークは近景ほど面の色に近い。

### テーマ

ライトとダークのテーマは、セマンティックトークンの参照先を替えて作る。  
プリミティブトークンとテーマ変数のファイルは、テーマごとに分けない。

- ライトの値は `semantic.css` の `:root` に、ダークの値は `semantic-dark.css` に置く。`semantic-dark.css` は、`@media (prefers-color-scheme: dark)` の `:root:not([data-theme="light"])` で参照先を替える。
  - ダークの値を別のファイルに置くのは、コントラストのチェックが、ライトの値だけのファイルと、ダークのブロックを分けて読むためである。
- 訪問者は、OS の設定でテーマを選ぶ。サイトの中にテーマの切り替えを置かない。
- Storybook は、ツールバーでテーマを切り替える。`[data-theme="dark"]` にもダークの値を当て、`[data-theme="light"]` では OS の設定がダークでもライトの値にする。Storybook だけがこの属性を使う。
  - ツールバーのデフォルトは「OS の設定」にし、サイトと同じく OS の設定に従って描く。
- コントラストのチェックは、ライトとダークの条件ごとに流す。

### 色

地は生成り、文字は墨、罫は温かい灰にする。  
差し色は、くすんだ緑、藍、錆の 3 つにする。主の色（`primary`）と内部のリンクはくすんだ緑、外部のリンク（`link-external`）は藍、目次の現在地とサイトのヘッダーのナビの今いるページ（`current-page`）は錆にする。訪問済みのリンクは、色で分けない。  
状態の色は、DADS の色相のとおり、成功を緑、エラーを赤に当て、注意を錆、情報を藍にする。どの値も、生成りの地の上で選ぶ。

- 出典: [DADS の色](https://design.digital.go.jp/dads/foundations/color/)
- ADR-0024: [トークンを、fukuemon.dev の値のプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、生成りの地と旧サイトの差し色で、角丸と影を使わない版面にする](../../docs/adr/0024-tokens-of-fukuemon-dev.md)

文字と面の組は、WCAG 2.2 の AA を満たす。  
文字は 4.5:1 以上、入力欄と押せるものの枠とフォーカスの表示は 3:1 以上にする。

### 文字

書体は、本文に Noto Sans JP の 400 と 700、記事の題と見出しに Zen Old Mincho の 600、等幅に Noto Sans Mono を使う。  
書体は Fontsource で self-host し、外部の CDN から読まない。

- Zen Old Mincho は、ビルドで見出しに使う字だけのファイルにする。
- 等幅の和文の字は、BIZ UDGothic の 400 と 700 で受ける。M PLUS 1 Code と比べて、見出しの字に絞ったときのファイルが小さく（400 字で約 70 KB と約 150 KB）、Fontsource に静的なウェイトがあるためである。
- 見出しの明朝のウェイトは、テーマ変数の `font-semibold`（600）で書く。
- どの書体も `font-display: swap` にし、和文の分割は preload しない。
- ADR-0023: [個性として和の感じを残し、見出しを明朝にし、主の色を緑にする](../../docs/adr/0023-keep-art-and-key-color.md)

テーマ変数には、DADS のテキストスタイルのうち使うものだけを、用途の名前で置く。

| 名前         | DADS のスタイル        | 用途                                       |
| ------------ | ---------------------- | ------------------------------------------ |
| `caption`    | Dns-14N-130            | 補足、図の説明、時刻                       |
| `body-dense` | Dns-16N-130            | 表のセル、入力欄の値、ファイルのツリーの行 |
| `body`       | Std-16N-170            | 記事の本文                                 |
| `label`      | Oln-16B-100            | ボタン、タブ                               |
| `heading-sm` | Std-18B-160            | 記事の小見出し、ダイアログの題             |
| `heading-md` | Std-20B-150            | 記事の見出し                               |
| `heading-lg` | Std-28B-150            | 記事の題                                   |
| `code`       | 等幅の 16px のスタイル | コードブロック、エディタ、端末             |
| `code-dense` | 等幅の 14px のスタイル | HTTP のヘッダと本文、端末の狭い表示        |

等幅の 2 つの行は、DADS の等幅のテキストスタイルのうち、大きさが同じものの行高を使う。

- 14px より小さい文字を使わない。
- `code-dense` だけが、本文でない 14px の文字になる。HTTP のヘッダは長い値が多く、16px では 1 行に収まらないためである。

### 余白と区切りと重なり

- 余白は、Tailwind のデフォルトの段（1 段 4px）で書く。ブロックの間は 8px の倍数にする。DADS は余白の段の値を決めず、使う側に任せている。
  - 出典: [DADS の余白](https://design.digital.go.jp/dads/foundations/spacing/)
- 区切りは、罫線と余白で示す。ヘッダーの下と表の頭の上は 2px の墨の罫、ほかは 1px の `border` の罫にする。
- `Link` は、文中に置くかで左右の余白を分ける。
  - 文中のリンクは、左右を 6px 空ける。フォーカスの表示が外へ 6px 広がり、前後の文字に重なるためである。
  - 記事の一覧の題のように文中に置かないリンクは、`isStandalone` を付けて左右を空けない。見出しや帯と左端をそろえるためである。
- 操作できる要素と重なる面の角は、2px で丸める。テーマ変数に置く角丸の名前は、`rounded-control` の 1 つだけにする。
  - 丸めるのは、`Button`、`IconButton`、枠のある `TextField`、`TreeView` の行、`Disclosure` の要約、タブの閉じるボタン、`Dialog`、`ActionMenu`、検索の候補の一覧である。
  - `Tabs` のタブ、下罫だけの検索の欄、メニューの項目、`Notice`、`StatusBadge`、`Table`、コードブロックの角は丸めない。罫で示す要素と、罫で区切る面のためである。
- 面の上に重なる面（ダイアログ、メニュー、候補の一覧）は、`bg-surface-raised`、1px の `border-field` の枠、`shadow-raised` の影を組にして書く。
  - 影は、ぼかさずに右下へ 4px ずらす。ぼかした影は、ダークの面の上でほぼ見えないためである。
  - 影は、重なる面だけに付ける。ボタンと入力欄には付けない。影が、重なりだけを表すためである。テーマ変数に置く影の名前は、`shadow-raised` の 1 つだけにする。
- ADR-0028: [操作できる要素と重なる面の角を 2px で丸め、重なる面にずらした影を付け、罫を引く動きを筆の線にする](../../docs/adr/0028-radius-shadow-and-brush-motion.md)
- ブレークポイントは、DADS の設定の例の 1 つ（48rem）だけを置く。
- 記事の本文の幅は、1 行を全角 40 字前後にする。測度の値は、テーマ変数の `--container-prose` に置く。
- ヘッダーと本文の外枠は、旧サイトの一覧の幅の 68rem にそろえ、テーマ変数の `--container-page` に置く。記事の一覧は、題と日付の列を青海波の帯と同じ外枠の幅に広げ、日付を右端に寄せる。記事の本文の列だけを、`--container-prose` に抑える。ヘッダーのロゴの左端と本文の左端は、余白を外枠の外側に置いてそろえる。

### フォーカスの表示

フォーカスの表示は、DADS の 2 重の表示（要素に接する黄色の輪と、その外の黒の枠）を、DADS の色の値のまま、テーマ変数のファイルの `focus-ring` の 1 つのユーティリティに置く。  
ダークのテーマでも、色と太さを変えない。  
黒の枠はダークの面の上で見えにくいが、黄色の輪が 3:1 以上を保つ。  
黄色の輪とダークの面の組を、コントラストのチェックに入れる。

検索の欄（`TextField` の `appearance="underline"`）だけは例外で、標準の輪を出さず、フォーカスすると緑（`primary`）の筆の線を左から 1 回引く。  
例外にする理由は、墨の罫だけで組んだ欄に黄の輪と黒の枠を重ねると、罫の版面が崩れるためである。運営者が、検索の欄の和の感じを罫で出すと決めた。  
緑の筆の線は、ライトで 6.55:1、ダークで 7.86:1 と、3:1 を超える。ただし、フォーカスの前の墨の罫との差は、色よりも太さ（1px の罫から、4px の筆の線）と、印の色（地味な墨から緑）が担う。キーボードの利用者の見つけやすさは、標準の輪より劣る。  
動きを減らす設定では、筆の線を引く動きを止め、全長の筆の線を最初から出す。  
ほかのコンポーネントには、この例外を使わない。`FOCUS-ONE` のチェックは、`focus` の変種に `ring`、`outline`、`border`、`shadow` を付ける書き方を止める。この欄は、`peer-focus:visible` と `peer-focus:animate-stroke` で書くので、チェックに当たらない。

### 動き

動きの時間と緩急は、Tailwind のデフォルトのユーティリティと、テーマ変数のファイルに足した animation とユーティリティで書く。  
テーマ変数のファイルに足すのは、デフォルトで組めない動きだけにする。  
サイト全体の動きの規則（位置を動かさない、動きのために JavaScript を配らない、5 秒を超える動きを止める）は、[全体の Design Doc の「動き」](../../docs/design/DesignDoc.md#動き) にある。

ADR-0028: [操作できる要素と重なる面の角を 2px で丸め、重なる面にずらした影を付け、罫を引く動きを筆の線にする](../../docs/adr/0028-radius-shadow-and-brush-motion.md)

#### 動きを付ける操作

動きを付ける操作は、次のものだけにする。

- 木の行、タブ、タブの閉じるボタンの色は、`transition-colors`（150ms）で替わる。
- ファイルの木と `Disclosure` の山形は、開閉で 90° 回る（150ms）。
- 選んだタブの下と、検索の欄のフォーカスには、緑の筆の線を左から 1 回引く（`animate-stroke` と `stroke-brush`、320ms）。筆の線は、入りが太く、終わりを払う形である。
- `Link` は、hover で下線の下に 2px の罫を左から 1 回引く（`link-rule`、240ms）。罫は背景で描き、文中のリンクが折り返したときは 1 行目から順に全ての行に引く。筆の線は、折り返さない所だけに使う。
  - 記事の一覧の題のように文中に置かないリンクを flex の子にして折り返したときは、罫は最後の行の下にだけ、リンクの幅で出る。flex の子の `<a>` はブロックの箱になり、背景は箱の下端に 1 本だけ描かれるためである。
- ナビゲーションは、折り返すかで線の形を分ける。
  - サイトのヘッダーのナビは、今いるページの印を錆の筆の線にし、ページを開くと左から 1 回引く（320ms）。hover では、墨の筆の線を左から 1 回引く（240ms）。ヘッダーのナビの文字は折り返さない。
  - `Breadcrumb` のリンクは、hover で、リンクの箱の下に筆の線を左から 1 回引く（`brush-hover`、240ms）。線は箱に付けるので、ラベルが折り返しても 1 本で崩れない。
  - `TableOfContents` の見出しと、`SeriesPager` の記事の題は折り返すので、hover で文字のすぐ下に 2px の罫を引く（`link-rule`、240ms）。行高 130% で折り返しても、罫は次の行の文字に接しない。
    - `SeriesPager` の記事の題には下線を引くので、罫は下線に重なり、hover で下線が太くなる形に見える。
  - フォーカスの表示には、ナビゲーションでも動きを付けない。
- `Button` は、押している間は面を濃くし、離すと文字の色の墨がにじんで消える（`ink-press`、480ms 以下）。
- ダイアログ、メニュー、検索の候補の一覧と候補が無いときの文は、濃度を上げて出る（`animate-fade-in`、150ms）。ダイアログは、上端に墨の筆の線を 1 回引く。
- `Button` の読み込み中は、3 つの点が左から順に薄くなる（`loading-dots`、1 周 1200ms）。`Loading` は、薄い罫の上を主の色の罫が伸びて抜ける（`animate-loading`、1 周 1600ms）。

#### 動きの長さ

- 操作に応える動き（色、濃度、山形の回転）は、150ms 以下にする。
- 罫と筆の線を引く動きは、320ms 以下で 1 回にする。
- 墨のにじみは、480ms 以下で消す。押した結果を待たせない飾りなので、操作に応える動きの長さの外に置く。
- 繰り返す動きは、処理中の印（`Button` の読み込み中と `Loading`）だけにする。

#### 動きを付けない所

- 操作の結果（切り替えた中身、開いた面の中身）は、動きの終わりを待たずに出す。動きは、結果の上に重ねる。
- フォーカスの表示には、動きを付けない。キーボードの利用者が、今いる場所をすぐに見つけられるためである。検索の欄の筆の線だけが例外である。
- 入力した文字と誤りの文には、動きを付けない。
- 位置と配置を動かさない。開閉で中身が出るときも、高さを動かさない。
- 動きのために JavaScript を配らない。
- OS で動きを減らす設定にした訪問者には、全ての動きを止める。筆の線は全長で、処理中の印は止まった形（濃い 3 つの点、全長の罫）で出す。止め方は、テーマ変数のファイルの末尾の 1 か所に置く。

### ファイルの印

`FileIcon` は、ファイルの名前の拡張子から、コード、文書、データ、そのほかの 4 つの系統を決める。  
系統は線の形で見分け、色は差し色の役割に合わせる。コードは藍（`info`）、文書は緑（`primary`）、データは墨、そのほかは薄い墨である。  
錆は目次の現在地と注意の役割なので、ファイルの印には使わない。  
ディレクトリは開閉で形が変わる。印は自前の SVG で、読み上げから外し、角は丸めない。

### コードの色

コードの色は、セマンティックトークンのコードの種類に置き、テーマごとに参照先を替える。  
記事のコードブロック、エディタ、端末は、同じトークンから作ったテーマを使う。

- ADR-0022: [コードの色を、セマンティックトークンから生成したテーマで、コードブロック、エディタ、端末に配る](../../docs/adr/0022-code-colors-from-tokens.md)

| トークン        | 当てる字句                                                       |
| --------------- | ---------------------------------------------------------------- |
| `code-surface`  | コードの面                                                       |
| `code-text`     | 識別子、記号、ほかの種類に当たらない字句                         |
| `code-comment`  | コメント。斜体を重ねる                                           |
| `code-keyword`  | 予約語、演算子のキーワード。太字を重ねる                         |
| `code-string`   | 文字列、正規表現                                                 |
| `code-number`   | 数値、真偽値、`null` のような定数                                |
| `code-function` | 関数とメソッドの名前                                             |
| `code-type`     | 型、クラス、HTML のタグ、JSON のキー                             |
| `code-ansi-*`   | 端末の 16 色。赤、緑、黄、青、マゼンタ、シアン、灰の階調に当てる |

- 字句の種類を増やさない。種類を増やすと、隣り合う色の差が小さくなり、見分けられなくなる。
- どのトークンも、`code-surface` に対して 4.5:1 以上にする。コメントも本文と同じ基準にする。
- 色だけで種類を分けない。コメントの斜体とキーワードの太字を、色に重ねる。
- 選んだ行と、エディタの選択の範囲は、状態の色の薄い面を使う。

生成のスクリプトは、セマンティックトークンをテーマごとに色の値まで解決し、`src/tokens/code-theme.gen.json` に書き出す。  
Expressive Code、エディタ、端末のテーマは、この JSON から作る。  
CSS の変数を読める描画（CodeMirror のクラスで当てる色）は、CSS の変数を直に使う。

- `src/tokens/code-theme.ts` の `toVsCodeTheme` が、JSON から VS Code の形式のテーマを作る。Expressive Code と Shiki は、このテーマを読む。
- ダークのコードの面は地より暗い墨にし、ページの面と分ける。
- 端末の bright の色は、ライトでは通常の色より暗い階調にする。ライトのコードの面の上で 4.5:1 を保つためである。
- 生成のスクリプトは `scripts/build-code-theme.mjs` で、`pnpm run check:tokens` が生成物のずれを見つける。

### HTTP の流れの色

HTTP の流れの表示には、新しい色のトークンを作らず、状態の色と区別の色に当てる。

| 表示するもの                                           | 当てるトークン                                      |
| ------------------------------------------------------ | --------------------------------------------------- |
| 1xx のレスポンス                                       | 状態の色を当てず、`StatusBadge` の `neutral` にする |
| 2xx のレスポンス                                       | 成功                                                |
| 3xx のレスポンス（リダイレクト）                       | 情報                                                |
| 4xx のレスポンス                                       | 注意                                                |
| 5xx のレスポンスと、届かなかったリクエスト             | エラー                                              |
| 通信する者（ブラウザ、クライアント、認可サーバー、DB） | 区別の色。1 つの流れの中で、者ごとに 1 色を固定する |

1 つの流れに出す者は、区別の色の数と同じ 6 つまでにする。  
7 つ目の者には、1 つ目の者と同じ色が当たり、色で見分けられなくなるためである。

状態コードと者の名前は、色と一緒に文字で出す。  
色を見分けられない訪問者も、どの者の間の、どの結果の通信かを読み取れるようにするためである。

### コンポーネントの分類と置き場

コンポーネントは BCD Design で分類し、名前はドメイン、場面、基本の語の順に並べる。  
`packages/ui` には Base と Case だけを置く。

- 出典: [BCD Design によるコンポーネントの分類](https://qiita.com/misuken/items/19f9f603ab165e228fe1)

| 分類     | 置き場                                                             | 例                                                       |
| -------- | ------------------------------------------------------------------ | -------------------------------------------------------- |
| Base     | `packages/ui/src/base/<名前>/`                                     | `Button`、`Tabs`、`TreeView`                             |
| Case     | `packages/ui/src/case/<名前>/`                                     | `SearchBox`、`FileTree`、`HttpExchangeList`              |
| パターン | `packages/ui/src/patterns/`                                        | まだ無い                                                 |
| Domain   | `apps/web/src/features/<機能>/`、`apps/playground/src/<関心ごと>/` | サイトの帯、記事の一覧の行、プレイグラウンドの画面の配置 |

パターンは、コンポーネントの組み合わせが 2 つ以上の画面に出たときに、`src/patterns/` に置く。  
`src/patterns/` には、まだパターンが無い。

コンポーネントは React で書く。  
クラスは clsx だけで組み、shadcn、Base UI、class-variance-authority、tailwind-merge を使わない。  
見た目は `variant` のような props で変え、呼び出す側から `className` で上書きさせない。  
Astro のページは、`client:*` を付けずに React のコンポーネントを置き、静的な HTML として描く。  
操作に JavaScript が要るコンポーネントだけを、island として `client:*` で読み込む。

記事の画面で使うコンポーネントは、JavaScript を無効にしても内容を読めるようにする。  
開閉は `<details>` で、タブの中身は全てのパネルを HTML に出してから JavaScript で隠す。

- 出典: [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/patterns/)

### カタログ

カタログは、`packages/ui` の Storybook にする。  
ページは、はじめに、トークン、コンポーネント、パターン、画面の 5 つに分ける。

- story は、コンポーネントの状態ごとに 1 つ置く。
- トークンとコンポーネントのページは、story に説明の MDX を付ける。
  - MDX のページの構成は、カタログの文書（`design/catalog.md`）の「カタログのページ」にある。
- MDX のページの背景と文字と、ページに iframe で埋めた story は、ツールバーで選んだテーマで描く。
  - Storybook の Docs のページは固定の色で描かれ、iframe の story はツールバーのテーマを受け取らないためである。
  - 描き方は `.storybook/preview.ts` と `.storybook/preview.css` にある。
- 全ての story で、Storybook の a11y のアドオン（axe）を動かし、違反をテストの失敗にする。
- カタログに載せるのは、コンポーネントとダミーデータだけにする。
- カタログは、サイトとは別の Worker に、`design.fukuemon.dev` で公開する。ドメインは `infra/cloudflare/` の Terraform で持ち、develop で check の workflow が通ったときに出す。

### DADS から外れる点

DADS から外れる点と理由は次のとおり。

- 色の値を fukuemon.dev が決める。地は生成り、罫は温かい灰、差し色はくすんだ緑、藍、錆である。DADS の色相の規則（成功は緑、エラーは赤）は守り、組み合わせをコントラストのチェックで確認する。運営者が、今のサイトの和の感じを残すと決めたためである。
  - 注意の色を、DADS の黄か橙ではなく、錆にする。錆は橙に近い色相で、旧サイトの差し色である。
  - 訪問済みのリンクを、色で分けない。旧サイトと同じく、内部のリンクの色を 1 つに保つ。
- 角丸と影に、DADS のコンポーネントごとの値を使わない。区切りは罫線で示し、角は操作できる要素と重なる面だけを 2px で丸め、影は重なる面だけにぼかさずに付ける。DADS のコンポーネントの角丸と影は、罫で区切る版面と合わないためである。
  - 検索の欄は、墨の下罫だけを引く（`TextField` の `appearance="underline"`）。送るボタンは置かず、Enter のキーで送る。欄が 1 つの form なので、JavaScript が無くても送れる。
  - 見出しは読み上げにだけ渡し、画面には虫眼鏡の印と、明朝の案内の文（placeholder）を出して欄の役割を示す。和の感じは、ボタンではなく欄の罫と書体で出す。
  - `Loading` の印は、円ではなく、薄い罫の上を主の色の罫が左から伸びて右へ抜ける形にする。版面と同じ罫で組めるためである。`Button` の読み込み中は、3 つの点で示す。罫は、ボタンの中では「—」に見えるためである。
- ダークのテーマを持つ。ダークの値も fukuemon.dev が選び、組み合わせをコントラストのチェックで確認する。
  - 訪問者は、本文とコードを長く読み、暗い部屋で読むこともあるためである。
- `Tabs` に閉じるボタンを足す。エディタのファイルのタブは、開いたファイルを閉じる操作が要るためである。
  - 閉じるボタンはマウスで押すためのもので、読み上げと Tab のキーの順から外す。タブの並び（`role="tablist"`）の中に、タブ以外の操作を置けないためである。
  - キーボードと読み上げでは、選んだタブで Delete のキーを押して閉じる。閉じられるタブは `aria-keyshortcuts="Delete"` を持つ。
  - マウスの中ボタンのクリックでも閉じる。Ctrl+W は、ブラウザのタブを閉じるキーと衝突するので割り当てない。
- `TreeView` に、APG の Tree View が必須にしない操作を 3 つ足す。
  - 文字を打つと、その文字で始まる項目へ移る（タイプアヘッド）。長い木で目的の項目へ早く移るためである。
  - `onRequestRename` を渡すと、項目で F2 のキーを押して名前の変更を呼べる。項目は `aria-keyshortcuts="F2"` を持つ。
  - `onRequestDelete` を渡すと、項目で Delete のキーを押して削除の確認を呼べる。項目は `aria-keyshortcuts="Delete"` を持つ。両方を渡すと、`aria-keyshortcuts` は `"F2 Delete"` になる。
  - 削除の確認は呼ぶ側が `ConfirmDialog` で行うので、キーを押しただけでは消えない。`Tabs` の Delete は表示を閉じる操作で、木の Delete は確認を開く操作である。キーの意味は、フォーカスのあるコンポーネントで決まる。
- `Button` の見た目の種類を、`primary`、`secondary`、`danger` の 3 つにする。
  - DADS の文字だけのボタンは持たない。文字だけの操作は `Link` か `IconButton` で足りるためである。
  - `danger` は、ファイルの削除のように、データを失う操作を確定するボタンに使う。DADS のボタンには、この種類がない。
- コードの色を持つ。DADS は、シンタックスハイライトの色を決めていない。
- 記事の題と見出しの書体を、Zen Old Mincho の 600 にする。`heading-*` のスタイルは、DADS の大きさと行高を使い、書体とウェイトだけを替える。運営者が、今のサイトの和の感じを残すと決めたためである。

## Interface

置くファイルは次のとおり。

| パス                                                  | 持つもの                                                                                                        |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `packages/ui/DESIGN.md`                               | 画面を作るときの原則と手順、アクセシビリティ                                                                    |
| `packages/ui/design/tokens.md`                        | トークンの使う場面                                                                                              |
| `packages/ui/design/components.md`                    | コンポーネントの選び方と、コンポーネントごとの規則                                                              |
| `packages/ui/design/catalog.md`                       | カタログのページと title の規則                                                                                 |
| `packages/ui/src/tokens/`                             | 3 つの層の CSS、書体の読み込み、生成したコードのテーマ                                                          |
| `packages/ui/src/base/`、`src/case/`、`src/patterns/` | コンポーネントと story とテスト。`src/patterns/` は、パターンを置くときに作る                                   |
| `packages/ui/.storybook/`                             | Storybook の設定と、カタログが返すレスポンスヘッダ（`public/_headers`）                                         |
| `packages/ui/wrangler.jsonc`                          | カタログを `design.fukuemon.dev` へ配信する Worker の設定                                                       |
| `scripts/`                                            | トークンの CSS の生成、コントラストのチェック、色の値のチェック、ユーティリティのチェック、コードのテーマの生成 |

チェックは、パッケージ design-system の手順で入れ、CI で流す。

- トークンの CSS とコードのテーマの生成物が、元のトークンと合っているか
- セマンティックトークンの組のコントラスト比を、ライトとダークの条件ごとに
- 画面のコードの色の値、プリミティブトークンの名前、原則に反するユーティリティ
- コンポーネントの状態、押せる領域の大きさ、story のアクセシビリティ（ブラウザで動かすテスト）
- Storybook のビルド
