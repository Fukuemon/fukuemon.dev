# デザインシステム（packages/ui）

## Overview

`packages/ui`（`@fukuemon/ui`）は、fukuemon.dev の画面が使うトークンとコンポーネントを持つ。  
記事の画面と、コードを動かす画面（エディタ、ファイルのツリー、端末、プレビュー、HTTP の流れ）を、同じトークンとコンポーネントで組む。  
値と規則は、デジタル庁デザインシステム（DADS）を元にする。  
トークンの層とコンポーネントの分け方は、buddy の `packages/ui` と同じ形にする。

- 出典: [デジタル庁デザインシステム](https://design.digital.go.jp/dads/)
- ADR-0020: [トークンを、DADS の値をコピーしたプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、ライトとダークをセマンティックトークンで切り替える](../../adr/0020-design-tokens-from-dads.md)
- ADR-0021: [packages/ui に Base と Case の React のコンポーネントを置き、packages/ui の Storybook をカタログにする](../../adr/0021-ui-components-and-catalog.md)

## Scope

持つものは次のとおり。

- プリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層
- ライトとダークのテーマ
- 文字、余白、角丸、影、ブレークポイント、動きの段
- コードの色（記事のコードブロック、エディタ、端末）と、HTTP の流れの色
- ドメインを持たない Base と Case のコンポーネント
- Storybook のカタログ
- デザインシステムの文書（`DESIGN.md` と `design/` の 3 つの文書）

持たないものは次のとおり。

- Domain のコンポーネント。サイトの帯、記事の一覧の行、プレイグラウンドの画面の配置は、`apps/web` の `features/<機能>/components` に置く。
- エディタと端末のエンジン（CodeMirror、xterm.js など）の選択と結び付け。プレイグラウンドの要求の prototype で決める。`packages/ui` は枠とテーマだけを持つ。
- 記事の Markdown の描画と、Mermaid の図の SVG への変換。サイトの基盤の要求で扱う。
- 縦組み。

## Design

### トークンの層

トークンを 3 つの層に分ける。  
画面とコンポーネントは、テーマ変数のユーティリティだけを書く。

| 層                     | ファイル                                                  | 持つもの                                                                                                       |
| ---------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| プリミティブトークン   | `src/tokens/primitive.css`                                | DADS の `@digital-go-jp/design-tokens` からコピーした値。色の階調、書体、文字の大きさ、行高、角丸、影          |
| セマンティックトークン | `src/tokens/semantic.css`、`src/tokens/semantic-dark.css` | 役割の名前。プリミティブトークンを参照し、テーマごとに参照先を替える                                           |
| テーマ変数             | `src/tokens/theme.css`                                    | Tailwind CSS のユーティリティの名前。Tailwind のデフォルトの色、文字の大きさ、角丸、影、ブレークポイントを消す |

- 接頭辞は、プリミティブトークンを `--fd-primitive-`、セマンティックトークンを `--fd-color-` にする。
- テーマ変数にないクラスと、任意の値のクラス（`bg-[#fff]` など）は、lint（oxlint の JS プラグインの eslint-plugin-better-tailwindcss）がエラーにする。Tailwind のデフォルトを消しただけでは、テーマ変数にないクラスは CSS を出さないだけでビルドが通るためである。
- コピーするのは、セマンティックトークンとテーマ変数が参照する値だけにする。新しい値が要るときに、DADS の同じバージョンから同じ規則の名前で足す。
- セマンティックトークンの種類は、面、文字、枠、操作、フォーカス、状態、区別、コードの 8 つにする。
  - 状態は、エラー、注意、成功、情報の 4 つにする。文字の色と、同じ系統の薄い面を組にする。
  - コードの種類は、DADS にない。下の「コードの色」にある。

### テーマ

ライトとダークのテーマは、セマンティックトークンの参照先を替えて作る。  
プリミティブトークンとテーマ変数のファイルは、テーマごとに分けない。

- ライトの値は `semantic.css` の `:root` に、ダークの値は `semantic-dark.css` に置く。`semantic-dark.css` は、`@media (prefers-color-scheme: dark)` の `:root:not([data-theme="light"])` で参照先を替える。
  - ダークの値を別のファイルに置くのは、コントラストのチェックが、ライトの値だけのファイルと、ダークのブロックを分けて読むためである。
- 訪問者は、OS の設定でテーマを選ぶ。サイトの中にテーマの切り替えを置かない。
- Storybook は、ツールバーでテーマを切り替える。`[data-theme="dark"]` にもダークの値を当て、`[data-theme="light"]` では OS の設定がダークでもライトの値にする。Storybook だけがこの属性を使う。
  - ツールバーのデフォルトは「OS の設定」にし、サイトと同じく OS の設定に従って描く。
- コントラストのチェックは、ライトとダークの条件ごとに流す。

### 色

主の色（`primary`）は、DADS の緑の階調にする。  
状態の色は、DADS のとおり、成功を緑、エラーを赤、注意を橙、情報を青の階調に当てる。  
リンクは DADS のリンクの色を使い、訪問済みのリンクを別の色にする。

- 出典: [DADS の色](https://design.digital.go.jp/dads/foundations/color/)
- ADR-0023: [個性として和の感じを残し、見出しを明朝にし、挿絵を作り替え、主の色を緑にする](../../adr/0023-keep-art-and-key-color.md)

文字と面の組は、WCAG 2.2 の AA を満たす。  
文字は 4.5:1 以上、入力欄と押せるものの枠とフォーカスの表示は 3:1 以上にする。

### 文字

書体は、本文に Noto Sans JP の 400 と 700、記事の題と見出しに Zen Old Mincho の 600、等幅に Noto Sans Mono を使う。  
書体は Fontsource で self-host し、外部の CDN から読まない。

- Zen Old Mincho は、ビルドで見出しに使う字だけのファイルにする。
- 等幅の和文の字は、BIZ UDGothic の 400 と 700 で受ける。M PLUS 1 Code と比べて、見出しの字に絞ったときのファイルが小さく（400 字で約 70 KB と約 150 KB）、Fontsource に静的なウェイトがあるためである。
- 見出しの明朝のウェイトは、テーマ変数の `font-semibold`（600）で書く。
- どの書体も `font-display: swap` にし、和文の分割は preload しない。
- ADR-0023: [個性として和の感じを残し、見出しを明朝にし、挿絵を作り替え、主の色を緑にする](../../adr/0023-keep-art-and-key-color.md)

テーマ変数には、DADS のテキストスタイルのうち使うものだけを、用途の名前で置く。

| 名前         | DADS のスタイル        | 用途                                       |
| ------------ | ---------------------- | ------------------------------------------ |
| `caption`    | Dns-14N-130            | 補足、図の説明、時刻                       |
| `body-dense` | Dns-16N-130            | 表のセル、入力欄の値、ファイルのツリーの行 |
| `body`       | Std-16N-170            | 記事の本文                                 |
| `label`      | Oln-16B-100            | ボタン、タブ                               |
| `heading-sm` | Std-18B-160            | 記事の小見出し、ダイアログの題             |
| `heading-md` | Std-20B-150            | 記事の見出し                               |
| `heading-lg` | Std-28B-150            | 記事の題                                   |
| `code`       | 等幅の 16px のスタイル | コードブロック、エディタ、端末             |
| `code-dense` | 等幅の 14px のスタイル | HTTP のヘッダと本文、端末の狭い表示        |

等幅の 2 つの行は、DADS の等幅のテキストスタイルのうち、大きさが同じものの行高を使う。

- 14px より小さい文字を使わない。
- `code-dense` だけが、本文でない 14px の文字になる。HTTP のヘッダは長い値が多く、16px では 1 行に収まらないためである。

### 余白と角丸と影

- 余白は、Tailwind のデフォルトの段（1 段 4px）で書く。ブロックの間は 8px の倍数にする。DADS は余白の段の値を決めず、使う側に任せている。
  - 出典: [DADS の余白](https://design.digital.go.jp/dads/foundations/spacing/)
- 角丸と影は、DADS の値をプリミティブトークンにコピーして使う。
- 面の上に重なる面（ダイアログ、メニュー）は、`bg-surface-raised` と `shadow-*` を組にして書く。
  - ライトでは、DADS の影で重なりを示す。
  - ダークでは、影の代わりに、明るい面（`surface-raised`）と 1px の枠で重なりを示す。DADS の影は黒なので、ダークの面の上では見えないためである。DADS の影の値は変えず、`shadow-*` が指すセマンティックトークンの値をダークで替える。
- ブレークポイントは、DADS の設定の例の 1 つ（48rem）だけを置く。
- 記事の本文の幅は、1 行を全角 40 字前後にする。測度の値は、テーマ変数の `--container-prose` に置く。

### フォーカスの表示

フォーカスの表示は、DADS の 2 重の表示（要素に接する黄色の輪と、その外の黒の枠）を、テーマ変数のファイルの `focus-ring` の 1 つのユーティリティに置く。  
ダークのテーマでも、色と太さを変えない。  
黒の枠はダークの面の上で見えにくいが、黄色の輪が 3:1 以上を保つ。  
黄色の輪とダークの面の組を、コントラストのチェックに入れる。

### 動き

動きの時間と緩急は、Tailwind のデフォルトのユーティリティだけで書く。  
OS で動きを減らす設定にした訪問者には、位置、大きさ、回転を動かす動きを出さない。  
止め方は、テーマ変数のファイルの末尾の 1 か所に置く。

### コードの色

コードの色は、セマンティックトークンのコードの種類に置き、テーマごとに参照先を替える。  
記事のコードブロック、エディタ、端末は、同じトークンから作ったテーマを使う。

- ADR-0022: [コードの色を、セマンティックトークンから生成したテーマで、コードブロック、エディタ、端末に配る](../../adr/0022-code-colors-from-tokens.md)

| トークン        | 当てる字句                                                              |
| --------------- | ----------------------------------------------------------------------- |
| `code-surface`  | コードの面                                                              |
| `code-text`     | 識別子、記号、ほかの種類に当たらない字句                                |
| `code-comment`  | コメント。斜体を重ねる                                                  |
| `code-keyword`  | 予約語、演算子のキーワード。太字を重ねる                                |
| `code-string`   | 文字列、正規表現                                                        |
| `code-number`   | 数値、真偽値、`null` のような定数                                       |
| `code-function` | 関数とメソッドの名前                                                    |
| `code-type`     | 型、クラス、HTML のタグ、JSON のキー                                    |
| `code-ansi-*`   | 端末の 16 色。DADS の階調の赤、緑、黄、青、マゼンタ、シアン、灰に当てる |

- 字句の種類を増やさない。種類を増やすと、隣り合う色の差が小さくなり、見分けられなくなる。
- どのトークンも、`code-surface` に対して 4.5:1 以上にする。コメントも本文と同じ基準にする。
- 色だけで種類を分けない。コメントの斜体とキーワードの太字を、色に重ねる。
- 選んだ行と、エディタの選択の範囲は、状態の色の薄い面を使う。

生成のスクリプトは、セマンティックトークンをテーマごとに色の値まで解決し、`src/tokens/code-theme.gen.json` に書き出す。  
Expressive Code、エディタ、端末のテーマは、この JSON から作る。  
CSS の変数を読める描画（CodeMirror のクラスで当てる色）は、CSS の変数を直に使う。

### HTTP の流れの色

HTTP の流れの表示には、新しい色のトークンを作らず、状態の色と区別の色に当てる。

| 表示するもの                                           | 当てるトークン                                      |
| ------------------------------------------------------ | --------------------------------------------------- |
| 2xx のレスポンス                                       | 成功                                                |
| 3xx のレスポンス（リダイレクト）                       | 情報                                                |
| 4xx のレスポンス                                       | 注意                                                |
| 5xx のレスポンスと、届かなかったリクエスト             | エラー                                              |
| 通信する者（ブラウザ、クライアント、認可サーバー、DB） | 区別の色。1 つの流れの中で、者ごとに 1 色を固定する |

状態コードと者の名前は、色と一緒に文字で出す。  
色を見分けられない訪問者も、どの者の間の、どの結果の通信かを読み取れるようにするためである。

### コンポーネントの分類と置き場

コンポーネントは BCD Design で分類し、名前はドメイン、場面、基本の語の順に並べる。  
`packages/ui` には Base と Case だけを置く。

- 出典: [BCD Design によるコンポーネントの分類](https://qiita.com/misuken/items/19f9f603ab165e228fe1)

| 分類     | 置き場                                     | 例                                                       |
| -------- | ------------------------------------------ | -------------------------------------------------------- |
| Base     | `packages/ui/src/base/<名前>/`             | `Button`、`Tabs`、`TreeView`                             |
| Case     | `packages/ui/src/case/<名前>/`             | `SearchBox`、`FileTree`、`HttpExchangeList`              |
| パターン | `packages/ui/src/patterns/`                | 確認のダイアログ                                         |
| Domain   | `apps/web/src/features/<機能>/components/` | サイトの帯、記事の一覧の行、プレイグラウンドの画面の配置 |

コンポーネントは React で書く。  
Astro のページは、`client:*` を付けずに React のコンポーネントを置き、静的な HTML として描く。  
操作に JavaScript が要るコンポーネントだけを、island として `client:*` で読み込む。

記事の画面で使うコンポーネントは、JavaScript を無効にしても内容を読めるようにする。  
開閉は `<details>` で、タブの中身は全てのパネルを HTML に出してから JavaScript で隠す。

### 画面ごとのコンポーネント

記事の画面とコードを動かす画面に要るコンポーネントは、次のとおり。  
DADS にないコンポーネントは、WAI-ARIA Authoring Practices Guide のパターンのキーボードの操作に従う。

- 出典: [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/patterns/)

両方の画面で使う Base は次のとおり。

| コンポーネント         | 使う場所                                         | 元にするもの                                    |
| ---------------------- | ------------------------------------------------ | ----------------------------------------------- |
| `Button`、`IconButton` | コードの写し、実行、ファイルの操作               | DADS のボタン                                   |
| `Link`                 | 本文の内部と外部のリンク                         | DADS のリンク                                   |
| `Tabs`                 | 記事の中の例の切り替え、エディタのファイルのタブ | DADS のタブ。エディタのために閉じるボタンを足す |
| `Dialog`               | 検索、ファイルの削除の確認                       | DADS のモーダルダイアログ                       |
| `ActionMenu`           | ファイルとディレクトリの操作のメニュー           | DADS のメニューリスト                           |
| `TextField`            | 検索の語、ファイルの名前の入力                   | DADS のインプットテキスト                       |
| `Table`                | 記事の表、SQL の結果、HTTP のヘッダ              | DADS のテーブル                                 |
| `StatusBadge`          | HTTP の状態コード、記事の種別                    | DADS のラベル                                   |
| `Notice`               | 記事の注意書き、実行のエラー                     | DADS のノティフィケーションバナー               |
| `Disclosure`           | 記事の補足、リクエストとレスポンスの詳細         | DADS のアコーディオン                           |
| `Loading`              | 実行環境の起動、パッケージのインストール         | DADS のプログレスインジケーター                 |
| `Breadcrumb`           | 記事とシリーズの位置                             | DADS のパンくずリスト                           |
| `TreeView`             | `FileTree` が組む木の表示                        | APG の Tree View                                |
| `SplitPane`            | エディタ、端末、プレビューの間の境界             | APG の Window Splitter                          |

記事の画面の Case は次のとおり。

| コンポーネント    | 担うこと                                     |
| ----------------- | -------------------------------------------- |
| `SearchBox`       | 記事の検索の語の入力と候補                   |
| `TableOfContents` | 記事の見出しの一覧と、読んでいる見出しの表示 |
| `SeriesPager`     | シリーズの中の前と次の記事へのリンク         |

コードを動かす画面の Case は次のとおり。

| コンポーネント       | 担うこと                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| `FileTree`           | ファイルとディレクトリの一覧、作成、名前の変更、削除。`TreeView`、`ActionMenu`、`TextField` を組む |
| `EditorFrame`        | ファイルのタブと、エディタのエンジンを置く枠                                                       |
| `TerminalFrame`      | 端末の題と、端末のエンジンを置く枠                                                                 |
| `PreviewFrame`       | プレビューの URL の欄と、iframe を置く枠                                                           |
| `HttpExchangeList`   | 行き来したリクエストとレスポンスを順に並べた一覧。者、メソッド、URL、状態コードを出す              |
| `HttpExchangeDetail` | 1 つの行き来のヘッダ、Cookie、本文                                                                 |

### カタログ

カタログは、`packages/ui` の Storybook にする。  
ページは、はじめに、トークン、コンポーネント、パターン、画面の 5 つに分ける。

- story は、コンポーネントの状態ごとに 1 つ置く。
- 全ての story で、Storybook の a11y のアドオン（axe）を動かし、違反をテストの失敗にする。
- カタログに載せるのは、コンポーネントとダミーデータだけにする。
- カタログは、サイトとは別の Worker に、`design.fukuemon.dev` で公開する。ドメインは `infra/cloudflare/` の Terraform で持ち、develop で check の workflow が通ったときに出す。

### DADS から外れる点

DADS から外れる点と理由は次のとおり。

- ダークのテーマを持つ。ダークの値は、DADS のプリミティブトークンの階調から fukuemon.dev が選び、組み合わせをコントラストのチェックで確認する。
  - 訪問者は、本文とコードを長く読み、暗い部屋で読むこともあるためである。
- `Tabs` に閉じるボタンを足す。エディタのファイルのタブは、開いたファイルを閉じる操作が要るためである。
- コードの色を持つ。DADS は、シンタックスハイライトの色を決めていない。
- 記事の題と見出しの書体を、Zen Old Mincho の 600 にする。`heading-*` のスタイルは、DADS の大きさと行高を使い、書体とウェイトだけを替える。運営者が、今のサイトの和の感じを残すと決めたためである。

## Interface

置くファイルは次のとおり。

| パス                                                  | 持つもの                                                                                                        |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `packages/ui/DESIGN.md`                               | 画面を作るときの原則と手順、アクセシビリティ                                                                    |
| `packages/ui/design/tokens.md`                        | トークンの使う場面                                                                                              |
| `packages/ui/design/components.md`                    | コンポーネントの選び方と、コンポーネントごとの規則                                                              |
| `packages/ui/design/catalog.md`                       | カタログのページと title の規則                                                                                 |
| `packages/ui/src/tokens/`                             | 3 つの層の CSS、書体の読み込み、生成したコードのテーマ                                                          |
| `packages/ui/src/base/`、`src/case/`、`src/patterns/` | コンポーネントと story とテスト                                                                                 |
| `packages/ui/.storybook/`                             | Storybook の設定                                                                                                |
| `scripts/`                                            | トークンの CSS の生成、コントラストのチェック、色の値のチェック、ユーティリティのチェック、コードのテーマの生成 |

チェックは、パッケージ design-system の手順で入れ、CI で流す。

- トークンの CSS とコードのテーマの生成物が、元のトークンと合っているか
