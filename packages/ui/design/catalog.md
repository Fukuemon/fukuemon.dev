# fukuemon.dev のデザインシステムのカタログ

この文書は、[デザインシステムの文書](../DESIGN.md)の一部で、カタログのページの組み方と、カタログに載せてよいものの規則を持つ。  
カタログは `packages/ui` の Storybook で、公開先の URL とローカルで開くコマンドは DESIGN.md の冒頭にある。

## カタログのページ

カタログのページに、規則の本文を写さない。  
原則の ID と規則の見出しを並べ、DESIGN.md と 3 つの文書のファイルとセクションの名前で指す。  
カタログの原稿には URL を書かないので、文書をリンクにしない。

例外として、トークンのページは、トークンごとに見本と使う場面を並べる。  
使う場面の文は、トークンの文書（`design/tokens.md`）の表から写し、表に文の無いトークンには文を作らない。  
見本を見ながら、どのトークンを選ぶかを決められるようにするためである。

| ページ         | 書くこと                                                                                                                     | 配置先                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| はじめに       | 原則の ID と、アクセシビリティの基準の項目の一覧                                                                             | `src/docs/`                            |
| トークン       | 色、文字、余白と区切りと重なり、コードの色                                                                                   | `src/tokens/`                          |
| コンポーネント | 変種と状態の例、Do と Don't の例。使う場面、使わない場面、キーボードの操作は、コンポーネントの文書のそのコンポーネントを指す | `src/base/<名前>/`、`src/case/<名前>/` |
| パターン       | コンポーネントを組み合わせた形。狭い画面と広い画面の例                                                                       | `src/patterns/`                        |
| 画面           | 記事の画面とコードを動かす画面の例                                                                                           | `src/screens/`                         |

- ページは、この表の順にサイドバーに並べる。順は `.storybook/preview.ts` の `storySort` が決める。
- トークンとコンポーネントのページは、story のファイルと同じディレクトリに説明の MDX を置き、`<Meta of>` で story に付ける。
  - トークンのページの MDX は、使う場面と当たる原則がある文書のセクションと、値のファイルを指す。
    - 色は、`ColorPalette` と `ColorItem` で 1 色 1 行にし、`subtitle` に使う場面を書く。
    - 文字、余白、区切り、重なり、フォーカスは、段ごとに見本と使う場面を並べる。
    - 見本は、ツールバーで選んだテーマで描く。
    - ページの末尾に、story を並べる。
  - コンポーネントのページの MDX は、「規則」「状態」「props」の 3 つのセクションにする。
    - 「規則」は、コンポーネントの文書のそのコンポーネントのセクションと、原則の ID を指す。
    - 「状態」は、story を全て並べる。
    - 「props」は、コンポーネントの props の表を出す。
- story は、コンポーネントの状態ごとに 1 つ置く。コンポーネントの文書のそのコンポーネントに並べた状態を、全部例にする。読み込み中とエラーのように、データで決まる状態も、ダミーのデータで作る。
- Show code は、ビルドのときに story のソースから作ったコードを出す。
  - Button の Primary では、`const Primary = () => <Button variant="primary">保存</Button>;` が出る。
  - `render` が `{...args}` で props を渡す story では、`args` の値が props に展開されて出る。
  - `render` が `args.headings` のように `args` のプロパティを読む story では、その式のまま出る。
  - `render` の JSX で、要素の直後に続くテキストの先頭の空白は、Show code に出ない。
  - 要素の直後に続くテキストが空白から始まるときは、`{" を読む。"}` のように文字列リテラルの式で書く。
- テーマは、Storybook のツールバーで「OS の設定」「ライト」「ダーク」から切り替える。
- 全ての story で a11y のアドオン（axe）を動かし、違反を `pnpm run test:ui` の失敗にする。

## 題の決め方

題は、ファイルの配置先から決める。  
`<名前>` は、ディレクトリの名前か、ページの名前である。

| 配置先                           | 題                           |
| -------------------------------- | ---------------------------- |
| `src/docs/はじめに.mdx`          | `はじめに`                   |
| `src/tokens/<名前>.stories.tsx`  | `トークン/<ページの名前>`    |
| `src/tokens/<ページの名前>.mdx`  | 付けた story の題            |
| `src/base/<名前>/`               | `コンポーネント/Base/<名前>` |
| `src/case/<名前>/`               | `コンポーネント/Case/<名前>` |
| `src/patterns/<名前>/`           | `パターン/<名前>`            |
| `src/screens/<名前>.stories.tsx` | `画面/<画面の名前>`          |

- トークンと画面のページの名前は、日本語の名前（`色`、`コードの色`、`記事`、`コードを動かす画面`）にする。
- トークンのページを足したら、`storySort` の `トークン` の並びにも足す。

## カタログに載せてよいもの

カタログは `design.fukuemon.dev` で誰でも開ける。  
載せてよいのは、コンポーネントとダミーのデータだけである。

- 人の名前と組織の名前は、ダミーの値にする。実際の画面やデータベースからコピーしない。
- API を呼ぶ例を作らない。データは例の中か、ダミーのデータのファイルから渡す。
- カタログの原稿に、URL、ホスト名、シークレットを書かない。
- カタログは検索エンジンの索引に載せない。`.storybook/public/_headers` が `X-Robots-Tag: noindex` を返す。
