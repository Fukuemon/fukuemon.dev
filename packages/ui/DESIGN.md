# fukuemon.dev のデザインシステム

この文書は、fukuemon.dev の画面とコンポーネントのコードを書く人が、書く前に読む規則である。  
値は fukuemon.dev が決め、アクセシビリティ、タイポグラフィ、配色、レイアウトの指標と参考に、デジタル庁デザインシステム（DADS）を使う。  
構成の判断は [Design Doc](DesignDoc.md) と、ADR-0021、ADR-0022、ADR-0023、ADR-0024、ADR-0028、ADR-0062にある。

- 出典: [デジタル庁デザインシステム](https://design.digital.go.jp/dads/)
- ADR-0021: [packages/ui に Base と Case の React のコンポーネントを置き、packages/ui の Storybook をカタログにする](../../docs/adr/0021-ui-components-and-catalog.md)
- ADR-0024: [トークンを、fukuemon.dev の値のプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、生成りの地と旧サイトの差し色で、角丸と影を使わない版面にする](../../docs/adr/0024-tokens-of-fukuemon-dev.md)
- ADR-0062: [コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくする](../../docs/adr/0062-dense-text-and-targets-in-playground.md)

カタログは https://design.fukuemon.dev で開ける。  
ローカルでは、リポジトリのルートで `pnpm --filter @fukuemon/ui storybook` を流し、`http://localhost:6106` を開く。

**画面とコンポーネントのコードを書く前に、この文書と 3 つの文書を全て読む。** この文書だけを読むと、トークンの使う場面と、コンポーネントの使い方と状態を知らないまま書くことになる。

| 文書                                             | 持つ規則                                                                           |
| ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| [トークン](design/tokens.md)                     | セマンティックトークンの使う場面、テーマ、文字、レイアウト、区切り、重なり、動き   |
| [コンポーネントとパターン](design/components.md) | コンポーネントごとの使う場面、変種、状態、内容の制約、キーボードの操作と、パターン |
| [カタログ](design/catalog.md)                    | カタログのページ、題の決め方、カタログに載せてよいもの                             |

## 元にしたデザインシステムとの関係

DADS から外れる規則は、この表に並べず、外れる規則の隣に、DADS が求めることと外れる理由を書いている。

| 項目                   | DADS の扱い                                    | このプロダクト                                                                                                                                                                                 |
| ---------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主の色                 | 使う側に任せる                                 | くすんだ緑（`primary`）                                                                                                                                                                        |
| 余白の段               | 使う側に任せる                                 | Tailwind のデフォルトの段（1 段 4px）。ブロックの間は 8px の倍数                                                                                                                               |
| 角丸と影               | コンポーネントごとに値を持つ                   | 角丸は 2px の 1 つだけを、操作できる要素と重なる面に使う。影は、ずらした影の 1 つだけを、重なる面に使う。外れる理由は [トークン](design/tokens.md)の「レイアウト、区切り、重なり、動き」にある |
| コントラスト           | 変えない（文字 4.5:1、文字でないもの 3:1）     | 確認: `pnpm run check:contrast`。ライト、OS の設定のダーク、Storybook のダークの 3 つの条件で見る                                                                                              |
| 状態の色相と意味の対応 | 変えない（成功は緑、エラーは赤、注意は黄か橙） | 確認: レビュー。注意だけを錆にする理由は [トークン](design/tokens.md)の「色」にある                                                                                                            |

## 画面を作るときの原則

- `COLOR-TOKEN`: 色、文字、動きは、テーマ変数のユーティリティだけで書く。色の値とプリミティブトークンの名前を、画面のコードに直に書かない。
  - 確認: 色の値とプリミティブトークンの名前は、チェック（`pnpm run check:raw-values`）で見る。文字、動きの時間と遅れの値は、レビューで見る。アニメーションと緩急の任意値は、`MOTION-TOKEN` のチェックで見る。
- `STATE-NOT-COLOR-ONLY`: 状態を色だけで伝えない。エラーと注意には、文と印を色と一緒に出す。
  - 確認: レビューで、色を見分けられない人がエラーの場所と内容を読み取れるかを見る。
- `TEXT-MIN-SIZE`: 14px より小さい文字を使わない。本文と操作の文字は 16px にし、14px は補足だけに使う。
  - 例外: コードを動かす画面のコンポーネントは、コードと操作のラベル、木の行、入力欄の値、表のセルを 13px、コンソールの値と補足を 12px まで小さくしてよい。DevTools とコードエディタに近い密度で、多くの行を見渡すためである（ADR-0062、ADR-0066）。
    - 使うトークンは、`text-compact`、`text-label-compact`、`text-body-compact`、`text-code-compact` の 4 つである。
    - ADR-0062: [コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくする](../../docs/adr/0062-dense-text-and-targets-in-playground.md)
    - ADR-0066（提案）: [コードを動かす画面の詰めたペインで、フォーカスの輪を要素の内側に引き、13px の文字のトークンを 2 つ足す](../../docs/adr/0066-inset-focus-ring-in-dense-panes.md)
  - 確認: `pnpm run check:utilities`。4 つのトークンをコードを動かす画面の外で使っていないかは、レビューで見る。
- `PRIMARY-ACTION-ONE`: 主のボタンは、1 つの画面かダイアログに 1 つまでにする。
  - 確認: レビューで、画面の主の操作が 1 つに決まるかを見る。
- `FOCUS-ONE`: フォーカスの表示は 1 つのユーティリティ（墨の 2px の 1 重の輪）だけを使い、コンポーネントごとに色や太さを変えない。例外の理由は DesignDoc の「フォーカスの表示」に書いた。
  - 例外: 検索の欄（`TextField` の `appearance="underline"`）の緑の罫。
  - 例外: コードを動かす画面の詰めたペインの中の行と、ペインの全体を占めるスクロールする領域の、内側に引く輪（`focus-ring-inset`）。
    - ADR-0066（提案）: [コードを動かす画面の詰めたペインで、フォーカスの輪を要素の内側に引き、13px の文字のトークンを 2 つ足す](../../docs/adr/0066-inset-focus-ring-in-dense-panes.md)
  - DADS は、黄色の輪と黒の枠の 2 重の表示を求める。墨の輪にする理由は、DesignDoc の「フォーカスの表示」にある。
  - 確認: `pnpm run check:utilities`。`focus-ring-inset` を詰めたペインの外で使っていないかは、レビューで見る。
- `TARGET-SIZE`: 押せる領域は 44×44 CSS px 以上にする。WCAG 2.2 の AA（2.5.8）の 24×24 より厳しい、AAA（2.5.5）の値を選んでいる。見た目を小さくするときは、見た目の外に押せる領域を広げる。
  - 例外: `Link` は対象にせず、WCAG 2.2 の AA（2.5.8）の 24×24 CSS px 以上にする。本文の中の文字のリンクを 44×44 CSS px にすると、行の高さが崩れるためである。
  - 例外: コードを動かす画面のコンポーネントは、WCAG 2.2 の AA（2.5.8）の 24×24 CSS px 以上にする。木の行と開閉の要約（`Disclosure`）は 24px、ボタン、入力欄、タブは 28〜32px にする（ADR-0062）。
    - ADR-0062: [コードを動かす画面だけ、文字を 12px と 13px まで、押せる領域を 24×24 CSS px まで小さくする](../../docs/adr/0062-dense-text-and-targets-in-playground.md)
  - 確認: `pnpm run test:ui` の component の project で、コンポーネントごとの、名前に「44 px」を含むテストが見る。コードを動かす画面の例外のコンポーネントでは、名前に「24 px」か「28 px」を含むテストが見る。例は、`src/base/Button/Button.test.tsx` の「S のボタンは、見た目の外まで 44×44 px 以上を押せる」である。カタログのアクセシビリティの自動チェックは、押せる領域の大きさを確認しない。
- `SPACING-SCALE`: 余白は、トークンの文書の「レイアウト、区切り、重なり、動き」の表の余白の段のユーティリティだけで書く。任意値（`p-[13px]` のような書き方）を書かない。
  - 確認: `pnpm run check:utilities`
  - 入力欄と、その見出し、補足の文、誤りの文の間は、`gap-2`（8px）以上にする。フォーカスの表示（`focus-ring`）は、欄の外へ 4px 広がる。狭いと、フォーカスの表示が近くの文字に重なる。
    - 確認: レビューで、欄と近くの文字の間が、その段以上かを見る。
- `LAYOUT-OVERFLOW`: レイアウトのブレークポイントの幅ごとに、ページの横方向のオーバーフローを出さない。長い文字とデータの多い状態でも出さない。
  - 確認: ページの全体の幅は、`pnpm run test:ui` の `src/screens/Playground.test.tsx` の、名前に `LAYOUT-OVERFLOW` を含むテストで見る。320px、767px、768px、1280px の幅を見る。内側の領域で切れた文字とボタンは、撮った画像をレビューで見る。
- `MOTION-TOKEN`: アニメーションと緩急は、トークンの文書の「レイアウト、区切り、重なり、動き」の表の動きのユーティリティだけで書く。任意値（`animate-[ping_1s_infinite]` のような書き方）を書かない。アニメーションの任意値はテーマ変数を通らないので、`MOTION-REDUCE` の止め方では止まらない。
  - 確認: `pnpm run check:utilities`
- `MOTION-REDUCE`: 利用者が OS で動きを減らす設定（`prefers-reduced-motion: reduce`）にしたときは、位置、大きさ、回転を動かすアニメーションと遷移、スクロールに合わせた動きを止める。残すのは、状態の変化を伝える短い透明度の変化と、機能に欠かせない動きだけにする。今の止め方は、透明度の変化を含む全てのアニメーションと遷移を止めるので、残す動きは無い。WCAG 2.2 の AA に無い、AAA（2.3.3）の基準を選んでいる。止め方はテーマ変数のファイル（`src/tokens/theme.css`）の末尾の 1 か所に置き、画面のコードに設定ごとの条件を書かない。
  - 確認: レビューで、テーマ変数のファイルの止め方を見る。動きを減らす設定で描画した画面を調べるテストは無い。

## 画面を作るときの手順

### 順

1. 参照先の表、トークンの文書、コンポーネントの文書、カタログから、使うパターン、コンポーネント、トークンを探す。合うものがなければ、画面のコードで作らず、デザインシステムに足すかを尋ねる。
2. テーマ変数のユーティリティと、このデザインシステムのコンポーネントだけで書く。
3. 使ったコンポーネントの状態のうち、画面で起きるものを作る。
4. 下の「流すコマンド」を、表の順に流す。
5. 描画した画面を、トークンの文書のブレークポイントの幅ごとと、テーマごとに撮り、横方向のオーバーフローを確認する。撮った画像はレビューで見る。
6. チェックが通らなければ直し、手順 4 から流し直す。チェックの出力を見て自分で直すのは、2 回までにする。<!-- 回数を変えるときは、ここの数を直す -->
   - 2 回直しても通らないか、違反の数が減らないときは、直すのをやめて止まる。最後に全てのチェックが通ったコミットに、通らない変更を混ぜない。通らない変更は、コミットせずに差分として報告に添える。
   - 全てのチェックが通ったコミットが無いときは、作業を始めたときのコミットを代わりにし、そのときに既に通らなかった原則の ID を報告に書く。
7. 下の「報告の形」で報告する。止まったときは、最後に通ったコミットの SHA と、通らないまま残った原則の ID を書く。

### 流すコマンド

| コマンド                    | 見るもの                                                                                                                       | 原則の ID                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| `pnpm run check:tokens`     | 2 つの生成物が、トークンと合っているか                                                                                         |                                                               |
| `pnpm run check:contrast`   | セマンティックトークンの組のコントラスト比                                                                                     |                                                               |
| `pnpm run check:raw-values` | 画面のコードの色の値とプリミティブトークンの名前                                                                               | `COLOR-TOKEN`                                                 |
| `pnpm run check:utilities`  | 画面のコードの、原則に反するユーティリティ。規則の ID がこの文書にあるか                                                       | `TEXT-MIN-SIZE`、`FOCUS-ONE`、`SPACING-SCALE`、`MOTION-TOKEN` |
| `pnpm run lint`             | テーマ変数にないクラスと、任意の値のクラス                                                                                     | `COLOR-TOKEN`                                                 |
| `pnpm run test:ui`          | コンポーネントの状態、押せる領域の大きさ、コードを動かす画面の幅ごとのページの横方向のオーバーフロー、story のアクセシビリティ | `TARGET-SIZE`、`LAYOUT-OVERFLOW`                              |

### 受け入れ条件

- [ ] 「流すコマンド」が全て終了コード 0 で終わった
- [ ] 「確認の方法」がレビューの原則を、描画した画面で見た
- [ ] 幅とテーマごとに撮った画像を、レビューで見た
- [ ] 使ったコンポーネントの状態が、コンポーネントの文書のそのコンポーネントのセクションと合っている
- [ ] 報告に、5 つの状態のどれでもない原則がない
- [ ] 報告に、対象のコミット、コミットしていない変更の有無、デザインシステムの文書のバージョンがある

### 報告の形

| 状態           | 意味                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| 通った         | チェックが流れ、基準を満たした                                                       |
| 通らない       | 違反の証拠がある。場所と、出たチェックの出力を添える                                 |
| レビューで見る | 描画した画面かコードはあるが、判断はレビューの人がする                               |
| 見ていない     | 確認の規則、チェック、証拠のどれかが無い。前のコマンドの失敗で流していないものも含む |
| 対象外         | 作業の範囲から外れる。理由を添える                                                   |

| 項目                               | 書くこと                                                                                                                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 対象のコミット                     | チェックを流したときの `git rev-parse HEAD` の SHA                                                                                                                                         |
| コミットしていない変更             | なし、またはあり。ありのときは、変えたファイルの一覧（`git status --short` の出力）                                                                                                        |
| デザインシステムの文書のバージョン | この文書と 3 つの文書のどれかを最後に変えたコミットの SHA（`git log -1 --format=%H -- packages/ui/DESIGN.md packages/ui/design/`）。どれかにコミットしていない変更があれば、そのことも書く |

## アクセシビリティ

| 項目                         | 基準                                                                                                                                                                                | 確認の方法                                                                                                                       |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 文字のコントラスト           | 4.5:1 以上                                                                                                                                                                          | `pnpm run check:contrast`                                                                                                        |

## 決まっていない選択

- カタログのアクセシビリティの自動チェックを、テーマごとに動かすか: 今はデフォルトのテーマ（OS の設定。テストのブラウザではライト）だけで動く。案は、`pnpm run test:ui` の storybook の project を、ライトとダークの 2 つの条件で流すこと。ダークの組み合わせは `pnpm run check:contrast` が見ているが、描画した story の違反は見ていないためである。
- `LAYOUT-OVERFLOW` のテストを、記事の画面とダークのテーマに広げるか: 今は、コードを動かす画面をライトで見るだけである。案は、記事の画面の story にも同じ幅のテストを足すこと。
- 動きを減らす設定で、状態の変化を伝える短い透明度の変化を残すか: `MOTION-REDUCE` は残してよいとしているが、今の止め方は透明度の変化も止める。案は、今のまま全てを止めること。残したい動きが出たときに、止め方の例外として足す。
